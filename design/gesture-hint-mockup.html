Cards 模式 · 「Alt + 滚轮」首次示意

一个自创、零线索的手势：卡片看着是静态缩略图，按住 Alt 滚滚轮能滚它里面的内容。 这一页是三个候选的并排小样 —— 只有 HTML/CSS/SVG，不进产品。 色板、字体、圆角、阴影、卡片几何全部取自 design/ui-mockup.html； 节奏取自 bt-render/src/motion.rs 与 bt-app/src/{keyhint,toast}.rs。 示意卡只在首次进入 Cards 时出现一次，之后不再打扰。

红线

时长全是变量，页面上有实时读数

  • --hint-in: 140ms — POPUP_ENTER = MOTION_BASE_MS，进场带 --hint-travel: 4px（MOTION_TRAVEL_LOGICAL_PX）。
  • --hint-dwell: 4000ms — toast.rs 的 TOAST_LIFE_QUIET。一条不出事的通知在这扇窗里活四秒，示意卡没有理由活得更久。
  • --hint-out: 90ms — POPUP_EXIT = MOTION_FAST_MS，只淡出、不位移。keyhint.rs 的原话：离开是没人在等的那一半，所以那一半是快的，而且它不旅行。
  • --ease: cubic-bezier(.25,.1,.25,1) — motion.rs 的 EASE。

CSS 里是两段串起来的 animation，第二段的 delay 就地写作 calc(var(--hint-in) + var(--hint-dwell))， 所以整条命的百分比一个都没写死 —— 改一个变量，三段全对。 这个 calc 不能抽成 :root 上的一条 --hint-hold： 自定义属性里的 var() 在它被声明的那个元素上就代换掉了， 抽上去之后 body.rm 改的 --hint-in 再也进不去， 关掉动画时 delay 会停在 4.14s 而不是 4.001s。

reduced motion 是怎么落的（这是红线，不是选项）

勾上复选框 = body.rm { --hint-in: 1ms; --hint-out: 1ms; --hint-travel: 0 }， 三行，没有第二套分支。示意卡单帧出现、停满四秒、单帧消失： 停留一秒不减，文案一字不改，位置一像素不动。 @media (prefers-reduced-motion: reduce) 走同一条路径， 所以系统设置和这个复选框说的是同一件事。
唯一在这条红线下站不住的是 C：它的信息全在补间里，动画一关就只剩一次跳变。 这不是 C 实现得差，是 C 这个形态本身把状态挂在了动画上。

图标

滚轮是新画的（产品里没有）：viewBox="0 0 16 16"、stroke-width="1.2"、 stroke-linecap="round"、单色 currentColor。 鼠标壳是描边（它是个框）；按刚立的规矩「框内的 field 该填实」， B/C 的实心轮心才是合法画法，A 的线稿轮心是违例。 Alt 键帽照 ui-mockup.html 的 .cap （20px 高、4px 圆角、--hover 底、11.5px）， 按下态加 --active + 一条内影 + 沉 0.5px， 用的是产品里 :active 已有的那一层，不是新词。
