## 1. live/备用屏稳定态检测(头号,开放设计)

现状:M1.9a 只检测冻结转录行;而 Claude Code 整个 UI 跑在备用屏、
永不入转录(2026-07-18 录制实锤 alt=1 持续 491 帧),意味着核心场景
(agent 输出里的公式)当前吃不到。原始设计(DESIGN 核心架构判断)本就是
「基于网格稳定状态检测」——本节把它落地:

- **稳定判定**:live/alt 网格中某区域持续 N ms 无 damage(N 待你论证,
  参考人眼可感知阈值与 Claude Code spinner 的更新节奏——spinner 行不稳定,
  但公式区域一旦画完通常静止)后,对该区域行做 `$$` 块检测(九类误报纪律
  原封复用,检测器与冻结路径共享)。
- **瞬态装饰**:命中块渲染为**无转录锚的网格装饰**(锚=GridPoint 区间);
  该区域任何字节级变化(CUP 重写、滚动、清屏)→ **立即失效回源码**,
  不做任何"猜测保留"。alt 退出→全部失效。primary live 行滚出定稿后,
  自然走既有冻结管线(两路径对同一内容的交接:冻结时若已有瞬态渲染结果,
  允许复用 artifact,避免重复排版——论证可行性,不行就重排)。
- **纪律**:live 检测绝不阻塞呈现(worker 侧);稳定判定用现有
  damage/generation 机制,不新增轮询;误报零容忍集在 live 路径同样全绿;
  BT_PERF_TRACE 记 live 检测次数/失效次数。
- **回归矩阵**:稳定→渲染→区域重写失效→再稳定→再渲染;spinner 邻行
  持续变化不阻断静止公式区;alt 进出;primary live 滚出交接;
  九类误报在 live 路径逐条。
