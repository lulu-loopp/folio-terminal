## 阻断 1:停在回看态(非底部)时,视野内的公式不渲染

**现象**:用户停在转录中部(右下角有 "Jump to bottom" 芯片=非底部),
满屏 `\begin{align}`/矩阵**保持源码不渲染**;**只要向上或向下滚一点**,
它们立刻渲染。

**根因方向(先定性再修)**:
- live 稳定检测(`advance_live_stability`)只在跟随底部时对 live 网格跑;
  进入回看态后,视野展示的是**冻结转录**,而冻结侧的检测入口
  (`schedule_scan` / `schedule_existing_artifacts`)是否覆盖"用户上滚后
  停在某屏,该屏内的 `$$`/`\[`/裸环境块从未被调度过"这一情形?
- 滚动一下就渲染,说明**某个滚动路径触发了调度**,而**静止停驻不触发**
  ——定位这个不对称:是 `settled`/signature 门?还是调度只发生在
  ingest_finalized(定稿)而回看时不发生新定稿?
- 给出 file:line 级因果链,再修。

**要求**:
1. 停在任意一屏(回看态)时,视野内**所有已定稿**的可检测块都应被调度
   并渲染,不依赖用户滚动;
2. 保持既有纪律:九类误报、配对完整性(context_start_trusted)、
   帧级铁律 B、内容级失效全部不回退;
3. 性能:回看态不得对**全部转录历史**反复全量扫描(阻断的教训:
   `try_handoff` 曾 O(n²));调度必须限定在**当前视口可见范围 + 必要
   上下文**。给出复杂度论证;
4. 回归:feed 大量含公式的行使其滚出→上滚停在中部一屏→断言该屏的块
   被检测并 Ready(不依赖再次滚动);性能断言随可见行数而非总历史线性。

## 阻断 2:滚动时公式退回源码(冻结转录侧)

**现象**:滚动过程中已渲染的公式**先变回源码**再重新渲染。M1.9g 修的
"滚动不销毁 live 装饰"通过了变异验证,但用户现在看到的是在
**回看/转录侧**发生——很可能那条修复只覆盖了 live 区。

**要求**:
1. **定性**:确认闪回发生在冻结侧还是 live↔frozen 交接;确认是哪条
   失效路径把滚动当作强失效(滚动不改变内容,不得失效);
2. 修复:冻结侧公式装饰在纯滚动下 artifact 存活(与 M1.9g 的 live 侧
   同原则,复用其模式);
3. 回归:滚动 N 次(含跨 live/frozen 边界)断言 frozen 侧 artifact 的
   Arc 指针不变、无重新光栅化、检测计数不增。**变异验证**能捕获回退。

## 3. 公式左缩进(用户实拍:顶着左边界)

**现象**:公式墨迹左侧紧贴 pane 左边界,而文字行的字符左侧天然有内边距,
视觉上公式"更靠左",不整齐。

**根因**:文字与公式都从 `pane_left = padding_px` 起(`bt-render:2157/2163`),
但公式栅格是 alpha 紧盒裁切、墨迹直接贴住左边界;文字行的字形在字符格
内有天然左侧留白。

**要求**:
1. 给公式块一个**小的左缩进**(建议 = 半个 cell_width 或一个固定 logical
   px 值,论证取值),使公式墨迹左沿与文字行的视觉左沿对齐;
2. 缩进计入块几何(`left_subpixels` 或等价),命中测试/工具条/裁剪框
   一致跟随,不得只挪绘制不挪命中;
3. 横向超宽块按 wrap 设置处理时,缩进不破坏既有横滚语义;
4. 回归:断言块的 `visible_left` = 文字行视觉左沿(±1px);缩进后
   命中测试仍落在正确区域。
