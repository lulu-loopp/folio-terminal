## 阻断 1:定界符配对越界,把正文当成公式渲染

**用户实拍 + 用户自己的因果推断(经协调者确认正确)**:

- 现象 A:多行 `$$` 块只要**没有完整显示在屏幕内**就不渲染(保守,安全);
- 现象 B:**更危险的一面**——上方公式的结束 `$$` 与下方公式的开始 `$$`
  被配成一对,**中间的中文正文被当作公式渲染**;
- 用户判词:「最上方的公式上面的 `$` 不在屏幕中,所以配对出现了问题,
  导致渲染的东西判定错了」。

**根因方向**:live 检测的可见上下文有边界(alt = 整屏;primary =
1024 行转录尾 + live 网格)。当块的开定界符落在上下文之外,扫描从中间
开始,**把闭定界符误当作开定界符**,于是配出一个跨越正文的假块。
这与 M1.9b 处理的"围栏上下文"是同一类问题,但块定界符本身没做这层保护。

### 要求

1. **配对完整性判据**:一个块只有在**开与闭定界符都落在可信上下文内**
   时才可成立。上下文起点之前存在未知状态时(alt 屏尤其如此),
   必须能证明"我看到的第一个 `$$` 确实是开而非闭",否则**整体拒绝**;
   - 可用的证据来源:上下文内 `$$` 的**奇偶性/配对栈**、
     primary 侧可回溯的转录尾、块内是否包含明显的正文特征;
   - **拿不出证据就不渲染**——保守是这条的唯一正确方向;
2. **禁止跨正文配对**:即使奇偶性看似成立,若配对区间内存在**独立成行
   的普通正文**(如中文段落、非数学 ASCII 句子),必须拒绝——真实公式
   块内部不会出现整行自然语言。给出你的判据与依据;
3. **现象 A 的改善(次要)**:在配对可信的前提下,块**部分可见**时应当
   仍可渲染(只是被视口裁切),不必要求整块在屏。若你判断当前"必须整块
   可见"的限制来自其它约束,如实说明;
4. **回归**:构造 alt 屏场景——上方块的闭 `$$` 在屏内、开 `$$` 在屏外,
   下方另有一个块,中间是中文正文;断言**中间正文绝不被渲染**;
   奇偶性歧义时整体不渲染;完整可见的块正常渲染。

## 阻断 2:CJK 缺字形,`\text{中文}` 渲染成豆腐块

**用户实拍**:`\text{ 项}`、`\text{四重根号}` 全部渲染为空心方块。

**根因**:Typst 引擎当前只嵌入了默认(拉丁)字体集,无 CJK 字形。

### 要求

1. 让数学排版能取到 CJK 字形。**优先方案**:复用系统已安装的中文字体
   (Windows 上如 Microsoft YaHei / 等线),避免把整套 CJK 字体嵌进
   二进制(当前 exe 已 65MB,嵌入 CJK 会再涨数十 MB);
   - 若 typst-kit 的字体搜索可指向系统字体目录,优先走这条;
   - 必须论证:字体缺失时的降级(不能整块渲染失败,应保持源码或
     用可辨识的替代字形);
2. **回归**:`$$\text{中文}$$`、混合 `$$x + \text{项目数}$$` 渲染出
   非空心方块的真实字形(可断言栅格中该区域的墨迹分布,或断言未命中
   .notdef);
3. 记录:二进制体积变化、字体许可与来源。

## 4. 定界符扩展(用户提问引出,协调者裁决:一起做)

当前只认 `$$...$$`。以下**标准 LaTeX 写法认不出来**,而它们正是 agent
和用户会自然写出的形式:

- `\[ ... \]`(标准 display 定界符)、`\( ... \)`(标准 inline);
- **裸环境**:`\begin{equation}...\end{equation}`、
  `\begin{align}...\end{align}` 等不包在 `$$` 里的写法
  ——按 LaTeX 规范这才是正确用法(`align` 本身即 display 环境)。

### 要求

1. 支持 `\[...\]`(display)。**`\(...\)` 暂不做**——它与行内检测同属
   高误报面,而行内检测目前是禁用状态,不要在此片重开;
2. 支持**裸数学环境**,但必须用**白名单**:equation/equation*/align/
   align*/gather/gather*/multline/aligned/cases/matrix 家族等;
   `\begin{document}`、`\begin{itemize}` 等非数学环境一律不认;
3. 九类误报纪律、配对完整性(阻断 1)同等适用于新定界符;
4. 回归:三种定界符各自的正例;白名单外环境不认;跨上下文的配对拒绝。
