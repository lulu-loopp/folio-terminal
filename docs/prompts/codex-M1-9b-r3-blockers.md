## 阻断 A:live 路径的围栏纪律结构性失守(最高优先)

**问题**:live 检测窗口只取「连续稳定行段」(`session.rs:672-683`),而
检测器的围栏状态**只由传入的那几行从零构建**(`bt-detect/src/lib.rs:317-330`)。
冻结路径传的是整篇文档(`session.rs:1966-1975`)——所以冻结路径全绿。

**后果**:开围栏与候选行之间只要有**一个不稳定行**(spinner、流式重绘),
稳定段就被切断,``` 被挤出窗口,**围栏内的 `$$x$$` 被当公式渲染**。
这正是"终端渲染你的字面文本 = 终端失败"的红线。

**现有测试不构成证明**:`bt-detect/src/lib.rs:547-566` 手工把围栏和候选
塞进同一个 `inputs`,恰好绕开了窗口化那一层。

**裁决(照此实现)**:

1. **上下文与稳定性解耦**:围栏状态必须从**可见范围的顶部**累积扫描,
   与"哪些行稳定"无关;稳定性只决定**哪些候选允许出结果**,不决定
   **能看到多少上下文**。
   - alt 屏:上下文 = 整屏第 0 行起的全部行;
   - primary live:上下文 = 转录尾部(足以覆盖未闭合围栏的合理行数,
     论证取值)+ live 区全部行,拼成连续上下文。
2. **未配对围栏一律保守**:可见上下文内出现**未闭合的开围栏** →
   其后所有候选**全部拒绝**(不渲染,保持源码)。
3. **已知限制如实记录**:开围栏完全落在可见范围之外(alt 屏上一屏之外
   的长代码块)时,终端在该时刻**不具备**判定信息。这是终端层面的
   事实,不是可补的信息——在代码注释与最终答复里写明该边界,
   **不许用启发式假装知道**。
4. **回归必须走真实窗口化路径**:构造「``` 开围栏 → 中间夹一个持续
   变化的 spinner 行 → `$$x$$` 候选」的 live 场景,断言**不产生
   placement**;以及未闭合围栏后多候选全拒;primary live 接转录尾部
   围栏的场景同样断言。**不许再用手工拼 inputs 的测试充数**。

## 阻断 B:右键菜单在 winit 回调内同步弹出 → 重入 panic

`TrackPopupMenu`(`bt-platform/src/lib.rs:171-179`)被 winit 用户回调
执行中同步调用(`main.rs:1081-1090`)。它必然开嵌套消息泵;winit
0.30.13 对 `RedrawRequested` 不缓冲直接进处理器(`runner.rs:208-211`),
`call_event_handler` 重入时 `take().expect("either event handler is
re-entrant (likely)...")` **panic**。

**修法**:把菜单弹出移出回调体——记下"待弹菜单"请求,在回调返回后的
安全点(如 `about_to_wait`,或经 EventLoopProxy 派发的 user event)执行;
或改用不开嵌套泵的方案。**必须有测试或明确的机制论证**说明重入不再
可能;若无法自动化测试,给出人工验证步骤并如实标注。

## 阻断 C:resize epoch 期间 `WaitUntil(过去)` 忙自旋

`advance_live_stability` 在 `resize_epoch.is_active()` 时提前返回
(`session.rs:636-638`),既不结算 `settled_revision` 也不清
`last_damage_at`;`live_stability_deadline`(`:624-630`)于是持续返回
已过期时刻,经 `main.rs:1779/1786` 变成 `WaitUntil(过去)` → 立即唤醒 →
再次提前返回 → **100% CPU 自旋**。静默条件是「最后输出 + 200ms」
(`scheduling.rs:65-70`),在**持续输出的备用屏应用**下无时间上界
——恰是本片的目标场景(Claude Code)。

**修法**:resize epoch 活跃期间**不得**产生已过期的 deadline
(要么挂起 live 稳定调度并清除其 deadline,要么把 deadline 推到
epoch 结束后)。**回归必须断言**:resize epoch 活跃 + 持续输出时,
事件循环的 wake deadline 不为"过去",且单位时间唤醒次数有上界。
