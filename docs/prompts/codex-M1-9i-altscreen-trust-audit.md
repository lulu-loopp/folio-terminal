## 【第二阶段:红线机理 —— 守卫为何存在,放松边界在哪】

守卫来自提交 `f2e7287`,防的是用户亲自定位的错配:
**开分隔符滚出屏 → 残留闭分隔符被当成开符,与下一个真开符配对,把中间
散文排成公式。**

协调者的关键观察(**你需在代码里证实或证伪**):

- 该错配**只可能发生在对称分隔符**(`$$` 显示、`$` 行内)——开闭同形,
  无法区分残留的是开还是闭;
- **非对称分隔符**(`\[`/`\]`、`\begin{X}`/`\end{X}`)开闭可区分:扫描器
  (bt-detect:778-845)遇到残留 `Close` 且 `opening==None` 时走
  第 844 行 `DisplayDelimiterToken::Close(_) => None`,**不会错配**;
- 因此"信任丢失"真正需要压制的,**只有跨越不可信起点的对称配对**,而非
  窗口内所有块;
- 进一步:即便对称 `$$`,风险也只在**第一个 `$$`**(它可能是幻影开符的
  闭);一旦发生一次 toggle,奇偶校验即重建,其后皆可信。

**同时评估另一条更强的结构性论点(可能翻掉守卫在备用屏的必要性):**
备用屏**没有 scrollback**——滚出顶部的行被备用缓冲彻底丢弃,app 每帧重绘
完整网格。session.rs:841-843 的注释也承认"滚到 row 0 之上的开符不可知"。
问题是:在备用屏,检测窗口就是**整块可见网格(row 0 起)**,row 0 之上
不存在被保留的历史。那么"幻影开符"在备用屏语义下是否**根本不成立**,
抑或仍成立(例:`\begin{align}` 半滚出、只剩 `\end{align}`+散文可见)?
给出**明确判定**:备用屏该不该沿用与主屏相同的信任模型,还是有独立的、
更弱的正确前提。

## 【第三阶段:修复 —— 最小且可证不错配】

在第二阶段结论基础上,设计**最小放松**,让备用屏里闭合完整的公式块恢复
渲染,同时**用测试证明不重新引入错配**。可选方向(择优或提出更好的):

- (a) 守卫粒度化:`context_start_trusted=false` 时不再整体返回空,而是只
  抑制**对称分隔符跨不可信前缀的配对**;非对称与单行块照常检测;对称块
  仅丢弃"可能咬住幻影开符"的那一个(通常是窗口内第一个),其后照常;
- (b) 备用屏专属前提:若第二阶段判定备用屏不存在幻影开符,则
  `alternate_context_start_trusted` 的语义应改为**由可见 row 0 是否中性
  边界决定**,而非"滚过就永久 false";给出如何廉价判定 row 0 中性。
- 若 (a)(b) 皆有正确性漏洞,如实说明并提你的方案。

**硬约束(不可回退):**
1. 九类误报守卫、CJK 散文守卫(`block_body_looks_like_prose`)、帧级铁律、
   内容级失效,全部不动摇;
2. 用户亲证的错配场景**必须有回归**:构造"开符在窗口前不可见 + 残留对称
   闭符 + 散文 + 下一开符"的输入,断言散文**不被**排成公式(对
   `context_start_trusted=false` 与放松后都跑);
3. 性能:备用屏检测不得对全历史全量扫描(m1.9h 的 O(n²) 教训);限定在
   可见网格 + 必要上下文,给复杂度论证。
