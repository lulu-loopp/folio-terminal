# 独立设计咨询(只读,不许改任何文件):让所有公式落地即渲染,且滚出前后视觉一致

你是独立设计顾问。**只读代码库,不修改任何文件,不跑门禁,不实现**。
产出是一份带 file:line 证据的方案论证。

## 问题

用户判词:「单行公式需要滚出去才能渲染,交互很烂」;进一步要求:
**所有公式都能直接渲染,且滚出前(live)与滚出后(冻结转录)视觉效果一致**。

现状(提交 eb6a534 及其后的 M1.9c 工作树):

- 冻结转录侧:公式 = display 排版 + **自由像素高度**,高度进高度树,
  多投影各自正确(`crates/bt-viewport`)。
- live/备用屏侧:裁决 B 精修——公式**等比缩放进源码行带**、左对齐、
  **绝不覆盖邻行**、低于 0.65 可读地板则保持源码
  (`crates/bt-term/src/session.rs` 的 live 路径、
  `crates/bt-render/src/lib.rs` 的 clip)。
- 因此:单行 `$$x$$` 的行带仅 1 行(~20px)而栅格 ~35px → 不渲染;
  多行块(3 行行带 ~60px)→ 渲染。**同一公式在 live 与冻结两侧
  形态不同**。

裁决 B 的理由(必须尊重或明确论证如何安全推翻):live 是 ConPTY 的
坐标空间,应用按行列绝对重绘;装饰覆盖邻行 = 遮挡活内容 + 留下过期
残影。DESIGN.md 亦有「活动平面固定行高、只允许等高装饰」的不变量。

## 你要回答的

**是否存在一条路径,使 live 区的公式也能按自由高度渲染(即与冻结侧
视觉一致),同时不破坏正确性?** 逐条论证下列候选(以及你想到的其它),
给出对现有不变量的影响、失败模式、实现代价与推荐:

1. **live 行可变高度 + 视口容纳**:让 live 行像转录行一样进入高度树。
   核心难点是**行数守恒**:ConPTY 认为屏幕是 N 行且全部可见;若公式
   撑高使总像素超出视口,必有若干行不可见。
   - 子方案 1a:**底部锚定优先**——保证屏幕底部(光标、输入行、状态栏)
     始终可见,溢出发生在顶部,用既有的滚动/`N lines above` 机制承接。
     论证:应用重绘时我们的行列→像素映射是否仍然正确?选区/鼠标命中
     (`live_viewport_mouse_hit`)是否仍然正确?ConPTY 的 resize 语义
     会不会被牵动?
   - 子方案 1b:**向 ConPTY 报告更少的行**(公式占位时 resize PTY),
     论证抖动与应用重排代价。
2. **公式所需额外高度受限时才撑高**(如 ≤2 行),超出则回退缩放/源码。
3. **两侧统一为"适配"而非"自由"**:让冻结侧也按行带适配。
   (代价:牺牲转录侧已有的自由高度优势,§7.4 的完整排版失效——
   论证是否值得。)
4. **行内数学模式**(协调者已起草的 M1.9d):live 单行用 inline 排版
   贴合行高。**但它不满足"视觉一致"**——inline 与 display 形态不同。
   论证:这个不一致在排版学上是否可接受(LaTeX 自身就区分二者),
   以及它与方案 1 的组合可能性。
5. 你认为更好的其它路径。

## 必须覆盖的检查点

- 应用坐标假设:CUP/EL/ED 按行列重绘时,可变行高是否引入任何
  语义错误(不只是视觉);
- 鼠标转发坐标(m1.8b 的 live 相对坐标语义)与选区;
- 备用屏进出、resize 事务(canonical 双馈)与高度变化的交互;
- 性能:live 高度频繁变化对行缓存(m1.8e 内容寻址)与呈现等价门
  (m1.8d)的影响;
- 失效纪律:公式区域被应用重写时的即时回退在新方案下是否仍然成立。
