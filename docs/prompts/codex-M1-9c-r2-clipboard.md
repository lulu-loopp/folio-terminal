## 阻断 B-1:`copy_selection` 仍会终止整个应用

第 1 条只降级了公式那一支(main.rs:847/861/1109,已核实闭环),但
**同一个 `set_clipboard_text` 的另一个调用者原样留着 `?`**:

```
crates/bt-app/src/main.rs:925  copy_selection 用 ? 上抛
 → :1281 keyboard_input ? → :1719 winit 分发 → :1764 self.fail()
 → :1653 event_loop.exit()
```

`OpenClipboard`(`bt-platform/src/lib.rs:132`)**无重试**,而 Windows 上
别的进程持有剪贴板返回 ACCESS_DENIED 是常态 —— 用户按一次 Ctrl+C
就可能关掉整个终端。同文件的**粘贴**路径早已降级(:1328-1333),
可见这是遗漏而非有意。

**要求**:
1. 复制路径降级为可恢复:失败不终止应用;给用户一个不打断工作的
   提示(与既有粘贴失败路径同风格),trace 记录原因。
2. `set_clipboard_text` / 读剪贴板加**有界重试**(Windows 惯例:
   若干次、短间隔退避,总时长有上界),仍失败才走上面的降级。
3. **自己 grep 一遍**:`crates/bt-app` 里所有把**可恢复的用户操作
   失败**用 `?` 传播到 `self.fail()` 的地方,逐个裁决(该降级的降级,
   确实致命的保留并说明理由)。列出清单与裁决结果。
4. 回归:复制失败(注入不可用剪贴板)→ 应用存活、状态自洽、可再次
   尝试;粘贴同理不回退。
