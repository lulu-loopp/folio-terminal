## 阻断 A:选区抑制用像素反推行号,自由高度下误杀公式之间的所有行

**根因(复审定位 + 逐值复现)**:
`crates/bt-term/src/session.rs:1746-1765` 仍用
`top_subpixels.div_euclid(cell_height)` + `.max(0)` 把像素反推成行号,
据此 retain 掉选区 span。

**这段代码与 HEAD 逐字相同** —— 等高时代它是对的(每行恒为
cell_height,除法即行号);M1.9e 的**自由高度 + 负 top** 让这个等式
不再成立,于是静默错位。**与 r3 修掉的 placement 锚点是同一家族的
第三处漏网**。

复审合成复现(40×24,四块):真 band 行 `{0,2,4,6}`,而计算出的抑制集
为 `{0,1,2,3,4,5,6}` —— **公式之间的每一行都被误杀**。
用户真窗口 oracle(三块)正好误杀 `after-1`/`after-2`,方向、位置、
幸存边界全部吻合;用户判词「after-2 被算到上面的公式那里」精确正确。
截图中那道落在 `∑` 上的全宽高亮是同一根因的另一半:幸存的公式源行
span 按撑高行高(≈3 个 cell)画出。

**已排除(复审逐条核实,不要改)**:渲染矩形走 `frame_cell_bounds_px`
→ row_map(`bt-render:2500/2859`)正确;`SelectionSpan.row` 是帧行索引、
两端一致(`bt-viewport:2018`)正确;命中测试 `hit_test_frame` →
`visual_row_at`(`bt-render:189` / `bt-viewport:307`)无 off-by-one。
**三侧都对,唯独事后被 retain 删了。**

### 要求

1. 抑制集**直接用 band 行**(与 r3 的 placement 同一基准),
   **禁止任何形式的"像素 ÷ 行高"反推行号**;
2. **全仓扫一遍同类反推**:凡把像素/偏移除以 `cell_height` 得到行号、
   或用 `row * cell_height` 得到像素的地方,逐个裁决(自由高度下这两个
   等式都不成立)。列出清单与裁决结果——这已是同一家族的第三处,
   必须一次扫干净;

   所以抓不到。新回归要:多块 + 块间文本行 + 真实选区,断言
   **块间文本行的 span 幸存**且**其高亮矩形落在自己那一行的
   row_map 区间内**;
4. 把这条做成**帧级不变量**(与 r3 的铁律 B 同族,下沉到
   `validate_shape()` 或等价位置):**每个 SelectionSpan 的绘制区间必须
