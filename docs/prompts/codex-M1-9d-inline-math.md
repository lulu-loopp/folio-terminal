# M1.9d 任务书:行内数学模式——单行块落地即渲染

档位 xhigh(排版模式选择是开放设计,需论证);基线 = M1.9c 之后的工作树。

## 动机(用户裁决 2026-07-19)

现状:live 区的**单行** `$$x$$` 因为行带只有一行(~20px)而公式栅格
~35px,缩放 0.57 低于 0.65 地板 → 保持源码,**必须滚出屏幕定稿后才
渲染**。用户判词:「单行需要滚出去才能渲染成公式的操作很奇怪,交互很烂」。

根因不是地板取值,是**排版模式选错了**:我们把所有 `$$` 块都按
**展示数学(display math)**排版,再硬塞进一行的高度。而排版学里
本来就有两种数学模式:

- **行内数学(inline)**:排在文本行内,分数横排小号、求和用行内形式,
  **高度天然贴合行高**;
- **展示数学(display)**:独占段落,自由高度,分数上下叠、求和带上下限。

## 要做的事

**按源码形态选择排版模式**:

1. **live 区的单行块**(`$$...$$` 写在同一行)→ **inline 模式排版**,
   目标高度 = 该行行带高度。**通过排版参数(字号/模式)达成,不是把
   display 结果缩小**——缩放会糊,行内排版是清晰的。渲染后**立即
   落地**,不再受 0.65 地板约束(地板仅作为极端情况的兜底,见 4)。
2. **live 区的多行块**(`$$` 独占行 + 体 + `$$` 独占行)→ 维持现状的
   **display 模式**,占其三行行带,居中(M1.9c 第 3 条)。
3. **冻结转录侧**:一律 **display + 自由高度**(§7.4 现状不变)。
   因此单行块滚出后会从 inline 形态**升级**为 display 形态——这是
   有意的"预览→正装",在代码注释与最终答复里写明,并确保升级过程
   不闪烁(复用 M1.9b 的 stale 保留策略)。
4. **兜底**:若 inline 排版结果仍然超出行带高度(极端嵌套),按既有
   规则保持源码;若横向超出行宽,按 wrap 设置处理(块内横滚或随 pane),
   不得撑破行带、不得覆盖邻行(裁决 B 铁律不动)。

## 实现要点

- Typst 侧:确认 inline(`$x$`)与 display(`$ x $`)两种模式的
  正确调用方式,MiTeX 转换 LaTeX 源时如何指定;论证字号如何选取
  才能使排版高度贴合行带(不是事后缩放)。
- 检测器需要向渲染任务传递「源码形态 = 单行 | 多行」这一位信息。
- 九类误报纪律、围栏上下文、失效链、时效检查全部不变。

## 回归

- 单行 live 块 → 产生 placement,`render_scale_milli` ≈ 1000(说明是
  排版贴合而非缩放),clip 不超行带,邻行完好;
- 同一公式的单行 live(inline)与冻结(display)栅格**不同**且各自
  正确(断言两者尺寸关系符合预期);
- 极端嵌套的单行块仍超高 → 保持源码;
- 横向超宽 → 按 wrap 设置,不越行带;
- 多行块行为不回退(仍 display + 居中)。
