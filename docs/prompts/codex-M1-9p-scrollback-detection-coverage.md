## 红线(不可让步)

回看态"前缀不可信"正是 M1.9k 那条 Ambiguous 守卫**存在的理由**——绝不能为了让块
渲染就猜一个前缀,导致**把散文错配成公式**(用户亲证过的错配红线)。任何修复必须:
- 只在**能证明**可见第 0 行处于中性解析边界(既非代码围栏内、也非某个开着的显示
  分隔符/环境内)时,才从可见顶检测;
- 无法证明时,对**受不可信前缀影响的对称配对**保持 Ambiguous → 保留源码(不猜);
- **非对称 + 自闭合**的块(可见屏内既有开又有闭的完整 `$$…$$`/`\[…\]`/
  `\begin…\end`,如用户那三个块)——它们的配对**不依赖屏外前缀**,应当能独立检测
  渲染。**这可能才是真正的修复点**:确认这些"屏内自闭合完整块"为何没被检测(是被
  不可信前缀一刀切压制了?还是别的?),让它们不受屏外前缀影响地渲染。
