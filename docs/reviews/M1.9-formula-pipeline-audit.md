## FM3 因果链与裁决

### 输入语义

矩阵换行是 `\\`。单个反斜杠后跟空格是 control-space，不是 row separator。仓库正确矩阵测试均使用 `\\`：[bt-math/lib.rs:447](/D:/Developer/BetterTerminal/crates/bt-math/src/lib.rs:447)。

### M1.9j 不会影响 rendered placement

- 新列跨度仅在 `show_source` 分支构造 Source placement：[session.rs:2002](/D:/Developer/BetterTerminal/crates/bt-term/src/session.rs:2002)。
- rendered display placement 仍统一使用半 cell inset：[session.rs:1948](/D:/Developer/BetterTerminal/crates/bt-term/src/session.rs:1948)。
- renderer 对 Source placement 根本不画 texture：[bt-render/lib.rs:2074](/D:/Developer/BetterTerminal/crates/bt-render/src/lib.rs:2074)。
- `source_width_columns` 也只在 Source geometry 分支读取：[bt-render/lib.rs:2177](/D:/Developer/BetterTerminal/crates/bt-render/src/lib.rs:2177)。
- live rendered block 会清除整个 owned band 的 cell glyph：[bt-viewport/lib.rs:1158](/D:/Developer/BetterTerminal/crates/bt-viewport/src/lib.rs:1158)；frame validator 和 GPU clip 又限制 block 不越界：[bt-viewport/lib.rs:263](/D:/Developer/BetterTerminal/crates/bt-viewport/src/lib.rs:263)、[bt-render/lib.rs:2125](/D:/Developer/BetterTerminal/crates/bt-render/src/lib.rs:2125)。

因此推翻“FM3 由 M1.9j left/source-span 改动引起”的猜测。

### 窗口尺寸相关性的真实基础

`live_detection_context` 将每个可见**物理行**独立变成 detector input：[session.rs:923](/D:/Developer/BetterTerminal/crates/bt-term/src/session.rs:923)。`captured_row_text` 丢掉 `continues/WRAPLINE`：[session.rs:3800](/D:/Developer/BetterTerminal/crates/bt-term/src/session.rs:3800)。多行 detector 再以人工 `\n` 拼接这些物理行：[bt-detect/lib.rs:803](/D:/Developer/BetterTerminal/crates/bt-detect/src/lib.rs:803)。

所以 resize 会改变：

- 定界符是否“独占一行”；
- start/end 与 byte span；
- 送给 MiTeX 的 source 分行；
- source band 行数与 viewport 预算。

FM3 应裁为 **(a) 输入语义 + (c) 物理行宽度依赖**，不是 **(b) M1.9j band/left bug**。若实拍确有最终帧中 terminal glyph 与 raster 真重叠，则必须取得原始 VT、`row_map` 和 `MathBlockPlacement`；当前静态不变量与该说法冲突，不能继续猜修。

## 架构结论

### 检测器应重写

新的统一 scanner 应：

- 输入逻辑行及真实初始状态，而非 `context_start_trusted: bool`；
- token 携带行/id 与 byte 范围；
- 支持定界符与 body 同行的跨行块；
- 用 `CapturedRow.continues` 重建逻辑行，同时保留逻辑 byte→物理 cell segment map；
- 分离 `original_source`、`render_source`、`mode`、`delimiter_kind`；
- 由真正 CommonMark block context 处理 fenced/indented code；
- 对未知前缀返回 Ambiguous，而非整体返回零块。

应支持：

1. `$$body$$` 单行及 `$$body...` / `...body$$` 跨行；
2. `\[body\]` 单行和跨行同行-body；
3. 当前经 MiTeX 验证的 equation/align/gather/multline/cases/matrix 家族，允许 begin/end 与内容同行；
4. outer dollars 内嵌环境和方向性环境嵌套；
5. escaped、空块、未闭合、超 8KiB、代码上下文保持字面；
6. `$...$` 与 `\(...\)` inline 继续禁用。

### 零闪现需要发布前同步 reconcile

必须在 terminal 完成一个 PTY drain 后、`viewport_frame` 前：

1. 对当前 screen revision 做 bounded 同步检测；
2. exact source + exact render key 命中即重算 occurrence/band；
3. 原子删除旧位置并在新位置安装同一 artifact；
4. cache miss 才等待 200ms 并调度昂贵 raster；
5. 纯 winit Expose 不检测。

安全性来自“当前 detector 独立证明 occurrence + 全文相等 + render key 相等”，不能只按 substring/hash 装回。

### M1.9j 应改造而非丢弃

内容寻址方向正确，但应改为：

- `get`/Arc clone，entry 保留；
- 相同公式多 occurrence、live/frozen、primary/alt 共享；
- 按 resident bytes 淘汰；
- cache 与 decoration 生命周期解耦；
- renderer 使用可比较结构键或唯一 artifact id，不只信 64-bit hash；
- cache-hit reconcile 前移到发布边界。

### alt 模型应改变

`alternate_detection_context` 当前代表连续输出流前缀，但 Claude TUI 可用 clear/home 重画任意历史 snapshot。parser state 必须绑定 repaint transaction/screen revision：

- 连续 full-screen output scroll：可由 removed rows 推进；
- 明确 clear 后全量 repaint：建立新的 snapshot boundary；
- 无法证明的 symmetric prefix：标 Ambiguous、保留源码；
- 不再使用“screen 名称级永久 context”。

## 有序修复路线

1. **R1：先建会红的端到端门。** 加 FM1 三族、长主屏/tombstone、缩进代码负例、真实 alt clear+repaint、两种宽度；FM2 必须在重画后 `<200ms` 构造 frame。
2. **R2：建立 `MathOccurrence`。** 分离 original/render source、delimiter、mode 和逐行 cell segments。
3. **R3：替换统一 scanner。** 同时解决 FM1、长会话 trust、CommonMark 和物理折行；这是最快改善“根本不渲染”的生产片。
4. **R4：使状态可观察。** 区分 Waiting、Ambiguous、RenderFailed、ViewportBudgetSuppressed。
5. **R5：重做 reusable artifact store 与 collision-safe renderer identity。**
