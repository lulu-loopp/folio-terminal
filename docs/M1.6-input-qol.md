# M1.6 输入 QoL

本片补齐基础终端编辑键和文本粘贴，不包含选区或复制。

## 输入协议

- 方向、Home/End 在普通模式发 CSI，在 vendor `Term` 的 `APP_CURSOR` 模式发 SS3；带 Shift/Alt/Ctrl 时统一使用 xterm modifier 参数。Insert/Delete/PageUp/PageDown、Tab/BackTab 和 Alt+可打印字符（ESC + UTF-8）同样在纯编码模块覆盖。
- `APP_CURSOR` 与 `BRACKETED_PASTE` 都在 PTY 输出经过 alacritty parser 后，直接读取 vendor `TermMode`；应用没有第二份模式状态。
- 非空 `Ime::Preedit` 是组字判据。方向、Home/End、Insert/Delete、PageUp/PageDown、Backspace、Enter、Escape、Tab 和粘贴快捷键在该分支停止，不向 PTY 发字节；`NamedKey::Process` 的 M0-beta 逻辑键保护仍保留。

## 粘贴安全政策

- Ctrl+V 与 Shift+Insert 暂时绑定为粘贴。Ctrl+V 会与 vim 块选等终端程序语义冲突，已登记到 P2-7 快捷键审计，届时统一做按 profile 可覆盖绑定。
- winit 没有剪贴板 API；实现沿用 `bt-platform` 已有的窄 Win32 边界，通过 winit 的窗口句柄读取 `CF_UNICODETEXT`。这只增加现有 `windows` crate 的 API features，不新增或加重第三方运行时依赖。
- CRLF 与 LF 归一为 CR；CR 与 Tab 保留，其余控制字符默认过滤，普通 Unicode 文本保留。
- 在任何包装之前剥除粘贴内容里的完整 `ESC [ 201 ~`，防止提前终止 bracketed paste。vendor `TermMode::BRACKETED_PASTE` 开启时，再包裹 `ESC [ 200 ~` / `ESC [ 201 ~`。
- 清洗后的数据沿唯一同步 PTY writer 以 16 KiB 分块写入，复用 `write_all + flush` 的 ConPTY 背压，不做单次任意长度底层写入。

## 验收边界

自动证据由编码全矩阵单测、DECSET 模式读取单测和粘贴清洗单测构成。`scripts/dev/ui-probe.ps1` 的注入键无法进入 winit 的 `KeyboardInput` 路径，这是既有探针限制，因此真实按键路径仍以 `scripts/dev/m1-6-input-acceptance.ps1` 的人工操作为准。
