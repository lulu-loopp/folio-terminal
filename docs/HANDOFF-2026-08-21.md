## 2. 禁区与坑(全是踩过的)

**硬禁区**
- **不许碰 `dist\`** 里用户正在用的东西;**绝不许 kill 任何你没起的 folio 进程**。出新版就覆盖
  `dist\folio-next.exe` 或 `folio-next2.exe` 中**没被占用**的那个(被占的会 Access denied,
  而 `| tail` 会把这个错误吞掉、退出码还是 0 —— 用**时间戳**确认拷贝真的成功)。
- **不许改 `~/.cargo/config.toml`**:`jobs = 19`(24 核留 20%)是用户裁决,别删。
- **不许对 `.rs` 用 `sed`**(CRLF 会被毁)。要脚本就用 python(`io.open(..., newline='')`)或 Edit 工具。新文件一律 LF。

**反复咬人的**
- **「用户环境里有没有装 X」一律问那个程序自己,别拼路径(2026-08-21,PowerShell 整合线现场)**:
  用户的 Documents 重定向到 `D:\`,`$PROFILE` 在 `D:\Documents\...` 而不是 `C:\Users\<user>\Documents\...`,
  后者那两个 2 字节空文件从来没被 shell 读过——一个自己拼路径的 build 会对一台早就装好的机器报「未安装」。
  判据改成 `pwsh -NoProfile -Command '$PROFILE.CurrentUserCurrentHost'`。同一类:装没装、装在哪、用的是哪个 profile
  ——**问,别推**。

- **`PSModulePath` 那条 export 已退役(2026-08-21,`test-env-immunity` 结案)**:当初「带 export 跑全量会挂、不带单跑就绿」是**两件方向相反的事**——
  (A)挂的两条测试(`real_powershell_input_reaches_a_viewport_owned_frame`、`sidecar_resize_keeps_history_navigation_on_a_clean_prompt_line`)
  是**墙钟总额被负载吹爆**,与 env 无关(改前/改后二进制同环境交替 7/8 vs 0/8);(B)export 真正救的是 **bt-pty 的 build.rs**——
  5.1 继承 pwsh 7 的 `PSModulePath` 会 `Get-FileHash` 找不到,现在 build.rs 自己算 5.1 的模块路径。两支探针改成**静默预算**(30s 静默 / 180s 天花板),
  `full_ring_blocks_writer` 的 20ms 假设也换成生产者自己的报告。规则进了 `CONVENTIONS.md`(超时按静默不按总额;A/B 必须交替)。
  **仍会抖的**:`dir_watch`(真竞态,已开单,§4)、`a_pathological_dollar_screen_arms_nothing…` 与 `finalized_line_ingest_stays_linear…`(时间比值门,多 cargo 并发必挂,单跑绿放行)。
- **i18n**:`crates/bt-app/src/i18n.rs` 的 `Text::ALL` 现在是 **419**,数字**手工维护**。
  新串一律**追加在 enum 末尾与 ALL 末尾同一块**。合并冲突的固定解法 = keep-both + 只留一个
  `ALL: [Self; N]` 头 + 重新数 + 加重复变体断言。**keep-both 会把函数或字符串字面量截断在半路**
  (今天发生过两次),解完必须 `cargo check`。
- **schema 版本撞车**:两条线同时占同一个版本号时,**后合的那条让号**(改迁移函数名、文档行、
  `Value::from(N)`、迁移表、常量、fixture 文件名与内部 `schema_version`、测试名与断言句子)。v16 是先例。

## 5.5 不许违反的不变量(动代码前先确认你没在推翻其中一条)

这些是产品的地基,写在 `docs/DESIGN.md` 里。它们不是风格偏好,是**推翻了就要重做一大片**的东西。

**§1.1 核心不变量(五条)**
1. **Canonical Transcript 是真相**(对已冻结内容);活动网格的真相是 grid 本身;富内容是转录区间上的**可撤销装饰**。
2. **双平面 + 单向冻结 + 可变尾部单一所有者**:稳态 alacritty scrollback = **0**;任一时刻只有一个 mutable owner;
   Live→Frozen 严格单向,**无 thaw**。其中拆出的两句要分清:
   **终端坐标不变量(不可动摇)**——ConPTY/vendor 永远持有固定 N×M 网格,**富内容绝不触发 PTY resize**;
   **投影布局不变量(可放宽)**——视口怎么把逻辑行映射到像素是我们的事。
3. **文档与投影分离**:`HistoryDocument` 无布局;每视口一份 `ViewportProjection`。
4. **核心逻辑与 GUI 解耦**:纯 crate + 语料回放。
5. **Damage 驱动调度,完整帧合成**。

**§7.0 内容×形态三法则**
6. **状态属于内容,随行不分叉**——容器不持有状态。
7. **拖拽换容器,落点定容器**——载荷 = 内容身份。
8. **一切限制是政策不是结构**——不开放的组合必须是**显式政策记录**(可翻案),不许变成结构性阻塞。
   今天「无终端 tab」那一片就是这条被违反了一年后的修复:拆墙,而不是翻案。

**§7.1 贯穿性纪律**
9. 预览与提交**共用同一个布局求解器**。
10. 手势期间**命中目标保持身份**、未变化的状态不得丢失。
11. 弹出浮层由**集中控制器互斥**。
12. 实现为独立纯布局求解器,**不模拟 CSS flex**。
13. **hover 原则**(被两次升格为产品核心差异点):查询 hover 化、**提交必点击**;高频任务 ≤2 次滑动 + 2 次点击。

**§9 三道退出门**(验收硬指标,不是软目标):G1 resize 生命周期回放矩阵、G2 多投影一致性、
G3 锚点与版本协议。原文:**「三门任一不过 → 按 R10 降级砍功能,不顺延。」**

## 6. 如实挂着的缺口(不是忘了,是做不了或已裁不做)

~~**副屏上单击本地文件链接不开预览**~~ —— **已结案(2026-08-20 晚):不是副屏,也不是 DPI。**
`BT_MOUSE_TRACE` 日志(`D:\folio-mouse.log`,**只读,别动**)把三个嫌疑一次判完:全程 `scale=2`,
`preview_landing_surface` 与 `activate_hyperlink` **一次都没被走到**——**跨屏 DPI 那条嫌疑就此撤销**,别再当活嫌疑。
真因在更早一格:用户点的是 **Claude Code,alt 屏**。日志是 `pane_press … pressed_target=Ours link=Some(…)`
紧跟 `pane_press forwarded=1 bytes=11 route=forward` —— 本窗认出了链接,却因 DESIGN §7.1.5f 闸门 ③「只在主屏」
把这一下整份转发给了程序。用户当晚**推翻了闸门 ③**(alt 屏现在也认 OSC 8 与裸 URL,下划线那句承诺在两块屏上一样欠着),
`press_belongs_to_the_window` 已去掉 `!modes.alternate_screen`,`modes` 参数随之消失。裁决、代价与 `Shift` 反向无解见 DESIGN §7.1.5f 段末。
**连带的两件**:alt 屏程序现在收不到压在链接上的那一下左键(用户知情接受);https 链接平点仍是 `arm=None`——§7.1.5g 平点 = 留在窗内,而网页预览(W2)没到货,所以**网页链接目前只有 `Ctrl+点`(交给浏览器)有动作**,W2 落地后平点才有去处。

- **PowerShell 整合未装 → 鼠标残留修复对用户不生效**(§5 第 6 条)。这不是代码缺口,是安装缺口,但后果一样。

- **`1015`(urxvt 鼠标编码)没关**:vendor 的 `NamedPrivateMode` 里没有它,这台终端进不去那个态——不是漏项。
