# 手势可发现性盘点(2026-08-26 · 只读审计)

盘点 Folio 全部**用户可触发的交互手势**,逐条判定「用户能不能自己发现」。

**口径**(先说死,免得判档看起来像口味):

- **甲 约定俗成** —— 浏览器 / VS Code / Windows Terminal / 资源管理器都这么用,用户带着肌肉记忆来。屏幕上有没有线索都不影响它被找到。
- **乙 容易发现** —— 屏幕上有线索。线索算数的五种:① 菜单里有**同义行**;② 有**可见按钮/图标**(带不带 tooltip 都算,带更好);③ 手势进行中有**落点高亮 / 光标变形 / ghost**;④ **自揭示**——用户只是把指针挪过去、什么都没多做,东西就自己出来了(所有 hover 浮层属此类);⑤ 快捷键提示卡列着(读 `shortcuts::BINDINGS`)。
- **丙 自创且无线索** —— Folio 自己发明的,且上述五种线索**一条都没有**。用户必须先知道才可能做出来。

**路径约定**:未加前缀的 `xxx.rs:NNN` 均在 `crates/bt-app/src/` 下;`bt-render/` 前缀者在 `crates/bt-render/src/`。行号对 HEAD `ce56864`。

**输入面的边界**(先钉死「全部」是什么):窗口事件分发在 `main.rs:76004-76060`,只有 `KeyboardInput` / `ModifiersChanged` / `CursorMoved` / `CursorLeft` / `MouseInput` / `MouseWheel` 六路是用户手势入口。**没有触摸、没有捏合、没有双指轻点、没有 OS 拖入**(`DroppedFile` 全仓无引用)。所以下面三张表就是全集。

## 丙档候选清单:为什么发现不了 + 最轻的够用露出

按「这条被错过的代价」排序。

### 丙1 · Cards 里的 `Alt`+滚轮(代价:中,功能等于不存在)

- **缺的是哪一层**:点用之处的线索全空。卡片列被 §7.1.6b′ 一次性判掉了 tooltip、判掉了 `⌄` 菜单,又在 2026-08-20 判掉了「卡上加新 affordance」,于是这个手势没有任何一个面可以站。`i18n.rs:3080-3090` 逐字承认了这一点——「A gesture that can only be found by holding down a key nobody was told about does not exist」——然后把那句话安置到了 Settings ▸ `Card height` 这个**讲高度的**行的说明尾巴上。用户不会为了滚动去读一个讲像素的滑块。
- **最轻的够用露出**:**一次性首到场示意**。第一次进 Cards 模式时,在卡片列脚下放一行会自己消失的小字「`Alt`+滚轮滚动卡片内容」,记一个 `seen` 位到 `settings.json`。它不占位、不接鼠标、不参与命中,所以不违背 2026-08-20 那条裁决的实质;它只说一次。
- **次轻的备选**(若拒绝首到场):卡片被悬停且**指针正在终端格子上**时,卡片右下角淡入一枚 8px 的滚轮小记号——只在悬停期出现,不接受点击。

### 丙2 · 拖出窗外撕新窗(代价:高,对 tab 是唯一门)

- **缺的是哪一层**:手势进行中的画面。落点被强制置空、ghost 被裁到窗外、光标不变——三条线索本来都存在,只是都在窗外失效了。再加上 tab 没有右键菜单,这个动词对 tab 而言无处可说。
- **最轻的够用露出**:**给 tab 补一个右键菜单**,先只放两行——`Move tab to new window` 与 `Close tab`。这是「菜单里有同义行」,一条就把丙2 变成乙,顺带补上本产品缺失的整个 tab 上下文菜单。
- **便宜的加强**(可选):指针离开本窗玻璃时,不止把 `landing` 置空,而让 **ghost 夹在视口边缘继续可见**(`seats.rs:16892` 处加一次 clamp),用户至少看得见手里还拿着东西。

### 丙3 · `Ctrl`+点本地路径 / 图片 = 交给系统(代价:中,用户会以为「点了没反应 / 开错了」)

- **缺的是哪一层**:修饰键的差别没有任何投影。web 地址那一行是设计过的(不按 `Ctrl` 就不给手指),本地文件那一行不是——两种目的地共用一个光标。
- **最轻的够用露出**:**把 `Ctrl` 的去向写进悬停状态行**。状态行已经在画了(`main.rs:13973`),把后缀从「只有 blocked 时才有」扩成「按着 `Ctrl` 时追加一句去向」,一处改动,零新面。
- **备选**:终端右键菜单在**指针底下有已验证引用时**多两行 `Open` / `Open with default app`——但那是新行、要判可用性,比上面那条重。

### 丙4 · 拖选即复制(代价:中,是「看不见的副作用」而非「用不到的功能」)

- **缺的是哪一层**:结果没有回执。这条与其它六条不同——用户做得出来,只是不知道自己做了什么。
- **最轻的够用露出**:**给它一个开关**。Settings ▸ Terminal 加一行 `Copy on select`,默认按现状(开)。一行设置同时解决两件事:告诉用户这件事存在,以及让不想要的人关掉。**不要**用 toast——每次拖选都弹一张卡是噪音。

### 丙5 · 录制框裸 `Backspace` 解绑(代价:中,是唯一门)

- **缺的是哪一层**:框内没有任何指示文字。`recording_state` 只回三样:行号、键帽、拒绝理由(`settings.rs:4550`)。
- **最轻的够用露出**:**录制期在框里放一句常驻小字**——「`Backspace` 解绑 · `Esc` 取消」。它已经有一个 hint 槽位(`capture.hint`),现在只在拒绝时才有内容;把「无拒绝时」的默认值填成这句即可,零新结构。

### 丙6 · 下载 sheet 的 `Esc`(代价:低-中,但会让人以为卡死了)

- **缺的是哪一层**:卡上没有关闭件,而遮罩与卡面都吞点击——用户能想到的三种关法(点 `×`、点外面、点卡)全部无效。
- **最轻的够用露出**:**给这张卡加一枚 `×`**。它是本产品五张失败卡里唯一一张「底下还有东西可以回去」的,所以加 `×` 不会造成 `websheet.rs:17` 担心的黑洞;这也是把它对齐到 toast / notice / float 三处已有的 `×` 惯例。

### 丙7(边界)· 拖未固定速览窗的头(代价:低,同结果有按钮门)

- **缺的是哪一层**:光标。`float_grasp` 对未固定的 peek 一律不给抓手,是有书面理由的(`main.rs:19466` 的注:未固定的东西不该显得能抓)。
- **最轻的够用露出**:**什么都不做也可以**。若要做,最轻的是让未固定 peek 的头也给 `Grab` 光标——但那与它的书面理由直接冲突,所以这条更应该走「留裁」而不是「补丁」。

## 系统性发现(三条,比单条手势重要)

**① 本仓有一条成文政策:「不为一个手势新造 UI 面」。** `docs/DESIGN.md:1793` 把话说透了——`Line wrapping · Off` 那句讲横滚的话,「与 §7.1.6b′ 拿 `DescFocusCardHeight` 还发现性那笔债是同一种交易」。也就是说,当一个手势没有可站的面时,本产品的既定做法是**把一句话塞进某个设置行的说明里**,当作把发现性的债还了。丙1 是这套交易的第一笔坏账,而用户的实测已经证伪了它:**设置行的说明句不是一个发现面**,因为读它的前提是用户已经在找这个功能。这条政策值得被重新裁一次——至少要区分「这个手势还有别的门」(可以只写一句)与「这个手势是唯一门」(必须有真的露出)。

**② 全窗没有任何菜单画快捷键。** `profiles.rs` 八族菜单全表无 accel 列(`5368` / `6064` / `6845` / `7985` / `9364` / `3400` / `4729` / `9646`),所以 `Close pane`↔`Ctrl+Shift+W`、`Zoom pane`↔`Ctrl+Shift+X`、`Find…`↔`Ctrl+F`、`Copy`/`Paste`↔剪贴板和弦,这几对「同一个动词的两扇门」在界面上从来没有被介绍过对方。提示卡(`keyhint.rs`)是从键盘那侧开的门,菜单这侧一扇也没开。**加一列 accel 是把十几条乙升级成「互相教」的最便宜的一次改动**,而且它只读 `Shortcuts::rows`,不新增数据源。

**③ 没有首到场,一次都没有。** 全仓无 `first_run` / `onboarding` / `coach` / `seen_once` 之类的任何机制。整个产品的教学面只有四样:tooltip(约 60 条,其中**只有三条印了键**——搜索胶囊的上一处 / 下一处 / 关闭)、菜单行、提示卡、以及五句藏在 Settings 说明里的教学话(`i18n.rs:2346`、`2905`、`2951`、`3098`、`2848`)。丙1 / 丙2 / 丙5 这类「唯一门且零线索」的手势,在没有首到场机制的前提下,只能靠加菜单行或加常驻小字来救——这三处补丁都很轻,但都需要先承认第 ① 条政策要开个口子。

## 附:不是手势、但同属可发现性的三个坑

- **`Ctrl+Shift+V` 不粘贴。** `is_paste_shortcut` 要求 `modifiers == CONTROL` **恰好相等**(`input.rs:25`),所以 `Ctrl+Shift+V` 落到编码器,给 shell 发 `^V`(0x16)。而 `Ctrl+Shift+C` 是能复制的——一个 WT 用户会先试这一对,然后只得到一半。
- **`Ctrl+Insert` 不复制。** 无任何分支,直接编成 `\x1b[2;5~` 发给子程序(`input.rs:205`)。`Shift+Insert` 粘贴是做了的,但这个词在全仓的用户可见字符串里出现零次。
- **`Select all` 在终端里只有鼠标门。** 菜单有 `Select all` 行(`i18n.rs:2700`),但 `Ctrl+A` 在终端里原样发 `0x01` 给 shell(`input.rs:184`)——这是对的;只是意味着这个动词没有键盘门,而菜单也没写它没有。
