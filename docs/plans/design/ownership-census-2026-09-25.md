# Who writes what: the ownership census, the asking/telling taxonomy, and what `bt-workbench` is born with — design note, 2026-09-25

Ledger rows: **D-11** (the split fixes file size, not coupling — the ownership census) and **D-8** (the asking/telling family has no taxonomy), as the ground for **D-57** (`bt-workbench` is born, 0.4.6) and for the 0.5 agent workbench (session / document / view ownership and side-effect contracts, ruled 2026-09-21). Read at `main` = `f7826bd4`. No code, no cargo run; anchors are names, never lines. The data behind §2 is committed beside this note as `docs/plans/design/ownership-census-2026-09-25.tsv` (one row per fact × module × function).

**Section signs.** A bare `§n` is a section of this note; `A§n` is a section of `docs/ARCHITECTURE.md`; `DESIGN §n` of `docs/DESIGN.md`; other documents are named where they are cited.

**What this note is not.** It rules nothing about UI: the asking/telling table is the owner's (`ARCHITECTURE` §8; D-8's ledger row: "the owner rules the table first"). §4's kinds are a proposal for that ruling. It moves no fact's owner; where a ticket below would (§6, marked (d) yes), that ticket waits for its own Codex-reviewed note (CONVENTIONS §十 rule 11).

## 0. In one page

- **The census.** `App`, `WindowRuntime`, `TabState` and `LeafSession` declare **436** fields (83 + 273 + 47 + 33). **393** are written somewhere after construction; **223** by one module; **170 by more than one** — 34 on `App`, 100 on `WindowRuntime`, 27 on `TabState`, 9 on `LeafSession`. That is the census table (§2). 2,099 write sites: 562 assignments, 1,206 mutating calls, 331 mutable borrows lent to a callee. Of the 170, **148** have more than one module writing other than by lending, and **67** are *assigned* from more than one module.
- **Most of it is not the A§4.2 problem.** A§4.2's five classes were drawn from twenty-two *cross-thread* facts. Every write in this census is on the window thread. Sorted by what the fact is, the 170 are: **67 view interaction state** (hover, press, drag, open menu, caret, scroll offset — no A§4.2 class; it is A§4.1's view owner), **42 projections**, **26 identity/lifecycle**, **10 durability**, **9 observations**, **8 asynchronous answers**, **5 document-model hubs** (A§4.3: `tabs`, `active_tab`, `seats`, `sessions`, `session`) and **3 resource handles** lent by `&mut` (`gpu`, `renderer`, `handoff_lane`), which are doors, not facts.
- **Why view state has many writers** — three shapes, all visible in the table: *routers* write each surface's state themselves (`chrome_mouse_input` writes 15 surfaces' state, `pointer_moved` 11, `keyboard_input` 7); *sweepers* reset many surfaces at once (`close_popup` 8, `cancel_composition` 7, `activate_tab` 7, `leave_preview_buffer_in` 7); *movers* carry one seat's view across five parallel `SeatId`-keyed maps (`move_seat_content`, `pane_into_new_tab`: `files`, `git_graph_view`, `git_scroll`, `preview_panes`, `preview_views`). The contract that removes all three is one: a surface's state has one module, and routers, sweepers and movers call its door.
- **Asking and telling.** 28 surfaces (§3). Their mutual priority is written three times — the rung order of `Runtime::keyboard_input`, the rung order of `Runtime::mouse_input`, and `KeyboardOwner::menu_or_dialog` — and the three lists already disagree (the restore card is absent from `menu_or_dialog` and answers keys only below the shortcut table, so a paste reaches the shell under it; ticket 57 is repairing the keyboard half in 0.4.5). Proposed: **seven kinds** — gate, instrument, toast, notification, mark, hint, log line — each with one rule (§4). Five places break their kind today (§4.1); one is a probable data-loss path (a window close while the dirty gate is already up is read as "nothing to ask": §4.1 V2, static, untested).
- **`bt-workbench`** can be born in 0.4.6 with `attention.rs` whole (the ledger depends on nothing in `bt-app` but `attention_wire::WAIT_TTL`), `WaitClock`, `attention_is_consumed`, and `notify`'s reach rule. The dependency on `WAIT_TTL` reverses; the window's attention place counter (census row 38, five lenders) becomes the ledger's own type. `deliver_attention`'s tab-traversing routing stays in `bt-app` until D-1's session registry (0.4.7). §5.
- **Seven tickets**, S or M, in order (§6). **Five open questions** (§7).

## 1. How the census was taken, and how to take it again

**The question asked of the code.** For every field `F` of the four structs: which non-test functions write it, in which module, reached from which trigger, and with which side effects near the write.

**Method** (a scratch script outside the repository did the arithmetic; everything it did is stated here so the table can be regenerated by hand or by the query of ticket A):

1. **Items.** Every `.rs` file under `crates/bt-app/src`, with comments and string and char literals masked. A function's owner is its innermost `impl` block's type; `#[cfg(test)]` / `#[cfg(all(test, …))]` items and every `*tests.rs` file are out.
2. **A write** is `.F` followed — possibly through sub-fields or an index — by `=` or a compound assignment; or by a call of a mutating method (the standard collections' mutators, plus every method name that the workspace, `vendor/` included, declares only with `&mut self`); or `.F`'s receiver chain preceded by `&mut` (a **lend**: the callee may write).
3. **The receiver is resolved by type, not by name**, which is A§4.3's instruction: `self.app.F` → `App`; `self.window.F` → `WindowRuntime`; `self.F` inside `impl Runtime` → `TabState` **through `Deref`**; `self.F` inside `impl X` → `X`; the navigation fields (`Runtime::{app, window}`, `FolioApp::{app, windows}`, `WindowRuntime::tabs`, `TabState::sessions`) and their elements (`[..]`, `get_mut`, `iter_mut`, `values_mut`, …); every function whose signature returns a reference to one of the four; each function's own typed parameters; and its `let`, `if let Some(..)` and `for` bindings whose expression resolves. What still does not resolve is attributed only when `F` is declared by exactly one struct in the crate (6 sites). **153** write-shaped sites stayed unresolved; sampled, they are other structs' fields of the same name (`SessionStore::session`, `FloatHost::pinned`, `ToastHost::toasts`, …) plus about ten real writes through untyped locals in `FolioApp::transfer_tab` and `Runtime::create` — the table under-counts those by that much.
4. **Module.** A file is a module, except `main.rs`, which is split the way `ARCHITECTURE` §13 splits it: `main[launch]`, `main[settings]`, `main[focus]` and `main[unassigned]` for its `Runtime` methods (by `docs/plans/bt-app-split-2a-manifest-2026-09-21.tsv`), `main[impl FolioApp]`, `main[impl <struct>]`, and `main[free fn]`. `main[free fn]` is one module in the count and hides breadth: `release_due_leaf_resize`, `drain_leaf_pty`, `deliver_attention` and the other free functions are called from many topics.
5. **Triggers.** A call graph over the crate's non-test functions (6,786 nodes, 12,838 edges; `self.m(`, `runtime.m(`, `Type::m(`, a free `m(`, and `x.m(` when `m` names one method in the crate), and reachability from six entries: **G** gesture (`keyboard_input`, `ime_input`, `mouse_input`, `pointer_moved`, `pointer_left`, the wheel and drop queues, `spend_parked_pans`, `raise_dirty_gate`, the modifier arm, `FolioApp::{route_clicked_notifications, answer_a_menu_row, settle_drag_handover, close}`); **O** OS event (`resized`, `window_moved`, `scale_factor_changed`, `os_theme_changed`, `redraw`, the `Focused` arms, `adopt_system_canvas`, `adopt_platform_chrome`); **L** lane answer (`FolioApp::user_event`); **T** turn clock (`FolioApp::about_to_wait_inner`, `Runtime::turn`, `service_ime_report`, not descending into `drain_pty`); **P** PTY output (`Runtime::drain_pty`); **S** launch (`Runtime::create`, `open_window`, `FolioApp::resumed`). "all" = all six.
6. **Effects at the write**: markers in the writing function's body or in a function it calls directly — **F** a frame (`request_redraw`, `present_chrome_change`, `publish_frame`, `present_seats_and_commit`, `redraw`); **W** a PTY write (`offer_pty_input`, `write_with_reason`, `send_user_input`, `paste_text`, `send_paste`, `flush_pending_pty_resize`); **D** a file write (`mark_session_dirty`, `.store(`, `store_keybindings`, `fs::{rename, write, create_dir*, remove_*, copy}`, `quit_save`, `save_preview_on`, `install_recorded`, `apply_recorded`, `add_to_profile`, `apply_psreadline`); **X** a process or thread (`create_leaf_session`, `spawn_at_priority`, `quiet_command`, `restart_shell`, the `begin_*` probes); **Q** a lane request (`*_worker.request`, the math worker's queues, `handoff_lane.submit`, `hand_off`, path-verification asks, `begin_monospace_scan`, `ask_for_file_indexes`). One level only, on purpose: transitively, every function under `keyboard_input` reaches every effect, which says nothing.

**Why no script is committed.** `crates/bt-source/tests/tripwire.rs` scans `.rs` **and `.ps1`** files for four shapes of source reader; a `.ps1` under `scripts/` that names a `.rs` path and reads it trips shape 2 ("a script is taken whole"), and a directory walk picking `rs` files trips shape 4. Python is outside the scan, but the Python source readers already in `scripts/dev/` are debt rows (`docs/plans/MIGRATION-DEBT.tsv`, class P0, D-19), and `scripts/ci/check-migration-debt.ps1` refuses an added row — so a new Python reader would be new debt the tripwire cannot see, which is worse than a red one. The sanctioned mechanism is `bt-source` (`syn` with `visit`, item identity, declared universes): ticket A (§6) makes the census a query there, with the committed TSV as its diff gate, and that also discharges D-18 (subject extraction by item, not by text).

**Limits, stated.** Lexical call resolution misses calls through closures stored in fields and trait objects; a write through a helper that takes the whole struct (`fn x(window: &mut WindowRuntime)`) is attributed to the helper, which is what a reader wants but not what a grep of the caller shows; "one level" of effects under-reports a write whose effect is two calls away. None of these changes a fact from single- to multi-writer.

## 4. The taxonomy — proposed for the owner's ruling (D-8)

The smallest set of kinds that covers the twenty-eight, each with one rule. **Kind** is chosen by what the reader is being asked to do, not by what the surface looks like; `notify::desktop_reach` / `interruption` and the attention ledger stay exactly as they are (`ARCHITECTURE` §8's first fixed point).

| kind | what it is | the one rule | members today |
|---|---|---|---|
| **Gate** | a question that must be answered before its scope (a window; the application for quit) is used | owns the keyboard **and** the pointer in its scope; Enter is the focused answer and Esc the answer that loses nothing; **one per scope, and a second question is answered "busy" — never "nothing to ask"**; no timer answers it | quit card, dirty gate, paste card; the restore card, first-run card and invitation are Q2/Q3 |
| **Instrument** | something the reader summoned on purpose | takes only the keys its focus implies; Esc puts away exactly one — the topmost; opening one in a slot replaces what held the slot; never appears unbidden | Settings, palette, search capsule, rename field, git prompt, menus, floats, web sheet, the system's pickers |
| **Toast** | a transient telling about what just happened, anchored to the surface it is about | no keyboard, no question; stays long enough to read (≥ 4 s); three per anchor, the fourth evicts the oldest; a loss it reports is also logged | toasts |
| **Notification** | a pane wants the reader, or news that outlives a toast | the reach ladder (marks < flash < desktop), seen is not answered, at most one desktop interruption per episode, answered from the pane | desktop message, taskbar flash; pane strips (ruled 2026-09-21) |
| **Mark** | state painted on chrome that already exists | no words beyond a number, no keyboard; a click does the one obvious thing or nothing; gone when the state is | attention marks, update dot, text-size mark, command rail |
| **Hint** | an explanation summoned by resting or holding | never the only copy of a fact, never a question; replaced by the next; dismissed by moving away; Esc may put it away and passes on | tooltip, key hint, card hint, glance card, layout peek |
| **Log line** | a record outside the window for whoever diagnoses | never the only way the reader learns something that changes what they should do | stall self-report, diagnostic notes |

**Enforcement** (the coordinator's decision 6 of 2026-09-21): once ruled, one declaration — a `const` list of surfaces with their kind — that `keyboard_input`'s modal rungs, `mouse_input`'s modal rungs and `KeyboardOwner::menu_or_dialog` all read, plus a generated `ARCHITECTURE` §8 table and a diff gate on the `check-shortcuts-table.ps1` pattern. A new surface adds a row before it adds a module. Ticket D.

### 4.1 Surfaces that break their kind today (these become tickets)

- **V1 — the restore card** (row 7). Keys reach the shell under it and it answers only below the shortcut table; ticket 57 (0.4.5) is making it own the keyboard, while DESIGN §7.1.4 and `restore.rs`'s module doc say *non-modal: a press beside it belongs to whatever is there*. A keyboard-owning, pointer-transparent surface is neither a gate nor an instrument. **Q2.**
- **V2 — the dirty gate answers "busy" with the word for "nothing to ask"** (row 2). `Runtime::raise_dirty_gate` returns `Ok(false)` both when nothing is dirty and when a gate is already open. `FolioApp::window_event`'s `CloseRequested` arm reads `Ok(false)` as "shut": a window close that does not pass through Folio's ladders (Alt+F4 or the taskbar's *Close window* while the gate is up for a close-tab, close-pane or git discard) sets `shutting` without asking about the buffers the gate is standing over. **Static reading; the path through `FolioApp::close` to the loss of the dirty buffer is not traced to the end and nothing was run.** A defect, not structural debt: it belongs on the adversarial-review ledger, and ticket E starts with its red test.
- **V3 — the status line** (row 17). A worker's death is put on one published frame and is gone at the next repaint (`take_math_worker_notice` and its siblings in `files`, `preview` and `git`: "worth exactly one frame") — in a busy pane, a sixtieth of a second, and a hand-off refusal's words use the same line with a dwell — two telling mechanisms beside the toast, one of which cannot be read. **Q4**, then ticket F.
- **V4 — pane strips** (row 15) are ruled notifications (2026-09-21) and are still strips. That is the 0.5 notification model's work (`docs/plans/design/agent-workbench-0.5-2026-09-20.md` §11–§13), not a 0.4.6 ticket; recorded here so the table is ruled with it.
- **V5 — the modal list is written three times** (§3's head) and already disagrees (the restore card). Ticket D.
