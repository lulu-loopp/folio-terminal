# Per-pane text size (terminal zoom) — design note, 2026-09-23

Owner rulings 2026-09-23: per pane, session only, 0.4.5. No code; anchors by name only.

**Verb names.** "Zoom pane" (`zoom-pane`, `Action::ZoomPane`, `toggle_pane_zoom`, 放大窗格) already means *make this pane fill the tab*, and `set_preview_image_zoom` / `wheel_zoom_notches` / `IMAGE_ZOOM_*` mean *scale a picture*. The new verb must not say "zoom" in code or UI: rows `text-larger`, `text-smaller`, `text-actual-size` ("Larger text" / "Smaller text" / "Actual text size"; the Chinese is opus46's to write); the field is `text_scale`, never `zoom`.

## 1. The fact and its owner
Today one `CellMetrics` per window (`WindowRenderer::metrics`, measured by `CellMetrics::measure_at` from `GpuContext::terminal_font_size_logical_px` × the window's scale) and copies pushed into every leaf (`DualPlaneSession::set_cell_*_subpixels`, `ViewportProjection`). New: **the pane owns a ladder index** `text_scale` (50 67 80 90 100 110 125 150 175 200 250 300 %; reset = the 100 rung; integer, so no float drift), stored on the *view* half of `LeafSession` beside `projection` so tear-out/merge carries it. The window keeps the **base** metrics and the scale factor. Every derived quantity has one source: a single `leaf_metrics(leaf)` = measure(base size × rung, window scale), memoised by (`font_environment_epoch`, logical size, scale). Grid, projection subpixels, mouse/selection mapping, IME caret, math key and the renderer's per-seat input all read that function; nothing else reads cell fields of `renderer.metrics()`.

## 2. What re-derives, where
All on the window thread (measurement is the same cheap call DPI already makes there). A step: re-measure (memo hit after first use) → `cmdrail::terminal_grid_for` for that seat → local reflow at once through `resize_leaves_to_layout`'s per-leaf path → the child is told through the existing `pending_pty_resize`, released by `flush_pending_pty_resize` after its 200 ms quiet window (session-transport lane; the PSReadLine re-anchor rides along). A wheel ramp of N notches is N local reflows and **one** `ResizePseudoConsole`. Renderer: `SeatFrame` gains the seat's `CellMetrics`; `ComposedRowKey` already carries `RowMetricsKey`, but `ShapeKey` (narrow/wide shaping caches) has **no size** and must gain it — the one silent wrong-size hazard. The glyphon `TextAtlas` in `GpuContext` is already keyed per glyph size; the per-frame trim bound (ink ≤ surface) still holds. A ladder, not a continuous scale, bounds atlas churn during a ramp. `sync_math_layout_key` keys by the leaf's size, not the window's `font_revision` alone.

## 3. Composition with DPI and Settings
Logical px = `drawable_font_size`(Settings base) × rung, clamped once (the R4-2 clamp generalised, effective range 8–72 logical px); physical = × window scale. Settings change: base moves, every pane keeps its rung (120 % stays 120 % of the new base). DPI change (`apply_scale_factor`): every distinct size re-measured at the new scale. `adopt_terminal_font` and `apply_scale_factor` today repeat the same "push metrics into every leaf" loop; both become one call of `leaf_metrics` per leaf. Order of events never matters because nothing stores a product.

## 4. Doors
**Keys:** three `BINDINGS` rows under a new `Scope::Terminal` (any screen; a preview or page keeps the chord), dispatched at the shortcut rung of `keyboard_input`, act on the focused pane. **Wheel:** a new rung in `mouse_wheel` after `seats::pane_at` has chosen a terminal seat and **before** `wheel_route` — so it outranks mouse reporting, alternate-scroll and local scroll; notches via `wheel_zoom_notches` with a per-seat carry like `CardAim`. Ctrl+wheel over a picture, a document or a page is untouched (picture zoom is plain wheel; a page zooms itself). **Indicator, owner's choice:** (a) nothing; (b) "120 %" in the pane head for ~1 s; (c) "120 %" in the pane head while ≠ 100 %, click = reset (recommended: session-only state that is invisible is state nobody can find, and it gives a non-keyboard path). **Persistence:** none — not in `session.json`; relaunch, startup restore and `reopen-closed` come back at 100 %; tear-out/merge keep it; `Restart shell` keeps it (same view).

## 5. Not changed
Preview panes, web panes, the files column and Git page, all chrome text (strip, heads, rail, cards, menus, Settings), pane padding and the rail lane (window scale), window minimum size (base metrics), the Settings font row and its stored value.

## 6. Tests that pin ownership
One owner: a source guard (the `file_reads_doors.txt` pattern) — cell fields of `renderer.metrics()` read only in `leaf_metrics`; `text_scale` written only by the three verbs; no copy on `TabState`/`WindowRuntime`/settings. Grid at 80/100/150 % for one seat rect, with and without rail. Sibling pane's grid and metrics byte-identical after zooming its neighbour. Five notches inside the quiet window → exactly one PTY resize with the final grid. DPI × scale: (Settings then DPI) equals (DPI then Settings) equals direct measure. Two panes, same text, two sizes → two shapes (the `ShapeKey` fix). Session snapshot unchanged by a zoom. Shortcuts table/`docs/shortcuts.md` generator gate.

## 7. Structural debt
Repaid: `renderer.metrics()` serving two facts (≈175 readers want only the DPI scale, the rest the grid) splits into `window_scale()` and `leaf_metrics`; the duplicated per-leaf push loop collapses. Advanced: D-1 — the field is view state and must land on the view half, per D-1's warning against moving client font state into the session. Added: a new rung in `mouse_wheel`/`keyboard_input` (§8's undocumented rung order grows by one — write it down) and, if (b)/(c), a surface row for D-8. Not one of the 22 cross-thread facts: it is window-thread only.

## 8. Risks and questions
Risks: a missed reader maps a zoomed pane with window metrics — mouse cell, selection, IME caret or link hit silently off by the scale (the guard is the answer); tiny grids at 300 % in a narrow pane; atlas churn on a fast ramp; Ctrl+wheel taken from TUIs that read it via mouse reporting.
**Q1.** Windows default chords: Ctrl+= / Ctrl+− / Ctrl+0 (browser and Windows Terminal habit) break "Control is left to the terminal", and Ctrl+− is ^_ (readline/Emacs undo in bash/WSL); or Ctrl+Shift+= / Ctrl+Shift+− / Ctrl+Shift+0? (Mac: Cmd+= / Cmd+− / Cmd+0, no clash.) Ties to #4.
**Q2.** Indicator (a)/(b)/(c)?
**Q3.** Ctrl+wheel acts on the pane under the pointer (every other wheel in Folio does) rather than the focused one, and a split/duplicate starts at 100 % rather than inheriting — agreed?

## Owner rulings (2026-09-23)

1. Windows keys: Ctrl+Shift+= / Ctrl+Shift+- / Ctrl+Shift+0 (bare Ctrl stays the terminal’s; Ctrl+- is ^_). macOS: Cmd+= / Cmd+- / Cmd+0.
2. Indicator: while a pane is not at 100 %, its head shows the percentage (e.g. 120 %); clicking it resets to 100 %. Nothing is shown at 100 %.
3. Ctrl+wheel acts on the pane under the pointer, like every other wheel action; a split or duplicate starts at 100 %.

## Codex review folded in (2026-09-23, gpt-6-astra / high, against 5833ef14)

Verdict: **adopt with changes**. Full text: `codex-zoom-review/review-pane-zoom-2026-09-23.md`. Owner direction stands; the note was not ready to authorise implementation. What changes, in Codex's order, and what the ticket must therefore say:

1. **Lifecycle, not just owner.** `text_scale` is the view's *requested rung*; measured metrics, projection, pending PTY size and presented-frame metrics are observations. The ticket writes a lifecycle table: birth/split/duplicate start at 100 % with the grid derived from the new view's metrics before spawn; tear-out/merge move the `LeafSession` (no copy in transfer metadata); cross-window transfer keeps the rung and re-derives at the **destination** DPI (`transfer_tab` runs no DPI loop today); `Restart shell` replaces the whole leaf (`restart_shell` → `create_leaf_session`), so the constructor takes the rung explicitly and a failed restart leaves the old leaf untouched; relaunch/restore/reopen omit it from `TermLeafV1`/`TabV1`/`SessionV1`/seeds. `card_skip` is the warning: it sits beside view fields and is persisted anyway. "Written by three verbs" becomes "one mutation door plus documented constructor/transfer operations".
2. **The reader inventory is the contract.** Not "one shaping hazard": both `NarrowShapingCache` and `WideShapingCache` (`ShapeKey` has no size, cached offsets depend on cell/baseline geometry); `table_paints`/`table_blocks` keyed by source text only (two identical tables at two sizes share one paint); every `WindowRenderer` internal `self.metrics` reader (`compose_frame`, `prepare_text_rows`, `prepare_math_draws`, `cell_rect`…); `ime_cursor_area` (hidden renderer read); hit tests (`pane_frame_hit`, `forwarded_mouse_hit*`, `drag_hit_in_pane`, `hovered_leaf`, `reference_run_rect`); wheel conversions (`take_forward_wheel_notches` has no seat parameter); math geometry queries; `resize_leaves_to_layout`/`resize_hidden_leaves_to_layout` (window metrics for every leaf); both `SeatFrame` construction paths (`redraw`, `retained_seats`). Presentation: `frame_matches_grid` checks cols/rows only and `PresentGate::SeatSignature` has no metrics — pair every pending/retained/presented frame with its metrics identity, and hit testing never mixes a last-presented row map with a newly requested cell width. Legitimate base/chrome readers (`line_height_subpixels` for chrome scrolling, `command_flash_layer` padding, `seat_metrics`/window minima) get a **named base/chrome interface** rather than being funnelled through a leaf.
3. **One derivation, precise clamps.** `effective = clamp(validated_base × rung, 8, 72)`; base validation stays `drawable_font_size`'s 10–24 (changing raw Settings validation is a separate decision); measure through `CellMetrics::measure_at` (expose a narrow service, do not duplicate its arithmetic); reuse `GpuContext::font_environment_epoch` for memo invalidation; one apply operation for size actions, Settings, DPI, creation and transfer, which updates subpixels/projection/layout key/frame identity even when the integer grid is unchanged. Corrections: `flush_pending_pty_resize` still runs `ResizePseudoConsole` synchronously on the window thread (the lane move is D-44, 0.5→0.6; reuse the exception, do not claim it); "N notches = N reflows and one OS resize" is wrong — bursts merge before `flush_wheel`, `plan_grid_change` reflows only on integer-grid change, `commit_leaf_resize` sends nothing if the final grid equals `conpty_grid`; the guarantee is *at most one* child notification per pane after the quiet boundary. The ladder has no 120 %: examples use 125 %; at base 10 px, 50 % and 67 % both clamp to 8 px — the indicator shows the requested rung, the tooltip the effective px.
4. **Input ruling before code.** Keys go through `Shortcuts::lookup`/`run_shortcut` with a new `Scope::Terminal` = `keyboard_owner_is_a_shell` (not `!focus.preview`; extend `Focus`, `Scope::holds`, labels, recorder, `webhost::claimable_chords`); decide whether the rung inherits "no action on repeat". Wheel: the new rung sits after terminal targeting **and before the math-block pan branch** (which precedes `wheel_route`); exact Ctrl on Windows (a blind `control_key()` takes Ctrl+Alt/Ctrl+Shift), Cmd on macOS — `no_macos_column_promises_a_control_pointer_gesture` rejects a literal "Ctrl+wheel" in Mac strings; it takes Ctrl-bit mouse reports from TUIs, which DESIGN §7.1.5f/§7.1.6b′ already reserve for scale — write the priority into RULES row 28; the 64-case `a_wheel_notch_belongs_to_the_pane_it_is_over_on_either_screen` has no Ctrl input and would stay green — extend it; `mouse_trace` line and route vocabulary gates apply. Carry: integer carry in the original currency like `CardAim`/`WheelBurst::less_notches`, reset on target/modifier/route change, defined reversal at the bounds.
5. **Atlas: no area proof.** `GpuContext::close_the_frame` already retracts the "one frame's ink fits" argument (bucketed allocator fragments across sizes). Keep unconditional frame closure, once-per-episode repack, `PresentedWithoutText` retry; extend the atlas soak to simultaneous mixed-size seats and alternating windows.
6. **Discriminating tests.** Of the proposed tests only "same text, two sizes → two shapes" is behaviourally red on base; the rest are vacuous or already green until the derivation/apply seam exists (see review §6 for the acceptance list: restart/transfer/renumber, two live panes at two sizes for selection/SGR/links/IME/formula/tables/scroll, retained and skipped presentation, identical-table dedup, Ctrl routing across modes, clamps and font-face change, mixed-size atlas stress). D-1: "aligned", not "advanced", unless a real view-owned configuration boundary is delivered. D-8: add the indicator's row (pane state / non-urgent / nonmodal / existing pane-head control) before implementing; specify where the badge lives when the pane head is absent or collapsed.

**Q1 reopened.** Codex: Ctrl+Shift+− is not conflict-free either — on a US layout it produces `_`, `control_byte("_")` = 0x1f = ^_, and `Chord::matches` accepts the produced character, so the binding takes exactly the readline-undo chord. Conversely Folio's encoder returns `None` for `control_byte("-")`: bare Ctrl+− sends no control code today. Recommendation: **Windows Ctrl+= / Ctrl+− / Ctrl+0** (the browser's own keys, the owner's stated model) as a documented terminal-scoped exception to "Control is left to the terminal"; test both spellings on shipping layouts and record the consumed chords; extend `takes_a_shell_control_key` disclosure to punctuation.
