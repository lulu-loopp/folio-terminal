## P2 · R-C — The meter needs a return context, not just an enter notification

**Exact targets.** §7 item 2's `Meter { enter: fn(DoorKey), leave: fn(DoorKey, Instant, Instant) }` and “`hang_watch` registers `enter` as its station push”; §8's “a `leave` that does what `during`'s exit does today”; §10's “the clock reads do not double”; §3.4's “the exit line `hang_watch` already writes.” Revision (b)4 changes unwind behavior, not these requirements.

**Code anchors.** `hang_watch::enter` returns `Location::Resume { station, node, scope }`. `during` saves that value and passes it to `at`; `Heartbeat::resume_at` restores all three pieces. `hang_watch_detail::Ledger` is a bounded, aggregated call tree, not a push/pop stack of dynamic invocations; overflow can leave it without a node for the entered call. `enter` and `at` each read the clock. The normal footer is produced by `diagnostics::run_footer` and sent by `main` through `trace_sink::stderr_line`; the watchdog's `watch_forever` has no exit-summary path.

**Consequence.** The proposed callbacks cannot directly substitute for `during`: the `Location` returned at entry is discarded, and `(DoorKey, start, end)` cannot reconstruct the caller's previous station, tree node and scope. Repeated same-door calls, pane scopes and exhausted call-tree capacity make “recover the parent from the door key” insufficient. An additional adapter stack could solve this, but its owner, capacity, nesting and unwind behavior are unspecified. Calling today's `enter`/`at` plus admission's two `Instant::now` calls also adds clock reads; removing an outer `during` does not by itself keep the count at two. Refusal reporting is assigned to a footer that the named module does not own.

**Obligation.** Specify how the entry's opaque return context reaches its matching leave. A shared numeric cookie held by `admitted`, with an explicit representation for the application's `Location`, or an explicitly owned bounded adapter stack can work without importing bt-app into bt-platform. Preserve station, node and scope, including nesting under `during_pane`, recursive/same-key admission and detail overflow. Provide deterministic tests of restoration and inclusive nested intervals, not only “station visible inside work.” Decide whether entry/leave receive admission's timestamps or take additional readings, and state the actual cost for A3 to measure. Pin the real refusal-summary writer and its output path.

The two-half meter is justified. I accept (b)4's explicit no-leave-on-unwind policy as a departure from the initial guard proposal; this finding does not ask to restore that guard. A caught panic does not promise that every later report forever retains that station: subsequent `at`, scope restoration or turn initialization can change it.

## P3 · R-A, R-C — Owner conversion is not yet an effect-level inventory

**Exact targets.** §11 A1d's list beginning “the owner-thread doors of B§R-A converted in place”; §8, “A1d wraps them in `admitted` where they are owner-thread rows”; §7 item 1's “today's single callers `create_leaf_session` and `Runtime::flush_pending_pty_resize`”; §4.4, “one admission pays for one door call.”

It first may reflow the actor and subsequently reconciles its resize transaction. `create_leaf_session` does substantial preparation before `PtySession::spawn_shell_in`. **Consequence.** Wrapping the outer resize flush once measures a multi-pane operation, not each raw resize, and granting an `expect` to that outer function will not authorize the listed method inside the separate `commit_leaf_resize` item. Refusing after the actor's partial mutation also differs from refusing before the operation. ## P4 · R-A, R-G — Revision (b)'s Drop debt is better specified, but still not closed or accurately scoped

**Exact targets.** §7 item 4, “only A2's lint … closes it”; (b)3's replacement exception table and “each of these waits can reach the window thread … an endpoint dropped at quit”; the `PtySession` row's “reader/writer joins.”

**Code anchors.** `trace_sink::Shutdown::drop` calls `flush` → `flush_sink` → `recv_timeout`, polling sleeps and a conditional join. `main` holds `_trace_shutdown` before `EventLoopBuilder::build().context(...)?`. It is absent from the revised exception set. `attention_wire::open` and `launch_wire::open` install successful endpoints directly in static `OnceLock<Option<_>>` values; their four platform `Drop` implementations join, but the product does not drop those static endpoints at quit. The Unix implementations explicitly document that lifetime. `PtySession::shutdown` detaches the writer (`self.writer.take()`), bounds the reader join, and drops the native master; `PtySession::drop` additionally finishes an input dump, which can write and `sync_data`.

**Consequence.** The revised list omits a product destructor containing a transitive wait. Its reachability needs care: normal exit explicitly flushes and calls `leave_process`, bypassing this guard. The early `build()?` return would drop it, but the pinned Windows/macOS constructors return `Ok` on the normal first construction; I have not established a reachable construction error in this product. The primary panic hook also terminates the process; its secondary-panic branch permits unwind. Thus this is an inventory and cleanup-policy gap, not a confirmed normal-exit stall. Similarly, the claimed ordinary endpoint-drop-at-quit path is not established; the successful product lifetime is static. The PTY description misstates the writer behavior and omits effects beyond joins. More generally, a resolved lint on `join` does not infer a destructor's transitive behavior: a `Drop` can call a permitted synchronous helper, including a newly admitted owner door, while containing none of the vocabulary itself. Registering `shutdown` does not automatically prohibit its use from `Drop`.

**Obligation.** Extend the revised inventory through real destructor call chains, including `Shutdown`, and distinguish product reachability from a public API's possible use or test-only destruction. Record the exact authorized effects/helper chain per exception, not merely a type-wide allowance into which new waits can be added. Give each temporary exception its repayment and version, as (b)3 now correctly requires. Specify how indirect destructor calls are fenced: explicit retirement requiring unavailable worker authority, or pinned destructor/helper edges with mutations proving that adding or extending an indirect blocking path fails. Do not claim Clippy supplies a call-graph prohibition it does not implement.

This is a disagreement with the completeness and reachability claims of (b)3, not a repetition of GLM's missing-`VideoSeats` finding. A bounded, reviewed list with real repayments is debt; a blanket exemption for these types is a permanent permission. Preserve native-resource/callback lifetime safety when repaying it. In particular, “remove the join” is not a valid repair for `DirWatch`'s handles, and “make PTY Drop a no-op” is not a valid repair for failed retirement-thread creation.

## P8 · R-A, R-C — The doctest pairs do not yet prove every claimed property

**Exact targets.** §9.2's “The pair proves the failure is caused by that statement” and its M3r/M4b/M4e/M4f/M5 rows; §9.1's source assertions for trait implementations and door signatures; §9.3's exact per-door counter increments and worker passing control.

**Code anchors.** `rust-toolchain.toml` pins 1.94.1. In that release, rustdoc passes `ErrorCodes::from(…is_nightly_build())` to the collector, and checks error codes only when the parsed list is nonempty. Thus the note is right about ordinary stable doctests: its E-code tag does not assert the reason. This follows from the pinned [rustdoc collector and runner](https://github.com/rust-lang/rust/blob/1.94.1/src/librustdoc/doctest.rs) and [language-tag parser](https://github.com/rust-lang/rust/blob/1.94.1/src/librustdoc/html/markdown.rs), not a run. The existing band tests exercise kernel priority; `HandoffLane::start` can run recording executors that never call `ShellThread::hand_over`.

**Consequence.** A passing control helps detect shared setup errors, but an error introduced by the mutation can still be unrelated to its claimed invariant. In particular:

- M3r's `thread::spawn` capture of a lent `&WorkerCtx` also violates the required `'static` lifetime. It can remain compile-fail after the non-Sync marker is removed. It does not independently prove either owned `WorkerCtx: !Send` or borrowed nontransferability.
- M4e likewise combines token transfer with a `'static` escape. Returning `&token` in M4b additionally fails because it borrows a local value; that alone does not test generativity. A mutable `static` in M4c can fail because of unsafe/static rules rather than scope escape.
- M3r′ and M4f explicitly have no matched control. M5's worker row names only the boxed closure mutation, not the promised function-pointer pair. The by-value single-use claim in §4.4 has no explicit consume-twice test. A recording executor does not establish that the real hand-off receiver retains thread affinity.
- Several refusal tests share `doors::Probe`'s atomic counter. A process-global install-once meter and counter deltas of exactly one need an isolation protocol; fresh test threads isolate TLS, not atomics or `OnceLock` installation.

**Obligation.** Keep compile-fail doctests, but make each case sensitive to removal of the property it claims. Add independent type-bound probes for Send and Sync, and scoped-thread transfer cases free of the unrelated `'static` obstacle. Use separate owned-token escape tests for the higher-ranked lifetime, safe outer storage, privacy, wrong identity and double consumption. Supply complete compiling controls for each named variant, and execute valid worker/owner indirect calls through both a box and a function pointer. Reuse the actual hand-off refusal path for a real-producer control, and cover `ShellThread`'s own nontransferability since it is the long-lived authority after `enter` returns. Specify meter/counter isolation and assert duplicate window entry cannot reset Running to Starting.

For properties the compiler can check, prefer typed assertions over reading syntax: instantiate `Door` constants to compare registry metadata; coerce effect functions to signatures carrying the expected token; check sealing, privacy and auto-traits through external compile cases. Retain source inspection for ownership/call-site inventories and unsafe/FFI policy. Counting trait `impl` text alone does not cover derives, and counting `WorkerCtx {` does not establish unique construction through every `Self` spelling. If exact diagnostic reasons remain an acceptance requirement, use a small pinned compiler-diagnostic harness; no rule requires adding trybuild or matching all stderr. Otherwise explicitly adopt the weaker, property-isolating paired-proof contract. Do not call a wrong-code canary a proof that every other mutant failed for its intended reason.
