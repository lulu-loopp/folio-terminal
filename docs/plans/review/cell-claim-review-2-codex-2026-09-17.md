## Must-fixes
**P2 — synchronized inline images still capture the wrong grid (A:783-798,928-936; S:9843-9855).** This pre-existing sibling is terminal correctness, not crafted claim laundering, and falls under bar (ii).
Repro on 40x4: `CSI ?2026h; CSI 3;5H; OSC 1337;File=inline=1:<PNG> BEL; CSI ?2026l` (semicolons between sequences are explanatory). The label is at zero-based (2,4), but InlineImage reports Primary(0,0). Insert `CSI ?1049h` after BSU: label is Alternate(2,4), event still Primary(0,0). Session registers that wrong anchor; default hover/peek metadata is affected even with image bands disabled.
Independent safety assertion failed (expected Primary(2,4), got Primary(0,0)); a generated, successfully decoded 1x1 PNG confirmed both wrong answers at every byte split. Final observation assertions passed and do not establish safety. Order image cursor/screen/placeholder-width capture after preceding buffered writes; add sync, screen-swap and right-margin controls.
**P2 — prompt atomicity promise is false (D:2069; matching comment A:813-820).** Every recognized shell marker ends the block, including A/B; the code has no exception for prompt drawing. `BSU left A` exposes `left` and clears the deadline; subsequent `prompt B input ESU` draws unsynchronized. A/B need not delimit different real-world moments. Only when all intended drawing precedes the first marker is that drawing committed whole. Remove the unconditional whole-prompt guarantee and document possible partial redraws when a producer embeds markers in a block. This is a documentation must-fix; no named healthy producer was proved to show the flicker.
