1. CONFIRMED — production Windows Mailbox, macOS Fifo; the offscreen Fifo is irrelevant.
render:4744–4767 inherits get_default_config and changes format, alpha, latency=1; wgpu/api/surface.rs:89–99 chooses the first advertised mode. hal/dx12/adapter.rs:1316–1319 advertises Mailbox, Fifo, then conditional Immediate; hal/metal/adapter.rs:463–467 starts with Fifo. render:7685–7698 explicitly sets Fifo/1 for FrameTarget::Offscreen. The second actual surface.configure call, render:11111–11117, reuses self.config; resize only updates dimensions (render:8428–8438).
Production CompositionVisual is passed at render:4704–4705 and is DX12-only in core/instance.rs:382–387. DX12 composition uses CreateSwapChainForComposition and FLIP_DISCARD (hal/dx12/mod.rs:1538–1551).
All modes get FRAME_LATENCY_WAITABLE_OBJECT; ALLOW_TEARING is a creation flag only when supported (hal/dx12/mod.rs:1477–1486). Present is Mailbox=(0,0), Fifo=(1,0), Immediate=(0,DXGI_PRESENT_ALLOW_TEARING); no DO_NOT_WAIT or TEST flag (1832–1843). Mailbox therefore has no nonblocking-call guarantee. Metal Fifo enables display sync, not a literal DXGI interval (hal/metal/surface.rs:223–226,289–290).
SetMaximumFrameLatency(1) and (latency+1).min(16) produce two buffers (hal/dx12/mod.rs:1501,1678). Obtaining/waiting on the handle additionally depends on latency_waitable_object (1681–1687,1734–1739); Folio currently uses the default Wait, not an explicit policy.

2. CONFIRMED for Folio's DX12 path; WRONG if “acquire cannot be made short from outside” is absolute.
core/present.rs:32,175–180 supplies 1000 ms. wgpu/api/surface.rs:148–199 has no timeout/try-acquire parameter. DX12 WaitForSingleObject returns Ok(false) at timeout (hal/dx12/mod.rs:1424–1447); acquire discards that bool and constructs a successful texture (1731–1762). No DX12 Timeout/Occluded construction exists; core/present.rs:263–265 only maps errors the backend actually returns. Thus render:11155–11167's Timeout/Occluded arms are unreachable for this production DX12 surface.
DX12 Present also turns the HRESULT into success/error without exposing an occlusion status (hal/dx12/mod.rs:1841–1845); Microsoft's [DXGI_STATUS documentation](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status) says flip-model swapchains do not return DXGI_STATUS_OCCLUDED.
N:40's “1022 ms is that constant expiring” is UNPROVEN: elapsed station time is not a recorded WAIT_TIMEOUT result. N:42's “constructed on Metal only” is literally false across backends: hal/vulkan/swapchain/native.rs:455,476 and hal/noop/mod.rs:215 construct Timeout too.
A public backend option can remove DX12's internal wait: types/backend.rs:869–872, below. That does not supply a portable nonblocking get_current_texture or bound driver/lock/configure work. Metal really ignores timeout and disables drawable timeout (hal/metal/surface.rs:285–287,300–332).

3. WRONG as the proposed gate; CONFIRMED that a corrected Windows gate is possible without a fork.
The handle is public: wgpu/api/surface.rs:233–238 → core/as_hal.rs:252–262 → hal/dx12/mod.rs:654–657. as_hal requires all HAL safety rules and forbids destroying an in-use resource (wgpu/api/surface.rs:224–229); its guard retains the surface, not a frozen swapchain configuration.
Caching the borrowed HANDLE across configure is invalid even if the COM swapchain survives: configure takes the old SwapChain and calls release_resources before ResizeBuffers (hal/dx12/mod.rs:1503–1508); release_resources closes the handle (1417–1419); configure obtains another handle (1681–1685). unconfigure closes it too (1710–1721). A held as_hal guard does not prevent these &self operations.
WaitForSingleObject(h,0) is a consuming wait, not a peek. Microsoft's [zero-timeout semaphore example](https://learn.microsoft.com/en-us/windows/win32/sync/using-semaphore-objects) explicitly decrements the count; [DXGI's contract](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgiswapchain2-getframelatencywaitableobject) pairs a wait with every rendered frame, including the first.
Trace under Folio's defaults: external wait consumes readiness → get_current_texture passes 1000 ms → acquire locks swapchain (1731) → Wait arm calls sc.wait (1734–1738) → second WaitForSingleObject (1434) → no remaining credit in the first-frame/empty-queue case → timeout → ignored false → GetCurrentBackBufferIndex, increment acquired_count, clone resource (1742–1762) → submit → Present decrements acquired_count (1828–1843). This can introduce a one-second stall on a READY frame. It is not necessarily permanent deadlock, because the internal timeout is ignored; nor is “half the frame rate” a universal prediction.
The missing solution is Dx12UseFrameLatencyWaitableObject::DontWait: it obtains the handle but explicitly delegates waiting to the application (types/backend.rs:860–872; hal/dx12/mod.rs:1681–1685,1734–1738). Folio creates default descriptors at render:6322,6444,6635; types/instance.rs:67–73 does not read environment overrides. Set the option explicitly wherever the gated GPU context is created/rebuilt.
Specify one readiness-credit owner per surface generation. Poll only after deciding an actual present is owed; a successful poll must fund exactly one Present, or retain that credit across a recoverable pre-present failure, or retire the corresponding chain. Never poll again merely because an unchanged/hide/coalesce path returned early. Missing/failed handles need distinct outcomes, not “not ready.”

4. WRONG — A is neither a trustworthy visibility test nor a harmless early return.
The proposed return at N:58/102 is Ok(None). app:104854 accepts None in the SAME arm as Presented, advances presented_picture_revision and clears unpainted_pane_output (104870–104878), replaces every last_presented_frame and marks panes painted (104921–104932), and clears pending_resize_present (104940). A skipped changed/resize frame would be credited as glass. Retained rendering clears chrome_present_pending at entry and accepts None without restoring it (104499–104501,104595); only SkippedNotVisible preserves debt (104623–104633,104955–104968). The existing hidden-preclear test only compares signatures (crates/bt-app/src/present_gate.rs:169–174); it cannot catch this.
The four booleans are not an authoritative “nobody can see this” fact. app:104365–104368 reads cached attention samples; their writers are app:84767–84771,85489–85491,117503–117506. platform:7155–7174 samples the centre and two quarter-inset points; 7217–7219 returns false when all three miss. Counterexample: place another window over Folio's central 60% rectangle, covering all three probes while leaving a wide visible border/tab strip. A freezes the visible portion indefinitely even with perfectly fresh samples. “Restore wake” cannot fix a predicate that remains false.
Windows visibility inventory and restoration obligations:
- Minimized: IsIconic is authoritative for minimization (platform:6943–6946; app:25219); WM_SIZE becomes Resized (winit/platform_impl/windows/event_loop.rs:1397–1417). app:101481–101485 intentionally ignores iconic geometry. Restore must refresh the admission fact before presenting, preserve debt, and request a frame; an old attention sample is insufficient.
- Covered by another window: winit Occluded is unsupported on Windows (winit/event.rs:421); IsWindowVisible only checks style and may stay true under total cover ([Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-iswindowvisible); winit/platform_impl/windows/window.rs:147–148). The three-point hit test is a notification heuristic, not a compositor occlusion oracle. No dependable uncover wake is established by this design; do not use this heuristic to suppress presentation.
- Cloaked/other virtual desktop: DWMWA_CLOAKED is queried at platform:6967–6998 and folded into hidden at app:25219, but no cloak/uncloak subscription was found in crates. Windows provides [EVENT_OBJECT_UNCLOAKED](https://learn.microsoft.com/en-us/windows/win32/winauto/event-constants); the design must name an actual owner-thread wake/re-query path before using cloak state as a lasting veto.
- Quake hidden / initial show: set_visible(false) is app:39853–39857; show explicitly publishes and redraws both before and after ShowWindow (39862–39891). This is an existing wake, but its second redraw still reads cached hidden/exposed state. A removes the pre-clear and miscredits it via None; first-show/DPI/retained debt must be tested at the caller, not assumed safe.
- Zero client extent: NOT part of PresentConditions.visible. app:101484–101485 and render:8428–8430 skip zero-size resize, retaining the old config; unrelated redraws can still acquire the old nonzero surface. Use current client extent as its own reason and a nonzero resize wake.
- Monitor asleep: none of the four bits establishes display power. Session-display off/on is available through [GUID_SESSION_DISPLAY_STATUS](https://learn.microsoft.com/en-us/windows/win32/power/power-setting-guids) and [registered WM_POWERBROADCAST notifications](https://learn.microsoft.com/en-us/windows/win32/power/registering-for-power-events); no such registration/handler was found in crates. It is session-level evidence, not proof about each physical monitor/window.
- Session locked / RDP disconnected: not encoded by these bits. [WM_WTSSESSION_CHANGE](https://learn.microsoft.com/en-us/windows/win32/termserv/wm-wtssession-change) provides lock/unlock and remote disconnect/connect only after registration; no WTS registration/handler was found in crates. A generic show/restore hook does not cover these transitions.
A must preserve document service/landing and the last acknowledged picture while retaining hidden debt. DESIGN §7.1.5p (docs/DESIGN.md:2384) and app:89128–89137 make landing a document operation, not proof of presentation. app:104513–104544 already resamples retained transforms before the funnel; skipping there changes what reaches glass even though the methods themselves are “untouched.” A responsive loop with false-negative visibility can freeze the image without triggering the UI hang watch.

5. WRONG as a bounded-input proposal; several narrower implementation claims remain UNPROVEN.
N:74's force-present-after-N explicitly violates N:19's one-interval invariant. It restores the exact multi-second input block being fixed; a deadline schedules an attempt, it cannot bound Present. N:70's “removes the single long present” also contradicts N:72's admitted residual. “Landing slips only one interval” (N:76) is false under repeated deferral, driver blocking, or failure; retain unpaced document landing and separately track the owed endpoint picture.
The retry must own an absolute deadline/age independent of frame replacement and unrelated event arrivals. A freshly recomputed now+interval can be pushed out forever; a count incremented on every event can exhaust N immediately during a flood. Once last_present_at is old, the existing pacer admits work (app:85807–85810); merely not stamping it can allow repeated composition/redraw churn while the compositor stays unavailable. Require bounded attempts/preparation across all windows, and zero polling with no debt (CONVENTIONS:405–409).
IME is not presentation-coupled today: app:67343–67359 offers the composed frame's caret BEFORE slot publication; app:62415–62426 sends it through the throttle, and app:84433–84441 updates the native candidate anchor/system caret. Deferral can leave candidates at the new cursor while the old text is displayed. Specify which picture owns anchoring during deferral and require a delayed-present IME/resize test; “untouched” does not establish coherent behavior.
CONFIRMED: focus cards are CPU projections/chrome, not several swapchains (crates/bt-app/src/focus_thumb.rs:48–57; crates/bt-app/src/seats.rs:8798; app:41965; render:10219–10225 has one submit/present). Actual separate windows remain serial on one UI thread (app:113873–113883); per-window wait budgets can accumulate and one forced fallback blocks every window.
Resize is underspecified. The renderer configures AFTER preparation and BEFORE acquire (render:9705–9711); a gate outside it can consume old-generation readiness before that handle is closed. Moving the gate after configure leaves configure's GPU/present-queue wait on input (wgpu/api/surface.rs:103–118; hal/dx12/mod.rs:1488–1490). CPU-only pending data avoids live-texture configure panic, but still needs generation validation and H:64–79's protected resize rule; “newest replaces anything” must not erase admitted resize debt. Deferring after uploads must retain/drain them and close atlas obligations, as render:11081–11091 and H:101–105 require.
Device loss must outrank hidden/not-ready decisions. Today's unchanged skip is disabled when loss is latched (app:104184), and the callback only records a latch (render:6208–6219); recovery is reached through failure handling (app:116590–116603). A new early gate must not conceal loss, hold a dead HANDLE, or carry old CPU/renderer identities into rebuilt surfaces. Define cancellation, rebuild wake, and fresh configuration/credit ownership.
“Presents deferred ×k” is reachability evidence only. It neither names the affected window/frame/beat nor proves successful presentation, visible freshness, or input dispatch. The tally is process-wide (render:4066,4139–4143); hang_watch:2464–2472 emits it in a hang report, which may never exist if B simply freezes pictures with a healthy pump. N:115 can therefore pass by rendering nothing.
Default-off is useful containment, not validation. diagnostics::switched_on treats “off” and “0” as ON (crates/bt-app/src/diagnostics.rs:135–136). Initial rollback requires clearing/unsetting the variable and restarting; later default-on needs a tested explicit off parser. For B, rollback must also restore backend Wait on every fresh/rebuilt context; disabling only the external gate while leaving DontWait changes baseline pacing.

Blocking objections (five; most severe first; obligation IDs for the review ledger):
- O1 — Do not acknowledge an unpresented picture. Reject A's Ok(None); preserve pending terminal/chrome/resize debt, old hit-test frames and painted revisions on every suppression/defer path. Exercise both actual callers, including shell-less retained windows and a changed resize frame (app:104595,104854–104940). This introduces a wrong-picture/geometry regression in ordinary use.
- O2 — A presentation veto must be conservative and have a complete wake lifecycle. Remove window_exposed's three-probe heuristic from hard admission; require an explicit hidden/minimized/zero/cloaked policy with fresh native observations and restoration wakes. The central-cover counterexample freezes a still-visible window; no extra wake cures it (platform:7155–7219).
- O3 — Exactly one consuming readiness wait per presented generation. Require DontWait, owner-thread configure exclusion, fresh handle acquisition, and credit retention/retirement across every early exit. The proposed positive gate otherwise creates the one-second input stall it promises to remove (hal/dx12/mod.rs:1434,1738). Test first frame, unchanged frame, resize, hide-after-ready, and loss-after-ready.
- O4 — No input-thread fallback to an unbounded driver call under a “never blocks” contract. Replace force-after-N with a defined suspended/recovery or lane policy; explicitly narrow B's promise if synchronous Present remains. Budget aggregate attempts and preserve endpoint/IME/resize semantics during long deferral; a timer and a Boolean fake do not prove these obligations (N:19,70–76; H:64–89).
- O5 — Acceptance must detect a responsive but frozen picture and failed rollback. Require per-window generation/sequence, pending age, last successful present+commit, skip/readiness reasons and durations, forced attempts, plus input-dispatch progress, emitted independently of hangs. Record a fresh baseline before suppression; test both switch branches and backend options. N:112–115's local gate tests and global counter cannot prove those facts (CONVENTIONS:374–376,394–409).
