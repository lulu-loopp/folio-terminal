Scope: commit `04cedbf6`, compared with main `e0f682b8`. Paths below are relative to `crates/bt-term` unless fully qualified; bare line references mean `src/session.rs`, all at `04cedbf6`. Rows are zero-based.

- Window scope: `src/session.rs:3068-3077` closes at every standalone feed / grouped drain end unless DEC 2026 is still buffering. An ordinary split across separate drain turns does not stay open; grouped slices defer settlement (`2886-2900`), and production brackets only synchronous feeding (`crates/bt-app/src/main.rs:84008-84013`).
- **P1 — mixed grid coordinates lose an unchanged formula:** `src/session.rs:6006-6027` projects current records through snapshot-to-current deltas without tracking which grid proved them. A feed that commits one DEC 2026 repaint and begins another retains the original snapshot (`2927-2929`, `3069`); detection between feeds now sees the committed NEW grid. Scratch oracle: seed one dormant raster; put identical three-row `$$ / x^2 / $$` blocks at rows 1 and 5; repaint them to rows 5 and 9, then append BSU+HOME in the same feed; prove/render both while open; ESU with no text changes. Close reduces **2 rasters to 1**, despite unchanged source. The +4 projection seats the first carried occurrence on the second's matching rows; ambiguous duplicate-source fallbacks cannot recover the other. Reproduced with the authorized oracle command (8 existing pass, scratch fails). Must preserve the carried records' coordinate provenance before applying the old-grid mapping.
- Measured lifecycle budget: **16 allocations, 21,304 B (120x40), 21,504 B (120x80)** per cycle; all 42 tests pass. This confirms the quoted numbers, with the coverage limitation above.

Restore consumes the queue (`6630`, `6716`); no same-ID dual ownership was found in this path. Rebase preserves occurrence birth (`12522-12524`), so it does not deduplicate independently detected occurrences. First-wins avoids stale snapshot state but is not sufficient for correct placement: see P1.

This faithfully isolates the reported census loss, but its final window changes no text and exercises no nonzero delta, repeated occurrence, or partial commit. Copied unchanged into a temporary worktree at `e0f682b8`: **7 pass, this test fails at line 585 (Source vs Rendered)**. Product code was not mutated to obtain the red result.

Normally settlement follows before any detection runs. However ESU/marker/overflow followed by a new BSU in the same drain leaves a deadline active and the earlier snapshot alive; the next between-turn detection can therefore prove NEW-grid records. No multi-thread race or unsupported detection inside a feed is needed for P1.
- Changed-source safety: projection compares proven text, wrap and cell boundaries (`13523-13545`), rejects interior mismatches (`13568-13585`), and restricts visible segments/bands to proven rows (`13597-13635`). Fallbacks also verify source. A scratch record first rendered inside BSU, then changed from `x^2` to `y^2` at its body row before ESU, correctly loses its stale raster. The existing completion-rejection test (`18094-18106`) does not cover an already-rendered carried record.
- **P2, pre-existing liveness gap:** that changed-body scratch case does not render the replacement even after another stability interval (0 rasters; no new detection). Only the body's signature is cleared (`6792-6804`); unchanged delimiter candidates retain theirs (`3730-3733`), and the context hash excludes plain `x^2`/`y^2` body rows (`12735-12746`). This is not a stale-raster acceptance or a new change in this commit, but “a changed formula still replaces the picture” is not generally established.
- Atomic-scroll control: with two carried three-row formulas at rows 5 and 9, a single BSU/HOME, proof while buffered, then CSI 4 S + ESU preserves both. The failure requires the mixed-coordinate lifecycle above, not every nonzero projection.
- **P1, pre-existing safety gap at commit/reopen:** prove/render `$$ / x^2 / $$` inside an open window; feed CUP/body replacement `y^2`, ESU, then BSU/HOME in one read. The published grid contains `y^2` but the frame still has the `x^2` raster; `held_unbacked_records()` reports that exact old source at band 1-3. Scratch assertion fails (1 raster, expected 0). Suppression skips invalidation (`6803-6804`), settlement sees the next deadline and skips projection (`3069-3071`), and publication reads residents without re-verifying their cells (`8437-8474`). This precedes the changed close loop and also exists in the parent logic. It violates the requested no-mismatched-raster bar, even though a final ESU would subsequently reject the record.

The unwrapped-stream claim is too broad. Without 2026, a complete unchanged source still visible at a new location can be preserved by exact row/cell projection, identity support, bounded detection, or exact-source restoration (`src/session.rs:6020,6046,6631,13380`); this is already non-heuristic behavior. If a read exposes only incomplete/contradictory source, identical bytes can describe either an unfinished repaint or a real edit, so there is no universal safe continuation proof from that grid alone. Atomic publication removes that ambiguity, but code inspection cannot establish that all 28 recorded events fall into it or that all are unavoidable. The supplied replay counters were not independently replayed in this review.
