Method: read-only product review; temporary integration probes compiled main and target detector source with identical inputs under the permitted bt-detect command. Row arrays below use zero-based indices; each quoted element is one logical row, and backslashes are literal.

**B1 — BLOCKS, regression: the suffix consumes a complete preceding block's closer** (`crates/bt-detect/src/lib.rs:3150-3164`, `:1685-1694`, `:1731-1741`).
Reproduce: [`$$x=y`, `+z$$`, `$$`, `a=b`]. Main detects the complete rows 0..1 block with its exact two-row source; target returns no blocks and `ClippedTail { body_start: 1, closer: 2 }`.
The phase walk closes the first block on row 1; floor is 1, so its closing row qualifies as suffix body. The next, genuine streaming opener has no forward-complete block, passes both guards, and is stolen as a clipped closer. Skipping row 1 then discards the previous block at row 2.
This also occurs with a fully visible following rejected block: [`$$x=y`, `+z$$`, `$$`, `ordinary prose here`, `$$`]. Main owns rows 0..1; target owns nothing. Standalone [`\[`, `x=y`, `\]`] and [`\begin{aligned}`, `x&=y`, `\end{aligned}`] before a streaming `$$` also regress.
Must fix: suffix evidence must not erase a separately complete in-window occurrence or its closing row; add these baseline-preservation cases, including the wrapped dollars form.

**B3 — BLOCKS, inline regression from the same overbroad suffix** (`crates/bt-detect/src/lib.rs:1685-1694`).
[`ordinary prose here`, `$x^2$`, `$$`, `a=b`] yields a valid inline occurrence on main and none on target. [`The expression $x^2+`, `y^2$`, `$$`, `ordinary prose here`, `$$q=r$$`] similarly loses main's valid joined inline occurrence. The display-body predicate accepts these inline rows, which are not floors.
The carry reset itself is correct: taking `inline_carry` before each skip prevents a join across body_start; consuming the closer also leaves no carry. A complete inline occurrence before body_start and inline math after the closer survive. The regression is selecting unrelated inline source as body, not a carry leaking across the boundary.

**Guard coverage and floors.** The unchanged convergence guard invokes the same scanner from the candidate opener, with no clipping/resync: forward-complete one/multi-line displays survive math-looking preceding rows, unfenced backslash code, and a backslash-terminated table row. Self-contained `$$...$$` is not itself a lone-closer candidate. No complete forward-valid dollars opener stolen was found.
The new phase check protects a still-open `$$x=y` / `z=w` / `$$`, an unclosed environment, a carried opener, and an active fence. It does not protect an already-closed preceding block: B1 is the concrete case both checks miss.
A recognized unindented `\begin{env}` sets floor to the following row; `\end{aligned}` alone is a valid body (nonempty, under 8192 bytes, and its backslash bypasses the prose heuristic). The recorded end-only shape therefore works. An unclosed environment prevents clipping; a completed one can produce B1/B2.
An open CommonMark fence prevents clipping; a closed fence bounds the suffix after its closing marker. A fence inside an active environment is inert to the phase walker but still advances floor syntactically; the directed fixture skips the remaining environment body. These are not semantic proofs of off-screen ownership.
The walker/scanner equivalence test is unchanged and passes; its scanner call supplies no clip evidence. Shared per-line state remains equivalent by design, while whole-window clip read-ahead and the resulting skips are outside that test's claim.

**Recorded for later — cost.** The suffix search is worst-case quadratic: H candidate rows spanning S bytes each rebuild a shrinking joined string, O(H*S) bytes copied (O(H^2*W) for W-byte rows), with O(S+H) peak temporary storage and O(H) allocation rounds. Prose in each prefix forces repeated trials. The 8192-byte limit is checked after joining, so it does not bound allocation/copy work; H is bounded by captured grid height, not a small helper limit. The 1024-line history cap applies to the prefix, not H. No performance benchmark was run.
