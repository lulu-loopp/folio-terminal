# Review: "Leaving no trace — how Folio is removed, on every channel"

Design: `docs/plans/design/clean-uninstall-2026-09-20.md`. Read-only review; repo claims verified against source, external claims against official docs (URLs inline). Severities: **BLOCKS** / **MUST-FIX** (before its ticket) / **NOTE**.

## 1. Trying to break it

**B1 — Agent-hook ownership is path-blind today; rule 3 is unimplemented work, not a generalisation.** Hooks are identified by the marker substring `"attention claude-code:"` (`crates/bt-app/src/attention_hooks.rs:62`, `group_is_ours` :232), Codex by any `notify` word `== "attention"` + `"codex:"` prefix (`attention_codex.rs:224`), Copilot by `"attention copilot:"` (`attention_copilot.rs:116`). None compare the exe path. So: *two copies on one machine* (the owner's own setup) → copy A's cleanup removes copy B's live hooks; and copy B's *install* silently rips out A's hooks (install = `remove_from` + append, `attention_hooks.rs:346`). Situation → second copy left with integrations shown ON in Settings but pointing nowhere → defeats rule 3 and §5 Q4's premise that the `explorer_menu` ownership test just needs "generalising". **MUST-FIX**: path attribution is new code in three modules; the door spec must state which copy may remove which entry (proposed: any copy may remove an entry whose named exe no longer exists; only the owning copy removes a live one; install must refuse, not replace, when another live copy's hooks stand — mirroring Codex's existing refusal, `attention_codex.rs:318`).

**B2 — The `$PROFILE` line is per-USER, not per-copy; the ownership rule cannot attribute it.** The line names `%APPDATA%\Folio\shell-integration\folio.ps1` (`shell_integration.rs:1270`), a *shared* data path every copy repairs (`powershell_script_repaired`, :1318). Copy A's cleanup removing the line silently breaks copy B's shells — B re-writes the script but nothing ever re-adds the line (no removal *or* re-add path outside the two user-press sites, `main.rs:45005`, `main.rs:54519`). Defeats layer-1's ownership default. **MUST-FIX**: the design needs an explicit rule for shared marks (e.g. remove the line only with `--purge`, or when no other copy's mark exists anywhere).

**B3 — The remover must enumerate profiles, not probe one shell.** Install asks the *pane's own* shell for `$PROFILE.CurrentUserCurrentHost` (`shell_integration.rs:1088`), so 5.1 and 7 are separate files (`Documents\WindowsPowerShell\...` vs `Documents\PowerShell\...` — VERIFIED, [about_Profiles](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_profiles?view=powershell-7.5)) and a user can accumulate the line in both. A remover probing "the" profile misses one → a surviving *unguarded* line errors at every startup (the design's own harm #2). OneDrive Known-Folder-Move puts `$PROFILE` under OneDrive ([redirect-known-folders](https://learn.microsoft.com/en-us/sharepoint/redirect-known-folders)); the shell-probe handles this at install, but the remover must resolve the same per-edition paths, and sync locks/placeholders can make the atomic write fail — must be reported, not crash. **MUST-FIX** (spec the enumeration), OneDrive-lock handling **NOTE**.

**B4 — Cleanup while Folio is running: scoop's ordering makes it destructive.** Scoop runs `pre_uninstall` *before* its running-process check; if Folio is up, scoop then **abandons the whole uninstall** (VERIFIED, [scoop-uninstall.ps1](https://raw.githubusercontent.com/ScoopInstaller/Scoop/master/libexec/scoop-uninstall.ps1)) — hooks/profile/marks gone, app still installed, rows still ON. Defeats the "one door" promise. **MUST-FIX**: the door must detect a live instance (the single-instance machinery exists) and refuse with a distinct exit/line when its own copy runs; package hooks then leave everything intact.

**B5 — T-E's Settings ▸ Apps entry has no answer for the winget channel.** Winget manifests carry no hook fields (VERIFIED, [manifest spec](https://learn.microsoft.com/en-us/windows/package-manager/package/manifest)), so no channel marker can ever be written for winget installs — yet winget *itself* registers an ARP entry for portable packages (VERIFIED, [winget-pkgs FAQ](https://github.com/microsoft/winget-pkgs/blob/master/doc/FAQ.md)). Result: two "Folio" rows in Settings ▸ Apps, and after `winget uninstall` Folio's self-registered row dangles forever (no process remains to self-repair) — T-E manufactures the dead-row harm the design exists to end. Also: two copies collide on one registry key (last wins; first copy loses its door), and "Folio's existing folder-moved self-repair covers it" is wrong — repair today covers only the Explorer registrations (`explorer_menu.rs:1015`, `context_menu.rs:179`); ARP-entry repair is new code. **MUST-FIX (blocks the T-E ticket as written)**: either scope T-E to non-managed copies via a test that does not violate rule 5, or defer T-E to the 0.4.5 installer.

**B6 — `--purge` vs the second copy and the running instance.** Both copies share `%APPDATA%\Folio`; purging from A destroys B's settings, and a *running* B will re-save `settings.json` on exit, resurrecting the dir. The WebView2 UDF (`%LOCALAPPDATA%\Folio\WebView2`, `webhost.rs:485`) is locked while any instance lives (Q5). **MUST-FIX**: `--purge` refuses/reports when another Folio process holds the data; per-mark "left: in use" lines.

**B7 — Mark locations are env-dependent at both ends; nothing records them.** Config roots come from `CLAUDE_CONFIG_DIR` / `CODEX_HOME` / `COPILOT_HOME` *at the time the code runs* (`attention_hooks.rs:79`, `attention_codex.rs:107`, `attention_copilot.rs:213`). If the var pointed elsewhere at install time than at uninstall time, the door looks in the wrong file, reports "nothing to do", and the marks live on. **MUST-FIX**: extend rule 5 — each module writes down where it landed its mark (in `%APPDATA%\Folio`); the door reads facts, not current env.

**B8 — Homebrew stanza is mis-named and under-specified.** Official taps reject legacy `uninstall_preflight` Ruby blocks; the form is `uninstall_preflight_steps { run … }`, running in a sandbox with **no home-directory writes** unless `writable_paths:` is declared, no network unless `network_access: true`, and failure aborts the uninstall unless `must_succeed: false` (VERIFIED, [Cask Cookbook](https://docs.brew.sh/Cask-Cookbook)). As drafted, a malformed `~/.claude/settings.json` (a *refusal*, exit≠0) would block `brew uninstall` entirely. **MUST-FIX**.

**B9 — macOS translocation poisons every path-based mark.** A quarantined app launched in place runs from `/private/var/folders/.../AppTranslocation/...` (VERIFIED, [Apple DTS](https://developer.apple.com/forums/thread/724969)); hooks written then name an ephemeral path, die on next reboot, and self-trash would trash only the translocated copy. **MUST-FIX**: refuse to install X marks when `current_exe` is under an `AppTranslocation` path (string check; no supported detection exists). Related: `main.rs:53878` falls back to a bare `"folio.exe"` if `current_exe()` fails → PATH-relative hooks; make that a refusal. **NOTE**: trashing an app in /Applications owned by another user fails for a standard user — entrance 1 must say so and still run cleanup (all marks are per-user).

**B10 — Self-delete on Windows (Q3).** `MoveFileEx` delay-until-reboot needs admin + empty dirs (VERIFIED, [MoveFileExA](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexa)) — disqualified. Detached `cmd /c … rd /s /q` is the only per-user form; pitfalls: `rd` fails on any process's CWD, leaving an empty husk (VERIFIED, [rmdir](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/rmdir)); `cmd /c` outer-quote stripping with spaced paths; non-ASCII paths vs the OEM codepage. AV/SmartScreen reaction to self-delete: UNKNOWN in docs (SmartScreen reputation is cert/hash-based, [SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)); keep the binary signed, test against Defender. The door must report partial deletion, not claim success. **NOTE**.

**B11 — Smaller breaks (NOTE).** (a) Copilot removal is a non-atomic `remove_file` with no backup (`attention_copilot.rs:654`) and refuses if *any* entry lacks the marker — a future Copilot schema touching `folio.json` makes it undeletable, but the failure is inert (logged-and-skipped, see Q1). (b) install.md's recovery recipe ("re-unpack, run the flag") must say *latest* zip — an old copy lacks newer removers. (c) PSReadLine removal while shells hold the DLL loaded fails on file locks — report, don't retry-loop; content-guarded removal (`psreadline.rs:970`) is otherwise sound, including a user later installing stock 2.4.6 over the leaf (removal correctly refuses). (d) Claude/Copilot JSON rewrites lose key order/formatting of the user's file (serde re-serialize; Codex's `toml_edit` preserves it) — acceptable, but say so. (e) `--remove-explorer-menu` shipped 2026-09-19 (commit `2ac0a5aa`), not 09-20; the first-run card does *not* pre-tick Explorer today (`first_run.rs:461`) — §2's parenthetical is a proposed change, not a fact.

**Q6 — missing from §1 (NOTE):** legacy `%APPDATA%\BetterTerminal` rename source (`persist.rs:1395`) — `--purge` should take it if present; OS-written keys outside Folio's control: `HKCU\...\Notifications\Settings\Folio.Terminal`, the AppModel repository entries for the sparse package (`explorer_menu.rs:556`), winget's `Links\folio.exe` shim and scoop's shim (package-manager-owned, fine); the toast AUMID key (deliberate keep — put the *reason* in the release note, users will audit).

## 2. Q1–Q7

**Q1 (mostly VERIFIED).** *Claude Code*: shell form runs via `sh -c` on Unix, **Git Bash on Windows, PowerShell if no Git Bash — never cmd**; exec form (`command`+`args`) spawns directly. Missing exe in a sync hook → one non-blocking transcript notice per event. `"async": true` completion is **suppressed by default** (visible only in verbose) — so Folio's all-async install (`attention_hooks.rs:386`) is *already silent* when the exe is gone. ([hooks reference](https://code.claude.com/docs/en/hooks)) *Codex*: `notify` is direct argv exec, stdio null, fire-and-forget; spawn failure → `tracing::warn` only, invisible (VERIFIED, [legacy_notify.rs](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/legacy_notify.rs)). *Copilot*: `notification` hooks are documented fire-and-forget; Folio's events (agentStop/sessionEnd/userPromptSubmitted/notification) are all non-gating → "logged and skipped"; only `preToolUse` is fail-closed and Folio doesn't use it ([hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference)). **Consequence: layer-0 for agent hooks needs no guard strings at all** (a single string can't serve both Git Bash and PowerShell anyway). Recommended exact forms, also satisfying rule 6 (no extra process): Claude → exec form `{"command": "<abs exe>", "args": ["attention","claude-code:Stop","--json","-"], "async": true}`; Codex → unchanged argv; Copilot → the CLI-only `exec`+`args` field instead of `powershell` (drops the pwsh-per-event spawn). UNKNOWN: Copilot exec-spawn-failure UX (runtime closed-source) — test before switching.

**Q2.** Precedented and acceptable per-user (Inno non-admin mode writes HKCU ARP; winget does it for portable). Carry DisplayName, Publisher, DisplayVersion (winget treats missing as "version Unknown"), InstallLocation, UninstallString = QuietUninstallString (the door), NoModify=NoRepair=1 ([MSI ARP docs](https://learn.microsoft.com/en-us/windows/win32/msi/configuring-add-remove-programs-with-windows-installer), [FAQ](https://github.com/microsoft/winget-pkgs/blob/master/doc/FAQ.md)). VERIFIED — but see B5.

**Q3.** See B10: detached `cmd /c` self-delete, report husks; macOS `trashItem` on own bundle — INFERRED permitted for notarised non-sandboxed apps (nothing in Gatekeeper/notarization docs forbids it; test the running-app case); translocation caveat per B9.

**Q4.** VERIFIED code: attribution is marker-only today (B1). Proposed rule: live-other-copy marks are left (and block install); dead-path marks are anyone's to remove.

**Q5.** Cannot delete a held WebView2 UDF; per-mark "left (in use by a running Folio)" line, exit non-zero only on refusal per the door's contract. Ties to B4/B6.

**Q6.** See B11/Q6 list above.

**Q7.** Cask: B8 (stanza name, sandbox, `must_succeed: false`). Scoop: hooks are arbitrary PowerShell, no rule against running the app's binary ([App-Manifests wiki](https://github.com/ScoopInstaller/Scoop/wiki/App-Manifests)); GUI+hooks excludes Main bucket anyway ([criteria](https://github.com/ScoopInstaller/Scoop/wiki/Criteria-for-including-apps-in-the-main-bucket)) — but B4's abort-ordering is a real conflict to design around. Winget: no documented prohibition of a self-registered ARP entry (UNKNOWN = absence of rule); the practical conflict is the duplicate/dead row (B5). Also note: the scoop manifest lives in `lulu-loopp/scoop-folio`, not this repo — tickets must name both repos plus `scripts/release/update-manifests.ps1`.

## 3. Slicing judgement

The split is broadly right, and the urgency ranking survives scrutiny with one correction: per Q1, stale agent hooks are *already silent* in all three agents — the only harm users actually *feel* today is the bare `$PROFILE` line (error at every PowerShell start) and the dead Explorer row. So **T-A is the right 0.4.3 headliner**; **T-B shrinks** from "make hooks inert" to "verify silence + switch Claude/Copilot to exec form" (still worth 0.4.3, now small). Move into 0.4.3 from the design's gaps: the mark-location record (B7 — cheap, and every later layer reads it), the running-instance contract (B4/B6 — the scoop hook ships in 0.4.3 and is broken without it), the cask corrections (B8), the multi-profile remover (B3), shared-mark ownership (B1/B2). **Hold T-E** (0.4.4) until B5 has an answer; T-D and T-F can proceed. Missing altogether: (1) **telling existing users** — the guarded-line upgrade reaches only people who run the new build; users who already deleted Folio need the recovery recipe, so `docs/install.md` must keep a hand-edit fallback, and the 0.4.3 **release note must say**: hooks/menu/profile now have one undo door, what `--purge` does and doesn't touch, and (at 0.4.4) *why* a Folio row appears in Settings ▸ Apps and why the toast key is intentionally kept. (2) **A test plan that never touches the dev machine**: the code already has the seams — `BT_POWERSHELL_PROFILE`, `BT_PSREADLINE_DOCUMENTS`, `CLAUDE_CONFIG_DIR`/`CODEX_HOME`/`COPILOT_HOME` all redirect to temp dirs; add HKCU redirection via a throwaway Windows Sandbox/VM snapshot matrix (two copies; moved folder; unzip-over upgrade; PS 5.1+7; OneDrive-KFM profile; winget/scoop/cask flows; cleanup-while-running).

## Verdict

**GO WITH CHANGES.** The three-layer shape and the layer-0-first ordering are sound, and Q1's evidence simplifies layer 0 (hooks are already silent; guard strings are unnecessary and unwritable cross-shell). Required before tickets: (1) path-based ownership for agent hooks + a shared-mark rule for the profile line (B1, B2); (2) multi-profile enumeration in the remover (B3); (3) door refuses/reports when any Folio instance is running; `--purge` handles shared data + locked UDF (B4, B6); (4) record mark locations at install time (B7); (5) cask `uninstall_preflight_steps` + `writable_paths` + `must_succeed: false` (B8); (6) translocation/`current_exe`-fallback refusal (B9); (7) hold or re-scope T-E for the winget channel and two-copy key collision (B5); (8) release-note + existing-user recovery text and the sandboxed test matrix (§3).
