## 1. The fact and its owner — agree on owner; missing lifecycle contract

`text_scale` should be the sole authoritative **requested ladder index**, owned by the terminal view. Settings owns the base font choice; the window owns display scale. Measured metrics, projection geometry, pending PTY sizes and presented-frame metrics are derived values or observations, not competing owners of that index. This follows [ARCHITECTURE §4](docs/ARCHITECTURE.md) and [D-1](docs/plans/structural-debt.md).

However, there is no separate “view half” type today. `LeafSession` in [main.rs](crates/bt-app/src/main.rs) contains `session`, `pty`, `incarnation`, `projection`, `grid`, `conpty_grid` and `last_presented_frame` together. Putting another field beside `projection` is compatible with the future split; it does not establish that split. Give the view configuration a named owner and a narrow metrics/apply interface. Do not introduce a `SeatId -> scale` map on `WindowRuntime`, `TabState`, the renderer or persistence.

The lifecycle must explicitly say:

| Path | Current code fact | Required behavior |
|---|---|---|
| Birth / split / duplicate | `create_leaf_session` measures through the renderer and creates both session and projection. `split_seat` calls it. `duplicate_tab` calls `new_tab_seeded_from` using profile and cwd. | New view starts at 100%; derive its initial PTY grid from that view's metrics before spawn. |
| Pane tear-out / merge | `tear_pane_into_tab`, `move_seat_content`, and `absorb_tab_sessions` move the actual `LeafSession` with remove/insert, including when the seat id changes. | Move the view configuration; do not copy a second scale into transfer metadata. |
| Cross-window transfer | `FolioApp::transfer_tab` moves `TabState`, rebinds wakes and calls `settle_seat_set_change`. That path solves grids and synchronizes math but does not run the DPI setter loop on the transferred leaf. | Preserve the index, then derive and apply **destination-window** metrics to the session, projection, math and frames. Moving the index alone leaves source-DPI derived state behind. |
| Restart shell | `Runtime::restart_shell` calls `create_leaf_session` and replaces the entire leaf with `self.sessions.insert(seat, spawned?)`. | Explicitly retain the view's scale intent and supply it to construction. Do not spawn at base size and repair it afterwards. On failure retain the old leaf unchanged. Do not retain selection, frames or pending resize debt belonging to the old transcript/incarnation. |
| Relaunch / startup restore / reopen closed | `TabState::term_leaf`, `Runtime::window_snapshot`, `restore_row_seed`, `seeded_tab` and `Runtime::reopen_recent` reconstruct launch/layout intent. `Action::ReopenClosed` calls `reopen_recent(0)`. | Omit scale from `TermLeafV1`, `TabV1`, `SessionV1`, recent/vault seeds and settings. All reconstructed views start at 100%. |

`LeafSession::card_skip` is a useful warning: it lives beside view fields **and is persisted** by `TabState::term_leaf`. Field location alone proves neither session-only lifetime nor absence of a second store.

“Written only by three verbs” needs refinement. Initialization, move and successful shell replacement are legitimate lifecycle operations. Make the three actions and indicator reset converge on one mutation door, with narrowly documented constructor/transfer operations. A literal three-writer guard would either reject the required Restart behavior or encourage an unguarded bypass.

## 2. What re-derives, where — disagree with sufficiency; missing consumers

The existing resize machinery is the right machinery. `LeafSession::grid_for` delegates to `cmdrail::terminal_grid_for`; `schedule_leaf_grid_change` calls `DualPlaneSession::resize_at` for a shown leaf; `release_due_leaf_resize` reaches `commit_leaf_resize`, which orders local reflow, child notification and reconciliation. Retain that order and the PSReadLine debt handling.

Correct two factual claims:

* `flush_pending_pty_resize` currently executes the synchronous `PtySession::resize` on the window thread. ARCHITECTURE §5's exception for `ResizePseudoConsole` explicitly schedules the session-lane move for 0.5 toward 0.6. Reuse this exception; do not describe the lane move as already implemented or smuggle it into this feature.
* N notches do not necessarily mean N reflows or exactly one OS resize. `queue_wheel`/`WheelBurst::plus` combine reports before `flush_wheel`. `plan_grid_change` reflows only when the integer grid changes. `commit_leaf_resize` sends nothing if the final grid equals `conpty_grid`; a return to the original grid still settles the local transaction. `service_pending_pty_resize` also holds release while a divider/native sizing gesture remains active. The guarantee is at most one final child notification per affected pane after the applicable quiet boundary, if its final grid differs.

**Rendering requires more than the proposed key edit.** `ComposedRowKey` already contains `RowMetricsKey`. `ShapeKey` has only text/bold/italic, so two `get_or_shape` calls at different sizes can return the first call's buffer and offsets. Fix both `NarrowShapingCache` and `WideShapingCache`. Key by all shaping/placement-relevant metrics, preferably a shared metrics key, plus a defined font-environment identity or equivalent clearing contract. The cached offsets also depend on cell width/height, baseline and primary cap geometry. A ladder index is not a cache key across Settings or DPI changes. A size-only key is sufficient only with an explicit invariant that the remaining inputs are determined by that size and a stable font environment. Preserve `adopt_metrics`'s font-change invalidation without calling it per pane and clearing every sibling's caches.

**There is a second concrete cache collision.** `WindowRuntime::table_paints` and `WindowRenderer::table_blocks` are `HashMap<String, ...>` keyed by table source. `table_sources` deduplicates identical sources across panes, and `table_paint_stamp` supplies one window font size. Two identical rendered tables at 80% and 150% therefore cannot coexist correctly even after the shaping fix. Include effective metrics/font environment in both table sizing and paint identity, or make the lookup explicitly per view. These are terminal tables, despite `build_table_block` living in `runtime/preview.rs`.

**Atlas identity is already size-aware; eviction is not proved safe by area.** The locked local dependencies confirm `glyphon::GlyphonCacheKey::Text` contains `cosmic_text::CacheKey`, including `font_size_bits`, font/glyph identity and subpixel bins. No new per-pane atlas is needed. However, `GpuContext::close_the_frame` explicitly retracts the older “one frame's ink fits, therefore the atlas cannot fill” argument: the bucketed allocator fragments across a ladder of sizes even with substantial area free. Preserve unconditional frame closure, no mid-frame trimming, once-per-episode repacking, `PresentedWithoutText` retry and device-loss handling. Existing tests include `no_exit_from_a_frame_may_skip_the_atlas_trim`, `the_frame_body_never_trims_the_shared_atlas`, `a_4k_chinese_frame_fits_the_glyph_atlas`, and `a_session_long_enough_to_wear_the_packer_out_gets_its_text_back`. Extend the workload to simultaneous mixed-size terminal seats and alternating windows. Twelve rungs limit choices for a fixed environment, not lifetime atlas fragmentation or all Settings/DPI combinations.

**Keep the covering checks distinct.** `CjkFace::covers` and `terminal_grid_family` check cached character coverage; changing text size does not change that ownership rule. `font_presentation_route` and `is_color_cluster_from_family_within_slot` additionally check actual emoji composition, color rasters and slot fit; the latter is size-sensitive and must run on a cache miss for the new metrics. Do not replace either with “the family exists” or let an old cached shape skip the new fit decision. Separately, `frame_matches_grid` checks only columns and rows, while `PresentGate::SeatSignature` has no metrics field. These presentation checks cannot certify that a retained picture was produced at the new scale. Pair each pending/retained/presented frame with its derived metrics identity and include that identity in presentation equality. Hit testing must not combine a last-presented frame's row map with newly requested cell width after a skipped present.

## 3. DPI and Settings composition — agree on formula; missing precise clamp/invalidation

Use one derivation for effective logical size and measurement:

`effective_logical_px = clamp(validated_base_px * ladder_percent / 100, 8, 72)`; physical measurement applies the window's display scale once.

The note's “clamped once” is ambiguous: `settings::drawable_font_size` already clamps the stored `u8` to `FONT_SIZE_OPTIONS`, currently **10–24**, while preserving the stored setting. Applying 8–72 after multiplication is a second, distinct boundary. Recommend preserving existing base validation, then defining the effective-size clamp once in the shared derivation. Changing raw Settings validation to 8–72 would change today's behavior for hand-edited/out-of-range settings and needs its own explicit decision. `CellMetrics::measure_at` accepts logical size and multiplies internally; do not pre-multiply by DPI or scale measured cells afterwards. It is private today: expose a narrow measurement service rather than duplicate its shaping arithmetic in bt-app.

Reuse the existing `GpuContext::font_environment_epoch`: `set_terminal_font` already advances it before loading primary/CJK files and replacing family mappings, and its contract requires future locale/fallback mutations to advance it too. Do not invent another epoch beside it. Bound/clear the new metrics memo across changing environments and monitor scales. A metrics cache is derived and discardable; no effective product is persisted as pane intent.

Push the result through one apply operation for size actions, Settings, DPI, creation and transfer. Update session subpixels, projection, layout key and frame identity even when floor rounding leaves columns/rows unchanged. `DualPlaneSession::refresh_projection` is the current session-to-projection update path; `set_font_size_subpixels` invalidates math through `set_layout_key`. These updates cannot be hidden behind the grid-changed branch alone.

There is no 120% rung in the proposed ladder; all three “120%” examples should use 125%. At a 10px base, 50% and 67% both clamp to 8px. Define whether the indicator reports requested percentage or effective size. I recommend requested percentage with the effective px/clamp explained in the tooltip; retain the index when Settings changes, and avoid redundant reflow/PTY/presentation work when the effective metrics do not change.

## 4. Doors — agree on table dispatch; missing policy amendment and wheel semantics

The keyboard should use the existing `Shortcuts::lookup` / `Runtime::run_shortcut` rung, not acquire another independent `keyboard_input` branch. Add `Scope::Terminal` based on `keyboard_owner_is_a_shell`, with no alternate-screen exclusion. Do not derive it as `!focus.preview`: a file tree, search field, menu or modal can own the keyboard while `focused_leaf` still names a shell. Extend `Focus`, `Scope::holds`, scope labels, effective bindings, recorder/serialization and `webhost::claimable_chords` consistently. The page must retain an out-of-scope chord.

Preserve the existing ordering: actual-keystroke normalization and dismissal; transient/modal/menu handling; IME-owned editing keys; terminal copy/paste; shortcut table; remaining field/content handling and PTY encoding. [RULES row 27](docs/RULES.md) explicitly preserves copy/paste ahead of recorded bindings. The shortcut rung currently consumes repeats but invokes actions only on `!event.repeat`; decide whether text-size keys deliberately inherit that policy. Do not assume holding a key will repeat.

For wheel, placement after terminal targeting is right **only if it is also before the math-block pan branch**, which currently precedes `wheel_route`. “Before `wheel_route`” alone could still let a formula swallow Ctrl+wheel. Keep hover cards, first-run/Settings, notices, palette, pages, floats, strip/rail, files/Git, pictures and document previews ahead of it. Use the addressed terminal without changing keyboard focus. State the existing no-pointer/lone-terminal fallback policy explicitly.

This is a deliberate wheel-policy extension, not behavior already authorized by the old router. `wheel_route` grants mouse reporting priority when Shift is absent, keeps displaced alternate-screen review local, uses alternate-scroll when requested, and otherwise respects a mute alternate screen. `input::mouse_bytes` encodes the Ctrl bit in mouse reports. A new Ctrl rung takes those reports from TUIs. [DESIGN §7.1.5f and §7.1.6b′](docs/DESIGN.md), and the horizontal-scroll explanation beside `wheel_axis`, also reserve Ctrl for scale; thus text scaling is consistent with that reserved meaning, but its priority over reports still needs to be stated in the current rule.

`a_wheel_notch_belongs_to_the_pane_it_is_over_on_either_screen` sweeps 64 combinations of Shift, modes and scroll state. It has **no Ctrl input** and calls `wheel_route` directly, so inserting an earlier Ctrl branch would leave it green while changing effective behavior. Extend the policy test through the new routing decision. Preserve the original matrix for non-size gestures. Update RULES row 28 alongside the DESIGN entry; it currently points to history and is “not yet folded.” The new return also needs `mouse_trace` output to satisfy `every_exit_of_the_wheels_road_writes_a_line`, and route vocabulary must satisfy `the_wheel_route_words_are_the_declared_ones`.

Specify exact modifiers, horizontal deltas and macOS spelling. Recommend exact Ctrl on Windows and the platform's application modifier on macOS, leaving Alt/Shift combinations to existing routes unless explicitly ruled otherwise. A blind `control_key()` condition takes Ctrl+Alt and Ctrl+Shift too. `upright_wheel` already rewrites macOS Shift-axis reports before burst merging. This is also a concrete existing test constraint: `i18n::tests::no_macos_column_promises_a_control_pointer_gesture` rejects shipped macOS strings containing `Ctrl+wheel`. A literal cross-platform Ctrl-wheel promise would fail it; use the established platform dialect or explicitly revise that ruling.

Finally, `wheel_zoom_notches` gives a floating conversion, not an integer carry protocol. `CardAim` deliberately uses `WheelBurst::less_notches` in the original currency so six 20px events equal one 120px notch without float residue. Reuse that property. Define carry reset on target/modifier/route change, saturation and currency changes. Test direction reversal at bounds: summing `+1,-1` at the maximum is not equivalent to individually clamping each step. `WheelBurst::plus` currently assumes sum-preserving routes; decide whether to flush at reversals or define net-burst semantics. Neither this nor N reflows per physical notch follows automatically from the existing burst code.

## 5. Not changed — agree, with corrected boundaries

Keep preview/web/file/Git typography, chrome, pane padding and lane widths at their existing base/DPI scales. `CellMetrics::measure_at` derives padding from `PADDING_LOGICAL_PX * scale`, independent of terminal em. `cmdrail::terminal_grid_for` subtracts the resting rail reservation using scale/padding before converting usable width to cells; keep that order. `terminal_scroll_bar`/`terminal_column_bar` take projection extents and DPI-based chrome geometry. Their thumbs can change with the new projection while their lane width stays fixed.

Window minima are the ruled layout metrics, as `apply_window_min_inner_size` -> `seat_metrics` -> `SeatMetrics::ruled` shows. Keep them unchanged, but explicitly accept the consequences at large text sizes: `CellMetrics::grid_for_pixels` floors at two columns and one row even if the physical pane cannot display that much ink. Test clipping, rail reservation and hit refusal there rather than silently increasing window minima.

The proposed two-accessor split is incomplete for legitimate non-pane base-font readers such as `line_height_subpixels`. Provide an explicitly named base/chrome metric interface as well as `window_scale` and terminal-view metrics. Do not funnel chrome through an arbitrary leaf to make a source guard pass. Terminal-rendered tables and formula source overlays are part of terminal content and must scale; standalone previews remain unchanged.

## 7. Structural debt — partly agree; overclaims need correction

Separating window scale from terminal-view metrics and consolidating the two setter loops reduces a real ambiguity. The claimed roughly 175 scale-only readers is not an acceptance criterion: classify callers by actual dependency, including indirect renderer methods and legitimate base-font readers. ARCHITECTURE itself warns against turning counts into a structural score.

**D-1:** placing scale with view intent avoids worsening the session/backend coupling. It advances D-1 materially only if the change introduces a real, narrow view-owned configuration/derivation boundary. A field beside `projection` inside today's mixed `LeafSession` does not discharge any independent session ownership. Keep D-1 open and describe this as alignment unless that boundary is actually delivered.

**D-8:** an indicator is persistent pane state, precisely one of the missing taxonomy cases. Add the proposed message-kind/urgency/modality/surface row before implementing it; final UI allocation remains the owner's decision. Reusing the existing pane head need not create a new surface family. Keyboard actions should reuse an existing rung, so “keyboard rung grows by one” is avoidable. The wheel gains a policy case and its precedence must be documented regardless of indicator choice.

The scale index is window-thread-owned and adds no new cross-thread authority. Nevertheless its derived size participates in existing async math/layout identities and PTY delivery ordering. “Not one of the 22 facts” does not exempt those contracts. Preserve D-2's recorded resize exception and D-7's requirement that guards enforce a written rule; do not report either debt repaid by this feature.

## 8. Risks and owner questions — missing decisions; recommendations

The listed risks are real, but “the guard is the answer” overstates a lexical check. The highest-risk omissions are table paint identity, last-presented geometry, Restart construction and destination-DPI adoption. Clamp-induced no-ops and wheel burst semantics also need defined behavior.

**Q1 — recommend Windows Ctrl+= / Ctrl+minus / Ctrl+0, with an explicit terminal-scoped default exception; macOS Cmd equivalents.** This matches the intended scale gesture and preserves the exact-modifier Ctrl+Shift+underscore route where the layout distinguishes it. Do **not** justify the Shift alternative as harmless to readline: on a US layout Shift+minus produces `_`, and `input::control_byte("_")` returns `0x1f`. `Chord::matches` accepts either the produced logical character or `key_without_modifiers`, so a Ctrl+Shift+minus binding takes precisely that chord. Conversely, the note's categorical “Ctrl+minus is ^_” is not a fact of this encoder: `control_byte("-")` returns `None`; an already-produced U+001F is accepted. Real layout/winit reports therefore matter. The existing `bare_control_letters_stay_with_the_terminal` test scans letters, not this punctuation, and will not settle the question. Test both logical/base spellings on the shipping layouts and document the consumed chords. If the owner's requirement is zero loss of any terminal control-code spelling on every layout, neither proposed Windows set is proven to meet it; ship configurable rows without Windows defaults instead of calling Shift safe. Also extend shortcut disclosure if these punctuation conflicts should receive the `shell` note: `takes_a_shell_control_key` currently recognizes only bare Ctrl plus ASCII letters.

**Q2 — recommend (c), persistent percentage while the requested rung is not 100%, click to reset.** It makes session-only view state discoverable and gives the reset an on-screen door.
