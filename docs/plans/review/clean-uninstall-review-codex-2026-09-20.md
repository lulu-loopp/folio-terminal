# Review: “Leaving no trace — how Folio is removed, on every channel”

## Bottom line

The three layers are the right product shape, but the proposed ownership model, package hooks, and self-deletion are not safe enough to ticket as written. The key correction is to distinguish **per-copy marks** (agent hooks, ARP, Explorer registration) from **per-account shared marks** (PowerShell profile/script and PSReadLine), and to record every path/owner at install time in a durable ledger.

## 1. Try to break it

### Layer 0 — inert marks

- **BLOCKS — old profile never migrates:** an existing user launches Folio but no PowerShell pane → the unguarded line is unchanged → deleting `%APPDATA%\Folio` still breaks every shell, defeating “upgraded next time Folio runs.” Repair currently occurs only when `shell_integration::offer_for` is reached, and even that repairs the script, not the profile line (`shell_integration.rs:offer_for`, `main.rs:spend_powershell_intent`).
- **BLOCKS — the profile mark has no copy owner:** two copies exist → both use `. "$env:APPDATA\Folio\shell-integration\folio.ps1"` → no path in that line identifies either executable, so “another existing copy is left alone” cannot be generalized (`shell_integration.rs:integration_line`, `script_path_ps1`). This defeats rule 3.
- **MUST-FIX — false-positive removal:** a user-written live line merely contains `folio.ps1` → current recognition calls it Folio’s (`shell_integration.rs:profile_declares_integration`) → a remover based on that marker deletes user code. Use a unique managed comment plus exact normalized statement; migrate only exact legacy forms.
- **MUST-FIX — two profiles / redirected Documents:** PS 5.1 and PS 7 report different `CurrentUserCurrentHost` files, and Documents may be OneDrive/redirected → cleanup discovers only shells presently installed/on PATH or the current redirected location → the other/old profile remains. `profile_probe` asks each executable at install time but stores no ledger (`shell_integration.rs:PROFILE_COMMAND/profile_probe`). Microsoft confirms the distinct 5.1 and 7 paths and redirection behavior: [about_Profiles 5.1](https://learn.microsoft.com/da-dk/powershell/module/microsoft.powershell.core/about/about_profiles?view=powershell-5.1), [PowerShell 7 profiles](https://learn.microsoft.com/en-us/powershell/scripting/learn/shell/creating-profiles?view=powershell-7.6).
- **MUST-FIX — profile filesystem cases:** a profile is read-only/locked → cleanup cannot rewrite it; a profile is a symlink → atomic replacement can replace the link rather than its target; a profile did not exist → Folio may have created it and its directories. Report refusal nonzero, follow a verified link target deliberately, preserve encoding/newlines/ACLs, and delete a now-empty file only when the ledger proves Folio created it (`shell_integration.rs:add_to_profile`).
- **BLOCKS — Claude is not proved silent:** app folder is deleted → shell cannot start the hook → Claude classifies this as the same non-blocking failure notice as exit 127; async completion notices are suppressed by default but reappear in verbose/debug modes. `async:true` makes it non-blocking, not universally silent, so it cannot establish rule 1; see [Claude hook exit behavior](https://code.claude.com/docs/en/hooks#exit-code-output) and [async hooks](https://code.claude.com/docs/en/hooks#run-hooks-in-the-background).
- **MUST-FIX — Claude’s Windows shell changed:** a path contains `$` or backticks and Git Bash is installed → the current Windows double-quoted command is expanded by Bash, not run by `cmd` as the source comment assumes (`attention_hooks.rs:quoted_program`). Claude now documents Git Bash by default, PowerShell only when Bash is absent; explicitly select the shell: [exec/shell form](https://code.claude.com/docs/en/hooks#command-hook-fields).
- **BLOCKS — environment-selected agent roots move:** install with `CLAUDE_CONFIG_DIR=A`, uninstall with it unset or `=B` (same for `CODEX_HOME`/`COPILOT_HOME`) → cleanup examines the wrong file and leaves the live hook (`attention_hooks.rs:config_dir_from`, `attention_codex.rs:config_dir_from`, `attention_copilot.rs:config_dir_from`). Store the exact config paths written.
- **BLOCKS — current removers are family-wide:** copy B takes over an agent hook, then cleanup is run from copy A → current Claude/Codex/Copilot recognition is by `attention <family>:` rather than exact executable → A removes B’s live hook (`attention_hooks.rs:remove_from`, `attention_codex.rs:declares_folio/remove_from`, `attention_copilot.rs:entry_is_ours`). This directly defeats “this copy.”
- **MUST-FIX — malformed/locked/new schema:** agent is running and locks/changes its config, or the file is malformed → cleanup cannot safely edit it; today readers refuse, but the design’s “non-zero only when attempted” can report success without removal. A Copilot `folio.json` with a future `version` or unknown top-level field but only Folio hook rows passes `holds_somebody_elses_entry` and the whole file can be deleted (`attention_copilot.rs:holds_somebody_elses_entry/apply_to`). Unknown schema/fields must refuse, byte-preserving edits must be atomic, and unverifiable requested cleanup must be nonzero.
- **MUST-FIX — PSReadLine is shared and movable:** copy A and B share one nine-file module; A’s cleanup removes it while B still relies on it. If Documents redirection changes, cleanup checks the new root and misses the old one (`psreadline.rs:documents_directory/module_directory/remove_from`). Treat it as a per-account, reference-counted/last-live-owner mark and ledger the resolved install root.
- **NOTE — shell-start budget is not bounded:** `Test-Path` against roaming `%APPDATA%` can block on a network/offline-files path. It is one operation, but not necessarily cheap; the acceptance test needs a disconnected redirected root.

### Layer 1 — cleanup and entrances

- **BLOCKS — “all R” is internally false:** cleanup promises every X/R mark, while the plan says the Windows toast AUMID is never removed and says the only new remover is `$PROFILE`; no AUMID remover exists (`bt-platform/src/lib.rs:notification_aumid_key`, `windows_impl::Notifier`). The macOS notification grant is OS-owned and not programmatically retractable. Reclassify OS-held preferences as explicit exclusions; add removal for Folio’s HKCU AUMID declaration and clear pending notifications if supported.
- **MUST-FIX — unknown Explorer state exits 0:** deployment/registry state is unreadable → `MenuRemoval::Unanswerable` becomes `MenuFate::left`, so the command succeeds while a dead menu may remain (`explorer_menu.rs:package_taken_off/both_registrations_removed`). “Could not verify requested removal” must be nonzero.
- **BLOCKS — macOS Services is absent from the inventory:** deleting/moving the bundle can leave LaunchServices/pbs caching `NSServices` temporarily → Finder can retain a dead “Open in Folio” row. The repo’s own proof explicitly unregisters then updates pbs (`packaging/macos/Info.plist.in:NSServices`, `docs/plans/port/m4-9/m4-9-door.sh:unregister and remove`); cleanup needs the supported equivalent or must state/test OS convergence.
- **BLOCKS — recursive folder deletion deletes user material:** a zip was unpacked beside documents, another Folio copy, or user-added plugins → `cmd /c rd /s /q <folder>` deletes all of it → rule 4 is defeated even without `--purge`. Remove only a signed/package manifest’s files, then remove directories only if empty; never recursively delete an arbitrary archive parent.
- **MUST-FIX — moved/in-place/side-by-side identity:** a folder moves → its old ARP command is dead before self-repair can run; unzip-over should keep one identity and refresh `DisplayVersion`; unzip-beside needs a second identity. Put a random install UUID beside the binary, use it in a per-copy ARP key, and migrate that key when the UUID-bearing folder next launches.
- **BLOCKS — duplicate Settings rows:** enabling Explorer’s sparse MSIX already creates a Settings ▸ Apps row, then the proposed portable ARP registration creates another “Folio” row; the wrong Uninstall removes only the sparse package. Distinguish the sparse entry as an integration or replace the architecture; do not present two indistinguishable doors (`explorer_menu.rs:package_removal`, `bt-platform/src/msix.rs:register/remove`).
- **MUST-FIX — standard users and foreign ownership:** HKCU and per-user MSIX need no elevation, but a standard user cannot remove an app bundle/folder owned by another user or protected location. Cleanup may remove that user’s X/R marks, then must leave files and clearly report the permission boundary; Apple says deletion can require administrator credentials: [Apple uninstall guidance](https://support.apple.com/en-gb/102610).
- **BLOCKS — cleanup/purge while Folio lives:** another copy invokes the early CLI door while Folio/WebView2 is using the shared data roots → settings can be lost/recreated and UDF deletion is partial or denied. Acquire the same data-directory claim and refuse purge while any owner is live; GUI uninstall must close windows, flush, release WebViews, then hand off.
- **MUST-FIX — partial cleanup must gate app deletion:** a locked/malformed profile or agent file refuses removal, but GUI/package removal continues → the executable disappears and the foreign mark remains. Do not delete the owning files unless every non-inert X mark was removed or independently proved inert; print an actionable retained-path result.
- **MUST-FIX — Windows paths:** spaces/non-ASCII work only if the entire launch uses `CreateProcessW`/native argv; a trailing separator and roots must be canonicalized and refused as delete targets. Shell quoting around `cmd /c rd` is not an adequate containment proof.
- **MUST-FIX — self-delete can be blocked:** Defender/SmartScreen or another AV blocks the spawned `cmd`/batch self-delete pattern → cleanup reports success but the application folder and dead ARP entry remain. Use the signed native helper described in Q3, wait for and report its result, and leave a retryable entry when deletion fails.
- **BLOCKS — macOS translocation:** a quarantined zip app launched from Downloads may execute from a randomized read-only path, and Apple provides no supported way to recover the original path → “move itself to Trash” targets the translocated copy or fails, leaving the original. Require installation/move first, or clean integrations then reveal the original for Finder; see [Apple DTS App Translocation notes](https://developer.apple.com/forums/topics/code-signing-topic?page=2&sortBy=oldest) and [read-only translocation](https://developer.apple.com/documentation/fileprovider/nsfileprovidererror/code/providertranslocated).
- **MUST-FIX — Trash is an async, fallible operation:** the app is still open or `/Applications/Folio.app` is not writable → self-trash can show UI, require admin credentials, or fail. Use `NSWorkspace.recycle` after coordinating shutdown and report its result; the API explicitly returns per-item failures: [NSWorkspace recycle](https://developer.apple.com/documentation/appkit/nsworkspace/recycle%28_%3Acompletionhandler%3A%29?language=_1).

### Layer 2 — later installer

- **NOTE — deferral is reasonable only after Layer 1 is honest:** the installer may wait, but the per-copy UUID/ledger and manifest-safe file removal are Layer-1 primitives; deferring them would bake incompatible ARP/package state into 0.4.3/0.4.4.

## 2. Answers to Q1–Q7

### Q1 — agent execution and exact commands

- **VERIFIED — Claude:** shell form is `sh -c` on macOS/Linux, Git Bash on Windows when present, otherwise PowerShell; `shell` can force Bash/PowerShell. Hooks are synchronous unless `async:true`; missing commands are non-blocking failures for most events, with a transcript notice in normal synchronous handling; async completion notices are suppressed by default but visible in verbose/debug. Input is stdin ([official fields](https://code.claude.com/docs/en/hooks#command-hook-fields), [failure display](https://code.claude.com/docs/en/hooks#exit-code-output), [async behavior](https://code.claude.com/docs/en/hooks#run-hooks-in-the-background)). Use Windows `{shell:"powershell", command:"$p='C:\\…\\folio.exe'; if (Test-Path -LiteralPath $p -PathType Leaf) { & $p attention claude-code:<event> [--json -] }", async:true}`; Unix `{shell:"bash", command:"p='/…/folio'; if [ -x \"$p\" ]; then exec \"$p\" attention claude-code:<event> [--json -]; fi", async:true}`. Escape an apostrophe as `''` in PowerShell and `'\''` in sh; include `--json -` only where `attention_hooks.rs:command_for_on` does. `async:true` alone is **not** enough.
- **VERIFIED — Codex:** `notify` is direct argv, receives one appended JSON argument, redirects stdin/stdout/stderr to null, does not wait, and converts spawn failure to `FailedContinue`; runtime logs a warning but emits no user error event for continue ([official config](https://developers.openai.com/codex/config-advanced), [OpenAI source](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/legacy_notify.rs), [runtime](https://github.com/openai/codex/blob/main/codex-rs/core/src/hook_runtime.rs)). Keep the exact cross-platform array `[E,"attention","codex:agent-turn-complete","--json"]` (`attention_codex.rs:program_for`). This is screen-silent when E is missing, though not debug-log-silent; a shell guard would add a process, so the two absolute requirements cannot both be improved without a stable launcher or upstream conditional-exec support.
- **VERIFIED — Copilot CLI:** `bash` and `powershell` are shell strings; `exec`/`args` is direct. Most failures are logged/skipped, exit 2 surfaces stderr, `preToolUse` failures can deny, and only `notification` is fire-and-forget ([official schema](https://docs.github.com/en/copilot/reference/hooks-reference#configuration-file-syntax), [failure table](https://docs.github.com/en/copilot/reference/hooks-reference#exit-codes-for-command-hooks)). Folio installs several non-notification events (`attention_copilot.rs:rows_to_install`), so guard them: Windows `powershell:"$p='C:\\…\\folio.exe'; if (Test-Path -LiteralPath $p -PathType Leaf) { & $p attention copilot:<event> }"`; Unix `bash:"p='/…/folio'; if [ -x \"$p\" ]; then exec \"$p\" attention copilot:<event>; fi"`. Keep `timeoutSec:5`.

### Q2 — portable Settings ▸ Apps entry

- **INFERRED — acceptable, with constraints:** per-user applications are legitimately displayed in Add/Remove Programs, and Microsoft documents the values ([ARP configuration](https://learn.microsoft.com/en-us/windows/win32/msi/configuring-add-remove-programs-with-windows-installer), [Uninstall key](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key)). Use `HKCU\...\Uninstall\Folio-<install UUID>` with `DisplayName` (disambiguate folder), `Publisher`, `DisplayVersion`, `InstallLocation`, `DisplayIcon`, quoted `UninstallString`, truly silent `QuietUninstallString`, `NoModify=1`, `NoRepair=1`, and optional `EstimatedSize`/URLs. The UUID marker travels on moves; in-place update refreshes the same key; side-by-side copies get distinct keys. A fixed product key cannot meet the two-copy requirement.
- **VERIFIED — suppress it for WinGet:** WinGet portable install already creates registry entries and installed-app identity ([WinGet portable FAQ](https://github.com/microsoft/winget-pkgs/blob/master/doc/FAQ.md#how-do-portable-applications-get-installed)). A second Folio ARP row risks duplicate detection/uninstall and version matching; ship a WinGet-specific channel fact or change package type rather than infer. WinGet validation also tests unattended uninstall and residuals: [validation guide](https://github.com/microsoft/winget-pkgs/blob/master/doc/Validation.md).

### Q3 — self-removal

- **INFERRED — Windows:** there is no safe universal `cmd /c rd /s /q` form for this product. Copy a signed helper to a private temp/local-app-data nonce, launch it with native wide argv as `helper --wait-pid <pid> --install-id <uuid> --target <canonical path>`, have it wait for the exact process, verify UUID + containment, delete only manifest-listed shipped files, remove empty dirs, and self-clean later. Refuse roots, reparse points escaping the target, unknown files, and a target that changed identity. This handles spaces/non-ASCII without shell parsing and makes AV failure reportable rather than silent.
- **VERIFIED/UNKNOWN — macOS:** `FileManager.trashItem`/`NSWorkspace.recycle` can request a trash move, but Apple instructs users to quit first and may require administrator credentials ([trash API](https://developer.apple.com/documentation/foundation/filemanager/trashitem%28at%3Aresultingitemurl%3A%29?language=objc), [support](https://support.apple.com/en-gb/102610)). Whether a notarized non-sandboxed app can trash every ownership/location case without a prompt is **UNKNOWN** and should not be promised; translocation definitely prevents identifying the original supportedly.

### Q4 — ownership

- **INFERRED:** agent hooks have one active owner: B must show “installed by A” and require explicit takeover; takeover atomically rewrites to B; cleanup removes only an exact normalized B executable, or a dead Folio executable. Profile/script and PSReadLine are shared per-account resources: maintain a ledger of install UUIDs and resolved paths, prune dead owners, and remove only for the last live owner (or an explicit remove-for-all action). Cleanup from an unrelated copy must not call today’s family-wide removers.

### Q5 — purge/WebView2

- **VERIFIED:** WebView2 requires ending the session and waiting for browser processes; multiple app processes can share a UDF and must coordinate ([Microsoft UDF guidance](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder), [BrowserProcessExited](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2environment5)). Close every Folio/WebView, wait boundedly for the recorded browser PID/event, then delete. On timeout/lock, leave the root, print its exact path and reason, and exit nonzero; never claim “purged.”

### Q6 — missing inventory

- **VERIFIED:** `%APPDATA%\BetterTerminal` is a possible active/stale O root when migration fails or both old/new roots exist (`persist.rs:storage_location/storage_dir/relocate`); it is missing. The plan also says “five” macOS purge locations but names six when Application Support is included: Application Support, WebKit, Caches, HTTPStorages, Preferences, Saved Application State. `%TEMP%\folio-panic.log` is correct in current code (`main.rs:PANIC_LOG_FILENAME`), despite stale docs naming `bt-app-panic.log` (`docs/BT-ENVIRONMENT.md`). macOS `NSServices` registration/cache is missing (`packaging/macos/Info.plist.in:NSServices`). User-selected `BT_*` trace/dump paths are also writes outside §1, but must be explicitly excluded from purge because the user named them (`docs/BT-ENVIRONMENT.md:release-build table`). OS crash reports and notification preferences/grants should likewise be listed as OS-owned exclusions, not silently promised as purgeable.

### Q7 — package-manager policy

- **VERIFIED — Scoop conflict:** `pre_uninstall`/uninstaller are called on both uninstall **and update**; `$cmd` tells which ([manifest docs](https://github.com/ScoopInstaller/Scoop/wiki/App-Manifests), [script variables](https://github.com/ScoopInstaller/Scoop/wiki/Pre-Post-%28un%29install-scripts)). As written, an update removes integrations. Gate cleanup on `$cmd -eq 'uninstall'`; write the marker in install/post-install and test the version-directory versus `current` junction.
- **VERIFIED — Homebrew conflict:** official casks reject legacy Ruby flight blocks; only structured `uninstall_preflight_steps` are accepted, their sandbox needs declared writable paths, and `zap` runs only with `--zap` ([Cask Cookbook](https://docs.brew.sh/Cask-Cookbook)). Use a supported `run` step or `uninstall script:` and prove whether it also fires on upgrade; otherwise it will silently disable integrations. Zap must not remove directly user-created files. A marker written inside the notarized `.app` after signing invalidates the bundle; use a signed-in artifact or external ledger.
- **VERIFIED/INFERRED — WinGet conflict:** zip/portable has no Folio hook; `winget uninstall --purge` removes the package directory and `--preserve` retains it ([WinGet uninstall](https://learn.microsoft.com/en-us/windows/package-manager/winget/uninstall)). WinGet already owns portable ARP identity, so Folio’s self-entry must be suppressed (**VERIFIED**); how a duplicate would score in every client version is **UNKNOWN**. Test in Microsoft’s recommended Windows Sandbox path before submission.

## 3. Slicing judgment

- **MUST-FIX — 0.4.3 remains the foundation, but enlarge T-A/T-C:** ship exact guarded-hook forms; migrate legacy profiles/hooks on startup, not only when a pane opens; introduce install UUID + durable ledger; make all removers exact-owner, schema-aware, byte-preserving, idempotent, and nonzero on refusal/unknown; add Windows AUMID and macOS Services handling; correct the inventory before package hooks ship.
- **BLOCKS — do not ship the proposed Scoop/Homebrew hooks until update semantics are solved.** A cleanup that runs on upgrade trades stale marks for silently lost integrations.
- **MUST-FIX — move discoverability earlier:** ship `uninstall.cmd` (cleanup only, no recursive self-delete) and the rewritten docs in 0.4.3. Existing users need a one-time in-app/release-note notice: “Run 0.4.3 once to upgrade existing hooks/profile; thereafter deleting Folio is harmless. `folio --uninstall-cleanup` removes integrations; `--purge` also removes settings/data.” A deleted old binary cannot retroactively repair its marks; publish a signed standalone rescue command/binary or exact manual recovery page.
- **NOTE — 0.4.4 GUI can wait; ARP cannot be ticketed until helper/UUID/duplicate-MSIX/WinGet behavior is designed.** The GUI must preview exact paths, close/flush first, abort file removal on unresolved active marks, and report partial outcomes. Layer 2/installer may remain 0.4.5.
- **MUST-FIX — isolated test plan:** pure decision tests with injected filesystem/registry/process traits; byte-for-byte fixtures for LF/CRLF/UTF-8-BOM/UTF-16 refusal, symlink/read-only/locked/malformed/future schemas; temp `HOME`/`APPDATA`/`LOCALAPPDATA`/`CLAUDE_CONFIG_DIR`/`CODEX_HOME`/`COPILOT_HOME`/`BT_POWERSHELL_PROFILE`/`BT_PSREADLINE_DOCUMENTS`; two-copy, moved, unzip-over/beside, spaces/CJK/apostrophe/trailing-separator, dead-owner/takeover, partial failure, rerun/idempotence, and simulated power loss. Run registry/MSIX/WinGet/Scoop only in disposable Windows Sandbox/VM users; Homebrew/LaunchServices/translocation/ownership in a disposable macOS account or snapshot. Never use the developer’s real configs, clipboard, registry, or running Folio.

## Verdict

**RETHINK** the ownership and channel mechanics, not the three-layer product shape. Required changes: (1) install UUID + exact-path ledger; (2) separate per-copy from shared marks; (3) verified guarded agent commands and startup migration; (4) refuse/unknown is failure and gates deletion; (5) manifest-based helper, never recursive folder deletion; (6) solve package-manager upgrade/marker/duplicate-ARP behavior; (7) include AUMID, macOS Services, legacy data root, and explicit OS-owned exclusions; (8) move a safe discoverable cleanup and existing-user notice into 0.4.3.
