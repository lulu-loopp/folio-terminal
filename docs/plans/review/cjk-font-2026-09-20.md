# CJK terminal font review — 2026-09-20

## Baseline account (recorded before judging H1–H3)

- `prepare_text_rows` (`crates/bt-render/src/lib.rs:11696`) receives every live or
  transcript grid row and the status-overlay row, then calls both grid shapers.
- `shape_narrow_glyphs` (`:14831`) and `shape_wide_glyphs` (`:14878`) reduce those
  rows to per-cell `ShapeKey`s and enter their respective shaping caches.
- `shape_narrow_buffer_for_key` (`:14505`) and `shape_wide_buffer_for_key` (`:14952`)
  route ordinary Han as `PresentationRoute::TerminalText`, then request
  `Family::Monospace` (`:14514`, `:14965`).
- `terminal_font_system` loads a bounded Windows database (`:14171`), maps
  `Family::Monospace` to the primary terminal face (`:14198`), and supplies
  `FolioFallback` (`:14139`). The library, not Folio, therefore decided which
  loaded face supplies a missing Han glyph.
- Focus-card mini transcript labels are a second projection: `set_chrome_label_text`
  (`:12055`) calls `mono_label_spans` (`:12028`), whose `mono_cluster_family`
  (`:11999`) also returned `Family::Monospace` for ordinary Han.
- Markdown/preview monospace runs go through `set_preview_runs` (`:13039`). They are
  not a terminal-grid projection and are explicitly out of scope.

## Evidence and hypotheses

- A1 baseline command: `cargo test -p bt-render -j 4
  grid_han_uses_the_first_available_cjk_family -- --nocapture`.
- Result: 1 selected, failed. The shaped glyph's `font_id` resolved to `NSimSun`;
  the first installed chain entry was `Microsoft YaHei UI`. The failing assertion
  was `grid must name the first available family in its CJK chain`.
- This confirms H1 on this Windows machine. It also supports H2: an explicit named
  family bypasses the monospace-gathering stage instead of trying to influence it.
- H3 is structurally supported: cell columns come from captured wide-cell
  flags and slot columns; shaping buffers are placed at those absolute columns.
  The extended ASCII + Han + kana + fullwidth + emoji fixture keeps it executable.

## Chosen seam and ownership

- `terminal_cjk_family_chain` builds the ordered chain from the stored custom
  choice plus platform defaults. `resolve_terminal_cjk_families` resolves it once
  per font-setting change for Han, hiragana, katakana and hangul.
- Both terminal-grid buffer routes and `mono_cluster_family` consume that resolved
  state and return `Family::Name`. Folio therefore names every cared-about CJK
  script by construction; generic
  fallback remains only for scripts Folio does not name.
- Writer paths are startup and the hot settings change. The setting remains the
  persisted source; the GPU context holds the active rendering value.
- `set_terminal_font` advances the font-environment epoch and loads only files for
  explicitly selected primary/CJK families. Each window's `apply_font_change`
  reaches `adopt_metrics`, clearing text rows, status overlay, composed rows,
  narrow shaping, wide shaping, and math textures while bumping `font_revision`.
  The content-addressed glyph atlas is retained safely; its normal post-frame
  `trim` retires unreferenced old-font glyphs after all rows are re-prepared.

## Paths, budget, and remaining evidence

- Grid paths covered: live grid, transcript, and status overlay via
  `prepare_text_rows_with_cjk`; focus-card mini transcript via `mono_label_spans`.
- The picker walk is performed by the existing below-normal worker; the dialog's
  scan-counter test proves reading and drawing both rows does no synchronous walk.
- Before: one `Family::Monospace` request permits a database-wide monospaced
  coverage scan before script fallback. After: zero chain lookups at shaping time
  and one explicit named-family request; the library exposes no candidate counter.
- Startup loads no additional files for automatic mode. A custom family loads only
  the file paths returned by the platform enumeration. Quiescent work is zero.
- Unverified here: visual inspection in a real Folio window and the macOS runtime
  result (PingFang rather than `GB18030 Bitmap`). CI/a Mac must supply those.
- Rollback is commit reversion. Older builds ignore the added JSON key because
  deserialization does not deny unknown fields.
