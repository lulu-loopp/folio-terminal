## 二、「Folio」在软件领域是拥挤词

已知的同名在用者(非穷举,只是随手可见的两个):

- **FOLIO** —— 开源图书馆服务平台(library services platform),有基金会、有
  商标使用记录、在「软件」这个大类里活跃。
- **kkauff/folio** —— GitHub 上的同名 Windows 应用。

拥挤的后果是双向的:一方面别人很难拿这个词垄断整个软件类目,另一方面**我们
也拿不到干净的独占**,并且在具体子类(终端模拟器 / 开发者工具 / 远程访问 /
SaaS)里仍然可能撞上在先使用者。

## 三、公开 v0.1 之前该做的检索

建议在**首次公开发布之前**做一次名称检索,范围至少覆盖:

- 软件与开发者工具(USPTO 第 9 类 / 第 42 类的常见描述)
- 终端模拟器、命令行工具这一具体品类的在先使用(未注册也算)
- 远程访问 / 手机端控制类服务(见第五条,产品路线图上有)
- SaaS 与在线服务类

**检索出结果之前,不要在任何界面、文档或站点上使用 `®` 或 `™`。** `®` 在
未注册时使用在美国属于虚假标示;`™` 虽不要求注册,但在一个尚未做过检索的
拥挤词上主动宣示来源标识,只会在将来的争议里被拿来当作明知故犯的证据。
`TRADEMARK.md` 现在的措辞是「Folio 这个名字与标识不随双许可授出」,不含任何
注册宣称,这个尺度是对的,别加符号。

## 四、权利链:早期提交的归属

- 本仓库**最早的一批提交用的是学校(umich)邮箱**。门 0 的历史重写会把作者
  邮箱统一改成个人邮箱,但**改邮箱不改归属**:代码写作时的雇佣/学籍关系
  是什么,权利就按什么走。
- **作者须在发布前自查学校与雇主的知识产权政策**——多数美国高校对「未使用
  学校实质性资源、非职务范围」的个人项目不主张权利,但判据在具体条款里,
  不在惯例里。若有任何一条落在灰区,先取得书面放弃(waiver)或确认函,再发布。
- 这一条是**唯一一条会让双许可整体失效**的风险:版权不在手上,授出去的许可
  就是空的。优先级高于本文其余各条。

## 五、手机远程服务上线时另需的文件

产品路线图上有「手机远程控制终端」这一条。**那不是一次发版,是一次上线服务**,
届时另需(现在不需要):

- 隐私政策(collect 什么、存哪、留多久、第三方处理者是谁)
- 服务条款 / 可接受使用政策
- 若面向欧盟或加州用户:对应的数据主体权利与披露条款
- 若涉及账号与传输:安全声明与事件通报承诺

`SECURITY.md` 现在只覆盖本地二进制,不覆盖服务。别把服务条款塞进 README。
