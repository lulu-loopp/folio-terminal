# 分栏归栏(暂名)——整列分拣益智,游戏座位的第一个住户

> 规格由用户口述规则 + 三张实机截图(2026-08-30/31,#212–#214)定稿;玩法借「排队分拣」家族,美术、名字、角色全部自创;落地排在 v0.1.0-preview tag 之后。

## 一、规则(用户逐条确认)

1. **盘面 = 若干列**,列高不等;底部可有**石头**占格(地形的一部分,不可动)。
2. **每种动物的总数 = 恰好等于某一列的高度**:6 只的动物只能在 6 格列积满,4 只的只能在 4 格列。生成器保证这个配平。
3. **只有列顶连续同种的一段可动**,整段一起走;只能落在**顶端为同种**且剩余空间足够的列上。
4. **空列接受任何一段**(截图 #214 col 4 可被搬空;此条为家族惯例,实现后实测手感再钉)。
5. **一列全同种且积满 = 完成**:动物落座锁定,不消除,列从此不可落子。全部列完成 = 通关。
6. **暗牌 `?`**:被压住时不可见,上方搬走即翻开。
7. **临时格**:每格暂存一只(段落进临时格拆成单只?——**待实测原作**;先按「单只」实现);从临时格回场同样要顶端同种或空列。
8. **无步数限制、无倒计时**(原作有的倒计时不做;我们的场景是等 agent,不给时间压力)。
9. 撤回:免费不限;打乱:每局 1–2 次。

## 二、临时格政策(用户裁决 2026-08-31)

- **格数是关卡属性**:生成器用求解器量出该关最少所需暂存峰值 S,关卡自带 S+0~1 格(难关给 S,普通关给 S+1)。局内**不解锁**——「每完成一列解锁一格」被否决(后期滚雪球变简单)。
- **额外格 = 玩出来的(用户裁决 2026-08-31)**:卡关时点「+1 临时格」跳进另一个小游戏(跑酷)打一局,**达到目标分即解锁,本关有效**;每关至多 +1~2 格。目标分有默认值,设置里用户可自改(调到零也行——解锁权在用户,默认只留一个小门槛)。原作的广告位由此换成一局游戏。
- 后果:跑酷从「最后、可裁」升格为**门用游戏**,先于本作或与本作同批做(它同时仍是管线验证者)。
- 无广告、无内购、无任何联网(README 隐私承诺覆盖)。

## 三、生成(工程主难点,两段式)

1. **逆向生成保证有解**:从终局(各列纯色积满)出发做 N 步合法逆移动打乱;每步构造成正向可走,关卡天然携带一条解。石头/暗牌/列高在打乱前作为地形参数摆好。
2. **求解器定难度**:记忆化 DFS/IDA*(状态 = 各列栈 + 临时格,哈希去重)量出:最少步数、被迫暂存峰值 S、分叉宽度、暗牌造成的不可知步数。按指标分级、排曲线,越界重生成。
3. **关卡离线烤好**(种子 + 参数,进仓库或资源文件,确定性可重放);无尽模式 = 运行时按种子生成 + 求解器兜底(超时丢弃换种子)。
4. 难度旋钮:动物种数、列高分布、地形(短列/石头)、交错度(逆移动步数与选段策略)、暗牌数、临时格 S 余量。

## 四、工程形态(定稿见对话 2026-08-31)

- **游戏座位**:与预览/视频同级的 pane 内容,bt-render 直接画;输入走 pane 焦点;动画走 motion 三档;reduced-motion 生效。
- **逻辑纯 crate**:状态机 + `tick(input) -> 画布`,不知窗口不碰 GPU;整局可单测(录输入断言终局)。
- **Folio 规矩**:agent「等你回答」到达 → 自动暂停 + 提醒照常;失焦即暂停;存档 `%APPDATA%\Folio\games\`(回合制每步落盘)。
- **入口**:`folio.exe game <name>` 子命令 + 内置配置一条,热键终端选择器直接列出。
- 美术:终端字符/极简自绘方块,不借任何现有游戏的形象。

## 五、排期与顺序(用户裁决)

1. 跑酷先做(门用游戏 + 管线地基,最便宜)。
2. 本作(益智)第二,带着「+1 格走跑酷门」一起落。
3. 幸存者-like(长局)第三。
