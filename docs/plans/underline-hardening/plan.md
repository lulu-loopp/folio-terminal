## 由头
裸路径/URL 识别(DESIGN §7.1.5f–j)分五批长成,每批修一个现场:折行重接、非 ASCII 终止、行号、验证饥饿。用户 2026-08-23 裁:**不再一案一修,把形态×情境考虑清楚一次完善**。触发案例(最重的一条是「指错」):

- **A. 折断的前半截碰巧存在**:`C:\WINDOWS\system32\...\Modules` 被应用硬折在 `system|32`,前半截 `C:\WINDOWS\system` 是真实目录 → 通过 verified 门亮线,点开的是没人指的地方。违反「指错比不认严重」。
- **B. 引号内 `;` 路径列表**:`PSModulePath="A;B"` 整串当一个 token 验不存在;拆开各是真路径。无既定规矩。
- (已修入册的先例:软折行本来就通、全角前导排除、验证饥饿两因、`path:line:col`、尾部非 ASCII 放开、ASCII 点连认——见 §7.1.5j 边界表 23 行。)

## 方案四件
1. **折断截断门**:token 结束在行最后一列 = 疑似被折,**单独不验证不亮**(宁不认不指错)。治 A。
2. **五道闸重接**(应用折行的推断引用,此前挂账 #16):①上半截止于最后一列 ②下半截起于第 0 列(或与上半同缩进?待 Codex 议)③拼接后被同一套词法读成一个 token ④拼出的路径磁盘上存在(第二证人) ⑤两半各自单独都不是已验证路径。裸 URL 无磁盘证人,明写不重接(证据不同说不同的话)。
3. **引号内列表**:引号 token 整体验不存在时,按 `;`(PATH 语义)拆段逐验?或 `;` 直接为引号内终止符?待议——注意引号是「边界声明」的既有裁决,拆开是否背叛它。
4. **对抗性用例库**:边界表升级为组合矩阵(app 折行 × 软折行 × 引号 × 列表 × `:line:col` × CJK 前后 × 宽字形 × alt 屏 × 存在/不存在/前缀存在),每格一条测试;新形态先进表再写码。
