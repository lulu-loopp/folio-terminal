# BetterTerminal 要解决的问题清单（待确认稿 v1）

> 定位：**为 AI agent 时代设计的 Windows 终端**。技术路线已定：原生 Rust + GPU（wgpu），
> 复用 alacritty_terminal（VT 解析 + 网格）、cosmic-text（字体整形）、portable-pty（ConPTY 封装）。
> 本清单确认后产出详细技术方案，交 Codex 审核。

## P0 — 核心差异化：富内容自渲染（没有任何终端做到）

| # | 问题 | 说明 | 验收标准 |
|---|---|---|---|
| P0-1 | LaTeX 公式自动检测与渲染 | 默认档只识别强定界块级形式（`$$...$$`、`\[...\]`）；行内 `$...$` 默认关闭，仅 aggressive 档或已确认的 agent 输出块内开启（误检风险，见 DESIGN §4.2）。渲染引擎经 M-1 spike 定案 | Claude Code 输出的公式在终端里直接显示为渲染后的数学公式 |
| P0-2 | 检测时机（稳定性判定） | 基于**网格状态**而非字节流检测：行滚出活动区/一段时间未被覆写才检测；alt-screen（vim/htop）期间全局关闭 | vim、htop、Claude Code 的 ink 界面零破坏 |
| P0-3 | 变高布局（BlockList） | 公式块比单元格行高，需要 Warp 式 BlockList + SumTree 虚拟化，文本块与富内容块同栈滚动 | 滚动、resize、定位在混排内容下全部正确 |
| P0-4 | 误检测控制 | `$PATH`、`awk '{print $1}'` 等不能误渲染；保守启发式（成对闭合 + 内容像数学）+ 单块可还原 + 全局开关 | 日常 shell 使用中误检率接近零；误检可一键还原 |
| P0-5 | 复制语义 | 选中/复制公式块时得到**原始 LaTeX 源码** | 复制粘贴回 Claude Code/论文中可直接使用 |
| P0-6 | Markdown 就地渲染 | 代码块语法高亮、表格、标题、列表、粗斜体的美化渲染（同一套检测与块机制） | Claude Code 的 Markdown 输出可读性显著优于纯文本 |

## P1 — AI agent 时代适配（第二差异化，仅 cmux/superterm 等小众工具在做且均无 Windows 版）

> 范式判断：用户角色从"操作一个 shell"变成"监工 N 个并行 agent"，终端的新职责是**注意力管理**。
> UI/UX 不是附加功能，是与富内容渲染并列的设计支柱。

| # | 问题 | 说明 |
|---|---|---|
| P1-1 | 流式输出渲染鲁棒性 | agent 高频、多行、富 ANSI 输出下无孤立光标、无卡顿重绘、无状态栏残留（Wave 的反面教材）；大输出下性能不衰减 |
| P1-2 | **标签状态感知**（原名 "Agent 状态"，已纠正） | 这些是**标签的状态、不是 agent 的状态**——报错来自 `cargo`/`git`/任何东西，问 y/n 的是 `apt`，要密码的是 `sudo`。**状态列表由"终端能知道什么"决定**：运行中（OSC 133 C）/ 有进度（**OSC 9;4**，程序主动报的）/ 完成·未读（133 D 退出码 0）/ 失败·未读（退出码非 0）。**"等你"一般情况下无法知道**——只在程序经 side-channel 主动告知时才亮，否则如实显示为"运行中"。排在 P2-11 全局搜索之后（同源，见其说明）。详见 docs/UI-UX.md §8 |
| P1-3 | 会话元数据 | 每个会话显示 cwd、git 分支、运行中命令、agent 最新消息摘要（shell 集成 + OSC 协议）。**其中 cwd 不排在 P2-11 之后**：它是 **OSC 7**，shell 主动报的，不需要搜索+匹配去猜（那是 P1-2 状态检测的处境）。而且它**不是元数据装饰，是身份**——同时跑 N 个同类 agent 时图标与名字全同，**目录是唯一的区分**。已落原型：标签写 cwd、图标写 profile，两者配对才唯一。详见 docs/UI-UX.md §4 |
| P1-4 | 长任务友好 | 任务完成系统通知（点通知直达对应会话）。**Pin + 恢复（2026-07-16 大幅简化）**：pin 的单位是**一整棵分屏树**（叶子存 **profile + cwd + 名字**）；**恢复 = 在原来的目录里、按原来的布局、开一个全新的 shell。就这些。**
  - **启动只问一件事，而且不是 pin 过的标签**（2026-07-16 定）：**pin 本身就是那个答案**——它的含义就是「下次给我打开」，所以开机再问一遍「要不要打开你 pin 的」是**把同一个问题问两遍，而第一遍你早就答过了**。**pin 过的直接开。** 我们真正不知道的是：**那些你没 pin 的标签，是你想留的会话，还是你想关掉的一摊乱**——**那个才值得一问**。**§8.0 在 UI 层的样子：知道的别问，不知道的才问。**（浏览器就是这么解的：pin 的自动回来，"要恢复页面吗"只针对会话。）
  - **一个未知都没有时，弹窗根本不出现**（全 pin 的情况实测：不弹、不加占位 shell）。**而 pin 的标签就在弹窗后面开着——它们不需要一句话解释，你看得见。** ~~转录恢复 / 崩溃恢复 scrollback~~ **已删——输出不落盘**（见「明确不做」）。**这一刀把「重开的标签里『昨天的输出』和『这次的运行』要看得出边界」这个设计题整个删掉了：没有昨天的输出，就没有那条边界。** 「上下文」现在只剩一样能恢复:**位置**。**转录归它的主人**（Claude Code 自己存），**进程谁也恢复不了**（除非常驻服务，见「待定」），**而把它叫回来是自动化的事**（P3-4，如 `claude --continue`——§8.5.3 早就这么写了）。**能删掉一个问题永远好过把它管起来。** 详见 docs/UI-UX.md §8.5.2 |
| P1-13 | **最近打开（原「历史记录」）** | 存的是 **{profile, cwd, 名字, 时间}——不是输出**。**名字骗人**：叫「历史记录」用户会以为里面有输出，打开发现是一列文件夹。**它有一个被亿级用户验证过的样板：VS Code 的 Recent 列表**——「你最近在哪些文件夹开过东西」，是 VS Code 启动时你看到的第一样东西。**它不是历史记录的降级版，它就是 Recent，而 Recent 恰好正是 §1.0 说的「现代 app 该有的样子」。** **与 P1-4 共用一个存储层，三种取用方式**：**Pin**＝「这个永远给我恢复」、**最近打开**＝「所有的都可取回」、**撤销关闭（`Ctrl+Shift+T`）**＝「最近那个，现在，马上」。**分开做会得到三份写盘逻辑。** 撤销关闭在不存输出的模型下**依然成立、而且更诚实**：手滑关掉跑了两小时的标签，你要的本来就是「让我回去」——它不再假装能把上下文还给你 |
| P1-5 | 环境健康提示 | 检测开发目录未做 Defender 排除/未用 Dev Drive 时提示（agent 工作流下文件操作收益巨大）——终端不能让 grep 变快，但能告诉用户为什么慢 |
| P1-12 | **会话命名**（自主 + 手动） | 优先级链：**手动命名 > 程序标题（OSC 2）> cwd（OSC 7）**，每层比上层更具体。**和 cwd 同类——程序主动报的，不必等 P2-11**。agent 会主动命名终端（Claude Code 就在做）；**三个 claude 跑在同一仓库时，标题是唯一的区分**。**没解决的**：`Windows PowerShell` 这类默认标题无信息，而**按「是否有用」过滤就是在猜**——所以照实显示，**而这正是手动命名存在的理由**。**标题是程序控制的文本 = 不可信输入**：剥控制字符、限长、不得冒充 chrome。详见 docs/UI-UX.md §8.5.1 |
| P1-6 | 纵向会话侧边栏 | 横向标签在多会话下退化为窄条；侧边栏每会话一行：状态徽标 + 名称 + cwd + 分支 + 最新消息摘要（cmux 已验证方向） |
| P1-7 | 总览模式 | Mission Control 式一键铺开所有会话的实时缩略图网格，扫一眼全局 |
| P1-8 | 注意力队列与导航 | "N 个会话在等你"；单快捷键跳到下一个需要处理的会话，处理完继续跳 |
| P1-9 | 快速切换 + 命令面板 | 模糊搜索切换会话（按名称/目录/分支，类似编辑器 Ctrl+P）；所有操作可经命令面板搜索执行；Quake 模式全局呼出（WT 历史 653👍 需求） |
| P1-10 | 渐进式披露 + 布局可控 | 单会话时界面如 Ghostty 般干净，侧边栏/徽标随会话数增长才出现（自动模式默认）；但布局**必须可手动固定**：横向标签 / 纵向侧边栏 / 自动 三档（类 Edge 垂直标签的切换），不强迫用户接受自动切换（反面教材：Warp 的视觉噪音）。**验收原则已反转（2026-07-16）：不是"键盘优先 + 鼠标等价"，是「可发现优先 + 键盘完备」**——前者允许一个功能只有快捷键、没有可见入口，而**"只有背下来才能用"正是本产品要消灭的东西**（定位见 UI-UX §1.0）。任何功能须有"不知道它存在时也能撞见"的入口，且任何操作须能纯键盘完成。**注意「可发现」≠「鼠标」**：VS Code 的文件树全键盘可导航，它是「可见」控件不是「鼠标」控件 |
| P1-14 | **AI 命令助手**（2026-07-17 新增） | 场景：「不知道命令怎么打,又不想开 claude/codex」。**小而准,不做全能 agent**（全能的活归外部 agent,我们不抢）：命令面板 AI 模式（自然语言→命令建议）、解释选中命令、修复上一条报错。**模型无关**：任意 OpenAI 兼容端点（本地 Ollama / Foundry Local / 云端),Copilot+ PC 可接 Phi Silica（NPU 本地零配置）。**红线：绝不自动执行**——建议+用户确认,与 P2-6 paste-and-run 纪律同源。**语音闭环白嫖**：Win+H 对 AI 输入框听写 = 语音指挥,零额外成本（依赖 P2-14）。对标：Warp AI（已验证的形态）、WT Terminal Chat（预览试水）——Windows 原生阵地无人做好 |
| P1-11 | 分屏（panes） | **「Clicking a tab」那个模式设置已删除（2026-07-16）**：它让「tab」有两个含义（工作区 vs 寄存的会话），**而 pin 是第一张账单——实测 pin 会被静默销毁**；且它**是重复的**：拖标签到窗格中心做的是同一件事、同一段代码。**删模式、留能力。** 配套定下**「pin 跟着内容走」**（并入目标 → 目标继承；被顶出 → 保留原 pin；**但显式拖出成新标签 = 不继承**）。详见 docs/UI-UX.md §10 原则 20、21。tmux 式窗格是现代终端 table stakes（23/44 支持），Windows 无原生 tmux 更需要；agent 监工场景下"并排看两个会话"是高频需求；与 BlockList 视口天然兼容（每 pane 一个视口） |

## P2 — 基础正确性：把 Windows 终端的老毛病做对（table stakes 但普遍做不好）

| # | 问题 | 对标痛点 |
|---|---|---|
| P2-1 | CJK/emoji 宽度计算正确 | WT #370/#900：ambiguous width、grapheme clustering、VS15/16；中文用户日常痛点。**spike 04 实测查明：`bt-term` 今天没有 grapheme 聚类**（`vendor/alacritty_terminal/src/term/mod.rs:1203` 是逐 `char` 的 `c.width()`），所以 `👨‍👩‍👧‍👦` 现在会被拆成 **8 个 cell**、`👍🏽` 拆成 4 —— **WT #900 本体在我们自己的终端里**。**M0 裁决项：要不要给 bt-term 上 grapheme 聚类。****另有一个既有规格缺口**：CJK 语境下 **ambiguous width 判宽还是窄**（WT #370 的本体）DESIGN 里没有规定——`unicode-width` 的 `width()` 与 `width_cjk()` 对 `☆` 分别给 narrow/wide。**这条必须裁决后再写进任何测试**，否则测试只是把某一侧固化下来。详见 docs/spikes/04-ime-cjk.md |
| P2-2 | 中文 IME 体验 | Windows TSF 集成、候选框跟随光标、预编辑显示正确 |
| P2-3 | 输入延迟作为架构指标 | danluu 基准：目标事件→上屏个位数毫秒；waitable swapchain；避免 WT #649 式合成器掉帧 |
| P2-4 | 大输出不衰减 | iTerm2 #6897 反例：分段 buffer 设计，`tail -f` 大日志后打字不卡 |

| P2-8 | 秒开 | 冷启动目标 < 500ms（对标 conhost 体感，反例 WT 3-7s） |
| P2-9 | 回滚体验 | **有上限的、活会话内的**大容量回滚 + 正则搜索 + 水平滚动（WT #1860，252👍 最高呼声）。**「无限回滚」（WT #1410，153👍）明确不做，而这不是取舍是同一个决定的后果**：真·无限 = 输出必须写盘 = **「输出历史」那个蜜罐原样回来，只是改叫「回滚」**。原措辞「大容量」侥幸地对了，现在把它定死 |
| P2-11 | **全局搜索**（跨当前所有终端） | 搜当前所有**活着的**终端。~~乃至已关闭会话的输出~~ —— **已删（2026-07-16）：输出不落盘，见「明确不做」的「输出历史」**。**注意死的只是「落盘」，不是转录本身**：canonical transcript（逻辑行 + SourceMap + 锚点）照样是底座，`$$…$$` 检测（P0-1）、自动化的「等出现 X」（P3-4）、活会话搜索都要它。**与检测引擎同源**：`bt-detect` 找 `$$…$$`、y/n 检测找提问模式、搜索找用户给的模式——都是"在转录里找模式"，而 canonical transcript（逻辑行文本 + SourceMap + 锚点）正是搜索需要的底座。**先设计搜索，状态检测（P1-2）与自动化的「等待出现 X」积木（P3-4）都作为它的消费者落下来**，否则会孤立地实现两遍模式匹配再拆掉重做。**两个 API 面必须一起定**：`等屏幕出现 X` 与 `等历史出现 X` 是**两件事**（alt-screen 的程序不写转录，见 P0-2），且**匹配发生在字节到达时、不是轮询屏幕**——我们是管子本身，轮询会漏掉「打出来又被顶走」的那一行。详见 docs/UI-UX.md §9 与 §8.5.3 |

## 明确不做 / 非目标

- 不做 AI 功能本身（不内置 LLM 对话）——我们服务于 Claude Code 等 agent，不替代它们
- **不存输出历史**（2026-07-16 定）。**理由不是「没人要求」——那个论证第一个杀死的是 P0**（没有任何人要求过终端渲染 LaTeX，调研 02 空白需求 #5：「用户靠 `glow`」，零 👍，而那是我们的头号卖点）。**真正的判据是「有没有绕道行为」**：LaTeX 有（`| glow`、截图、切浏览器——**花力气绕缺口是显示性需求，比 👍 硬**）；跨会话搜输出**没有**。**因为它赢不了 `↑`**——"再看一眼那个输出"的成本是两个键，而搜历史返回的是一个过时答案。**调研三份文档里跨会话搜输出零条证据**；最高的两条恰恰都是「读当前会话」（#1860 水平滚动 252👍、#1410 回滚 153👍），`Ctrl+R` 是**命令**不是输出。**四条代价**：① 脱敏必须靠猜（§8.0），而**猜出来的过滤器比不过滤更危险**——它给人一种被保护的错觉；② 我们存的是渲染后的字节（ANSI、被覆写的行、TUI 中间态），**Claude Code 存的是 `~/.claude/**/*.jsonl` 结构化真相——我们只会是一份更差的副本，而主人就在旁边**；③ 体积；④ 把「终端」变成「记录仪」。**窄集合（两小时的构建、`terraform apply`、删掉的分支）的现成答案是 `tee`。**
  - **例外的形状不是「全存」，是「你自己标」**：一个「留下这个块」的显式动作（Warp block 模型 + §1.0 可发现）——秘密没了（**是你选的**）、体积没了。**和 mailbox 的「默认手动批准」同形：显式的人类动作，不是环境级监视。** 以后的事，不是这个决定的折中。
  - **会推翻它的证据**：我们自己用起来之后发现在 `tee` 一切。**这个问题不靠调研回答，几个月内它会自己回答。**
- **不造第二份副本 —— 把已有的那份呈现好**（今天出现三次，已升为原则）：**让程序自己报状态**（§8.0 / OSC 133）、**让 Claude 自己存对话**（上一条）、**让 shell 自己存命令**（PSReadLine/bash 已经存了命令历史，我们该给它一个好 UI——跨会话、按目录过滤、不是 `Ctrl+R` 那个单行洞——**而不是再存一份**）。**第二份永远更差：它是别人的真相经过我们之后的样子。**
- 不做账号系统、云同步、遥测（Warp 的反面教材）
- 第一版不做 macOS/Linux（架构上不排除，但 Windows 优先——竞品恰好都不在 Windows）
- 不承诺"命令跑得和 Mac 一样快"——进程创建/NTFS/Defender 是 OS 层问题，终端只负责渲染吞吐（见 P1-5 的缓解策略）

### 待定的架构决定（不是非目标，是还没决定）

- ~~**交互式 git UI（commit 树 / 暂存区 / 分支图）**~~ → **已升格并已落地（用户 2026-08-13 追认，G 块 G-0…G-5 交付，规格见 `docs/DESIGN.md` §7.1.3g）**。原文与它的结局都留在这里，因为这一条的价值在于它是怎么被翻案的：<br>原文——**不是非目标，是"不是第一版"**。原先以"lazygit 已经存在、它就跑在终端里"否掉——但那个论证在新定位下失效了：**对一个不想背命令的人，"你去用 lazygit"恰恰就是要消灭的那个毛病**（UI-UX §1.0）。**剩下的反对理由只有规模**（这是一个完整产品面）。**先做的是便宜的两层**：分支名 + dirty 进标签（P1-3，**走 shell 集成让提示符报出来，不要轮询仓库**）、diff 渲染（P3-9）。<br>**翻案的经过**：用户 2026-07-18 的两条 direction 直接把 Files|Git 双页签与 Git Graph 画进了小样（`design/ui-mockup.html` 1577/1651），也就是把"剩下的反对理由只有规模"这句话当成了一张可以支付的账单；2026-08-13 用户明确追认这条待定项升格，第一版范围 = 小样画的全部。<br>**上面那句"不要轮询仓库"没有被推翻，它被划清了**（R31，`DESIGN.md` §7.1.3g ②）：**标签上的分支名仍然走 shell 集成、零读仓**；面板/图/diff 是另一件事——没有任何 shell 会主动报暂存区——它们**只在某一列正站在它的 Git 页时**才读，加一个可以整块关掉的总开关。停在树上的列花费与从前完全相同：一个进程都不起。
- **手机 / 远程监控**：superterm 的主打（**agent 时代你不在电脑前，而解除阻塞往往只要按一个 y**），与 P1-8 注意力管理同源。但它要一个**服务端**，与「不做账号系统 / 不做云同步」的非目标**正面冲突**。**和常驻服务放在一起裁决——它们其实是同一个问题：关掉窗口之后，还剩什么。**
- **tmux control mode（WT #3656，221👍）**：清单原先完全没有，而呼声排在开放 issue 前列。**它会逼着「常驻服务」提前裁决。**
- **常驻服务（tmux/Zellij 路线）**：决定「关掉软件后进程还活不活着」。**这是 P1-4 恢复能力的天花板**——没有它，「上下文」只能恢复转录与位置，**进程恢复不了**；有它，才谈得上「你的 agent 还在想」。Windows 上 ConPTY 让它更麻烦。**当前倾向：先不做**，用 P3-4 的自动化让用户自己写「怎么把它叫回来」（如 `claude --continue`）。M4+ 前必须给出结论——**「你的文字回来了」和「你的 agent 还在想」是两回事，而本产品的场景是后者。**
