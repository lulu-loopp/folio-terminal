# M1.7 resize 转录语义记录（DESIGN v3.7）

> 本文原先记录的 v3.5/v3.6 “resize 历史严格净零”与 reversible staging/settlement
> 方案已被用户裁决推翻；演进原因保留在 `DESIGN.md` §3.1/§11。当前权威语义如下。

## 产品边界

ConPTY 的公开字节流无法同时证明“这是 repaint”并区分合法的相同真实输出。因此硬保证改为：
**不崩、不焊接、不静默丢真实输出**。快速拖拽后的应用回滚可留下每手势 0～几行由 vendor
原生 reflow 排整齐的干净重复；不允许用文本、样式或时间相等删除它们。

## 所有权与边界

- 稳态 vendor scrollback=0，正常 full-screen scroll 进入 transcript normal staging。
- 第一次本地尺寸变化先冻结既有 normal staging，再打开 primary vendor native history；事务期
  resize 驱逐和真实输出只由该 history 持有，没有 backing/snapshot/settlement 镜像。
- winit 0.30.13 没有公开的模态 resize enter/exit 事件。本地 surface/Term 每个 `Resized` 都跟随，
  ConPTY 只在 200ms 事件静默后收到最终尺寸。
- 最终请求后的 PTY 非空输出再静默 200ms，事务结束；history oldest→newest 一次收割入转录并
  恢复 limit=0。每个收割物理行成为独立 wrap-split candidate，同时保留 fragment WRAPLINE 与
  末列 cells，既防止旧 wrapped head 与新 hard line 焊接，也不以防焊接为名丢边界内容。

## Oracle

每次事务记录 resize request、PTY chunk、adapter 行来源/宽度、vendor tail、harvest 和 frame
`columns/rows/cells/anchors`。确定性回放及人工终审都必须覆盖多轮拖拽、最终 repaint、收割、
滚轮上翻，并直达 publish、selection 与 renderer 的矩形门禁。自动化期望是内容守恒、无焊接、
每手势有界干净增长和 frame 恒矩形；协调者真实 ConPTY 拖拽 + 截屏仍是最终验收。

## Vendor 面（R11'）

不复制 alacritty reflow。窄 seam 仅打开/查询/一次性取出/清空 primary native history，加既有
removed-row 事件用于 live anchor rebase；vendor 事务期独占 mutable tail，收割后转录重新独占
StagingId、配额与定稿。升级必须审计 grid/history 语义并跑 vendor 181 项基线。
