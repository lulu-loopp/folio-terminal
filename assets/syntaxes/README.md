# Vendored grammars

A `.sublime-syntax` file lands here when a language Folio's preview should read
is missing from the box `crates/bt-app/src/highlight.rs` loads — Sublime's
defaults plus bat's extras, shipped as one binary dump by `two-face`. There is
exactly one such language today, and the procedure below is what the next one
repeats.

Each entry states where the file came from, what it travels under, and **every
line of it that differs from upstream, with the reason**. A vendored grammar
with an unrecorded edit is a grammar nobody can update.

## The two files per grammar, and which one is the authority

The `.sublime-syntax` is the source and the only thing to edit. Beside it sits a
`.packdump`: the same grammar as syntect's own binary dump, built from it by an
ignored test, and the file the executable actually carries
(`crates/bt-app/src/highlight.rs`, `include_bytes!`).

The dump exists because of the *miss* case rather than because of PowerShell.
The lookup in `highlight.rs` reaches the vendored box whenever the main grammar
dump has no answer — a `.log` file, a ` ```output ` fence — and on this machine
loading the dump costs **0.08 ms** where parsing the 22 KB of YAML costs
**60 ms**. Sixty milliseconds of the window, spent to tell somebody their log
file is not PowerShell, is a stall charged to a document that has nothing to do
with this feature.

**The generated file cannot become the authority.**
`the_powershell_packdump_is_the_vendored_grammar` rebuilds the dump's contents
from the `.sublime-syntax` on every CI run, on all three platforms, and fails if
the two have parted company. After editing a grammar here, regenerate:

```
cargo test -p bt-app --bin folio regenerate_the_powershell_packdump -- --ignored
```

and commit both files together.

### Why it is vendored rather than taken from `two-face`

`two-face` ships this grammar, but only in its **Oniguruma** dumps. Folio runs
syntect on `regex-fancy`, the pure-Rust backend, because the alternative is a C
library and a build toolchain on three platforms (workspace `Cargo.toml`, the
comment above the `syntect` dependency). `two-face` excludes PowerShell from its
fancy dumps because one of the grammar's 97 patterns uses an Oniguruma-only
construct. One. The patch below is that one pattern, and with it applied every
pattern in the file compiles under fancy-regex — which is what
`every_pattern_of_the_vendored_powershell_grammar_compiles` asserts, and what
syntect's loader itself refuses to build a syntax without.

### Changes from the file named above

| Line | Before | After | Why it is the same grammar |
|---|---|---|---|
| `file_extensions` | `ps1`, `psm1`, `psd1` | `ps1`, `psm1`, `psd1`, **`pwsh`** | Not a pattern. syntect answers a markdown fence's info string with `find_syntax_by_token`, which reads a grammar's extension list before its name, so ` ```pwsh ` resolves to PowerShell only if `pwsh` is in that list. The cost of saying so is that a file literally named `x.pwsh` is read as PowerShell too, which is what it would be. |
| `unicodeEscape` | <code>\`u\\{(?:(?:10)?([0-9a-fA-F]){1,4}\|0?\g&lt;1&gt;{1,5})}</code> | <code>\`u\\{(?:(?:10)?([0-9a-fA-F]){1,4}\|0?[0-9a-fA-F]{1,5})}</code> | `\g<1>` is an Oniguruma **subroutine call**: it re-runs group 1's *pattern*, not its captured text (that would be `\1`). Group 1 is the single character class `[0-9a-fA-F]`, so the call is that class written out, and the replacement is a substitution of equals. The group itself is left in place, unused, so the pattern's capture numbering is untouched; this rule carries no `captures:` map, so nothing reads it either way. The construct fancy-regex refuses is `FeatureNotYetSupported("Subroutine Call")`. |

Nothing else differs — no pattern was deleted, weakened or retuned, so there is
no PowerShell construct this file highlights less well than bat does.

Three constructs a reader might expect to be in that table are **not**, because
fancy-regex accepts them and means the same thing by them. They were measured,
not assumed:

- **possessive quantifiers** — `^(?:\s*+)…` in `function`, `(?:[0-9_])?+` in the
  two exponent rules. fancy-regex has supported possessive quantifiers and
  atomic groups for several versions.
- **`\G`** — `(?:^|\G)` in the two `commentEmbeddedDocs` rules. fancy-regex
  implements it as "where this search started", distinct from `\A`: searching
  `\Gx` in `yxz` from byte 1 matches, and `\Ax` does not. That is the semantics
  syntect needs, because syntect searches each line from the position the last
  match ended at.
- **`{,6}`** — `` `u(?:\{[0-9a-fA-F]{,6}.)? `` in `unicodeEscape`. fancy-regex
  reads it as `{0,6}`, as Oniguruma does, rather than as six literal characters:
  `^a{,6}$` matches `aaa` and does not match the text `a{,6}`.

### Updating it

Fetch the file from bat at the commit you want, re-apply the two rows above,
regenerate the `.packdump` with the command at the top of this file, and update
the table. `every_pattern_of_the_vendored_powershell_grammar_compiles` is what
tells you whether the new copy needs a third row.
